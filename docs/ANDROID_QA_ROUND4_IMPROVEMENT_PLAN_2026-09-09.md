## 검토와 우선 판단

사용자 제공 4차 보고서, 현재 작업 트리, `artifacts/qa/android-e2e-round4-2026-09-09/`의 저장 오류·상단 잔상·비행 장면 캡처를 확인했다. 기존 2·3차 미커밋 작업은 보존한다. 이번에는 계획만 작성하며 코드 수정, 테스트 실행, 알림 취소나 기기 설정 변경은 수행하지 않았다.

가장 먼저 고칠 항목은 S-01이다. 크래시 0건이어도 특정 저장 명령이 항상 거부되므로 출시 전 필수 수정으로 본다. 전체 저장이 망가졌거나 기존 파일이 손상됐다는 뜻은 아니며, 실패 후 원본 보존 여부도 따로 검사한다.

실행 순서: **저장 전이·오류 복구 → 배너/고정 요소 배치 → 비행 화면·고피로 경로 → 상단 잔상 → 선택·성장·승격 안내 → 업데이트 설치 회귀 검증**. S-03 원인 조사는 초반에 재현 자료를 확보해 시작한다.

## 코드에서 확인한 사실과 아직 확인할 것

- S-01: `GameStore.abandonPitch()`와 `CSharpLegacyAggregateBridge.abandonPitch()` 모두 boundary와 abandonedReason만 변경한다. `PitchDurableState.validate()`는 ABANDONED에서 suspendedFrom과 terminalPitchId가 null일 것을 요구한다. SUSPENDED → ABANDONED의 불일치는 확인됐다.
- 이전 `Round2ProgressIntegrityTest`의 반복 포기는 주로 PLAYING에서 실행됐다. 재시작 검사가 있다는 것만으로 중단 후 포기까지 검증된 것은 아니었다. 이 공백을 명시적으로 메운다. 결함이 어느 커밋에서 처음 생겼는지는 별도 이력 확인 없이 단정하지 않는다.
- 현재 오류 처리에는 최초 실패의 재시도 문구와 반복 실패의 저장 공간 안내가 있다. 불변식 오류에 둘 다 맞지 않는다. 보고서처럼 매번 같은 문구인지와 별개로 오류 원인별 안내가 필요하다.
- S-02·05: 캡처에서 스크롤 영역 끝에 액션/대사가 일부만 보인다. 기존 Scaffold inset은 이미 적용돼 있다. 실제 가림인지 스크롤 경계 노출인지, 끝까지 스크롤하면 전체가 보이는지 측정한다. 단순히 버튼 높이만큼 padding을 또 더하는 것으로 끝내지 않는다.
- S-03: 반복 관측된 시각 결함으로 취급한다. 접근성 트리에 없다는 이유로 무시하거나 에뮬레이터 리사이즈 탓으로 보류하지 않는다. 중복 합성, 그리기 좌표, 레이어 재사용, 시스템 바 영역을 분리 조사한다. 원인은 아직 확정하지 않았다.
- S-04: 조준 화면과 비행 화면은 서로 다른 그림 경로다. 조준 격자를 고쳤다는 이유로 비행 장면도 정상이라고 간주했던 검증 범위를 확장한다. 정지 캡처만으로 ‘12초 탭 대기’ 원인까지 확정할 수 없으므로 시간축 로그를 확보한다.
- S-06 상세: `ConversationChoice`는 숨겨진 효과나 추가 설명이 있을 때만 상세를 제공한다. 세 번째 선택지에 실제 누락된 내용이 없다면 상세 링크 부재 자체는 결함이 아니다.
- S-06 목표: `AceCareerPresentation.goal()`은 완투 기록이 없으면 ‘첫 완투’를 계속 반환한다. 목표 유지와 진행 피드백 부재를 구분한다.
- N-13/S-10: 현재 `canFastForward()`는 튜토리얼 외 피로 80 이상에서 true다. 버튼에는 별도로 화면의 fatigue와 조준 UI 표시 조건이 적용된다. ‘고피로 표시를 본 화면’이 조준/비행/결과 중 무엇인지 구분해야 한다. 자동 강판 성공으로 수동 보조 버튼의 검증을 대체하지 않는다.

## 공통 상태 전이 규칙

모든 PitchBoundary 쌍을 허용하는 테스트를 만들지 않는다. **출발 boundary + suspendedFrom + 결과 커밋 여부 + 명령**을 기준으로 허용/거부 행렬을 만든다.

- 유효한 전이: 결과 상태가 validate를 통과하고, 저장→재개방에서도 동일해야 한다.
- 금지된 전이: 명시적으로 거부하며 파일·revision·기록·시드가 바뀌지 않아야 한다.
- RESERVED/PLAYING에서 멈춘 상태와 COMMITTED/CONSUMED/TERMINAL 결과가 남은 상태를 구분한다. 결과가 이미 저장됐다면 결과 확인/정산 경로로 복구하고 기록을 없던 일로 만들지 않는다.
- suspendedFrom만 지우면 되는 경로와 포기 자체를 거부해야 하는 경로를 구분한다. 검사를 통과시키려고 committedPitchIds, resultHashes, terminalPitchId 등을 무조건 비우지 않는다.
- ABANDONED는 중단 출처를 남기지 않는 현재 불변식을 유지하는 방향을 우선한다. 불변식을 느슨하게 바꾸려면 별도의 의미·호환성 근거가 필요하다.
- 같은 명령 재전송, 오래된 revision, 저장 실패 직후 재실행, 결과 확인 반복을 포함한다. 기존 S-01 실제 세이브를 fixture로 보존하되 원본은 초기화하지 않는다.

## 공통 화면 배치와 시각 검증 규칙

- 고정 액션·하단 탭은 한곳에서 크기와 inset을 관리하고 본문은 남은 영역에서 스크롤한다. 작은 화면에서 액션이 여러 개면 지원 가능한 배치를 명시적으로 선택한다.
- 오류 배너, 키보드, 효과 상세 펼침, 긴 번역, 큰 글자도 같은 화면의 필수 변형으로 검사한다.
- 버튼 modifier의 최소 높이만 검사하지 않는다. 실제 화면에 보이는 사각형과 입력 가능한 영역을 확인하고, 일부만 보이는 상태를 48dp 통과로 판정하지 않는다.
- 스크롤 끝에서는 마지막 콘텐츠 전체가 보여야 한다. 스크롤 중 경계에서 콘텐츠가 일부 보이는 현상과 영구적인 가림은 분리한다. 그라데이션은 스크롤 힌트일 뿐 가림을 고친 증거가 아니다.
- 접근성 트리에 없는 잔상은 픽셀 캡처로 검사한다. 동일 화면의 첫 진입·안정 프레임·탭 왕복 후를 비교하고, Compose 캡처와 전체 화면 캡처를 대조한다.
- S-03을 피하려고 전역 하드웨어 가속이나 애니메이션을 무조건 끄지 않는다. 고정 의존성에서 원인을 재현한 뒤 필요한 범위만 수정한다.

## 승격·목표 안내의 데이터 기준

현재 `ProKernel`의 승격 판정에는 감독 신뢰 60 이상, 내부 skill 46 이상, 그리고 2시즌 이상/현재 시즌 12경기 이상/40탈삼진 이상 중 하나가 사용된다. 다만 이 수치를 그대로 UI에 하드코딩하지 않는다. skill 계산과 주간 진행의 판정 시점, 현재 보직·규칙 버전을 함께 읽어 공통 규칙으로 추출한다. 내부 능력 눈금과 100점 표시 눈금을 섞지 않는다.

‘승격 가능’과 ‘이미 승격됨’을 구분한다. 조건을 만족해도 다음 주간 판정이 필요한 경우 그 시점을 안내한다. 선수 성적이 2군 기준으로 평가되는지 역시 기존 커널 정의를 따른다.

## 실행 및 재검증 순서

1. 실제 SUSPENDED 저장 파일, 피로 80 이상 상태, 비행 대기 상태를 확보한다. APK 해시·패키지·원본 세이브 해시·설정을 기록한다.
2. S-01 실패를 먼저 재현하고 상태 행렬 테스트를 작성한다. 전이 수정 후 실패 시 원본 보존과 대안 버튼 동작을 검증한다.
3. 공통 화면 배치에 오류 배너/드래프트/결과/설정 변형을 적용한다. S-03·04에는 짧은 영상이나 시간별 캡처와 상태 로그를 추가한다.
4. 고교·프로 각각 중단→포기→재실행→재개, 마지막 공→결과 확인, 저장 실패 후 복귀를 실제 UI로 실행한다. 기본 조작은 계속 투구 슬라이더이며 한 구의 저장까지 확인한다.
5. 승격·장기 목표·성장 감소는 경계값 및 이력 fixture로 검사한다. UI에서는 현재 상태에 맞는 안내인지 확인한다. 매번 고교 3년을 다시 완주해야만 회귀를 판단하는 구조로 만들지 않는다.
6. ko/en/ja × 글자 100/130/150% × 짧은 화면을 검사한다. 가능하면 실기기에서도 상단 잔상·비행 장면을 확인한다. 기기 연결은 실행 시 다시 확인한다.
7. 실제 기존 QA 세이브를 보존한 업데이트 설치로 포기/재개와 기록 보존을 확인한다. 별도 테스트 패키지의 통과와 사용자 확인용 QA 패키지의 설치 증거를 구분한다.
8. 관련 단위/계측 테스트, 기존 stage 복구·알림·계약·대화 결과 회귀, 정적/reference·문구/IP·현지화 검사를 통과하고 항목별 완료 근거를 기록한다.

## 완료 판정과 외부 조건

S-01 저장 전이와 복구 안내, S-02 액션 접근성은 출시 전 필수 완료 조건이다. 나머지는 코드 변경만으로 닫지 않고 해당 화면 상태와 증거를 함께 남긴다. 특히 S-03은 의미 트리 검사만으로, N-13은 자동 강판만으로 해결 처리하지 않는다.

보고서 S-06에 묶인 다섯 관찰은 A~E로 분리해 추적한다. 재검증 표에서 생략된 R-10B·R-11A/B도 이전 결과를 자동으로 ‘4차 통과’에 합산하지 않는다. 드래프트·계약의 소스/기존 캡처 확인은 이번 세션의 신규 완주 검증과 구분한다.

4차 보고서는 알림 권한을 원복했다고 하면서 동시에 허용 상태와 알람 1건이 남았다고 기록한다. 다음 실행에서 실제 상태를 확인하고 테스트 예약인지 식별한다. 이번 계획 작성 중에는 남은 알람을 취소하지 않는다. 구현/검증 작업에서는 이번 테스트가 만든 예약을 정리하고 원래 사용자의 예약과 구분한다.

OS 자동 복원·두 실기기 이전, 태블릿·폴더블, TalkBack 실청취 및 서명된 RC는 여전히 별도 조건이다. 실기기나 서명 설정이 없으면 준비·코드 검증은 계속하되 해당 검증을 완료로 표시하지 않는다. 이 계획은 업로드·출시 승인이 아니다.
