## 저장 보존 정책의 범위

영수증 배열 전체를 무조건 256개로 자르지 않는다. 기존 `phase7-<hash>`처럼 원래 revision을 복원할 수 없는 ID는 정확히 보존하고, 신규 앱 writer는 revision 결합 ID를 사용한다. 따라서 **기존 불투명 ID 수 + 최근 revision 결합 ID 256개**가 보존 범위다. 기존 파일의 1,554개 phase7 영수증을 삭제해 용량을 줄였다고 주장하지 않는다. 문자열 사전순을 시간순으로 취급하지 않는다.

앨범의 시즌 성적·등판 기록·선수 이력은 계속 저장된다. 예산은 선택적인 투구 재생 상세에만 적용한다. 기존 재생은 삭제하지 않고, 한도에 도달하면 새 재생 상세 추가를 중단하며 사용자에게 알린다. 이 정책은 최근 512개로 자동 교체하는 정책이 아니다. 이미 한도를 넘는 구버전/가져온 파일도 기존 재생을 유지한다. 전체 세이브 크기의 절대 상한을 만들었다는 의미도 아니다.

이 방식으로 기존 데이터와 백업 wire를 보존했다. 장기 기록을 별도 파일로 옮기는 구조 변경이나 실적 통계 삭제는 수행하지 않았다.

## S-03 — 검사 보완 완료, 제품 원인은 미확정

> 6차 QA 정정: S-03은 원본 캡처의 픽셀 검증 결과 오탐으로 철회됐다. 이 항목은 제품 수정으로 해결한 것이 아니라 오탐 철회로 종결하며, 아래는 5차 당시의 기록이다.

기존 검사는 Compose root의 y=4~29 픽셀만 확인했으므로 실제 상태 표시줄을 검증하지 못했다. 해당 검사를 레이아웃 경계 검사로 한정하고, 실제 MainActivity를 띄운 뒤 전체 화면을 캡처하는 `Round5LiveSurfaceUiTest`를 추가했다. 시스템 상태 표시줄 높이를 읽어 중앙 영역을 검사하며, 기존 검사 밖에 인위적으로 삽입한 ‘기록’ 픽셀을 검출하는지도 확인한다.

이번 실행에서는 **수정 전 설치 앱**의 설정·기록·중단 화면과, 테스트 앱의 탭 전환·런처 복귀에서 잔상이 재현되지 않았다. 현재 캡처 검사는 통과했지만 이는 보고된 결함의 원인을 수정했다는 증거가 아니다. 내비게이션 제품 코드에 추측성 패치를 추가하지 않았고, S-03은 ‘이번 환경 미재현·원인 미확정’으로 남긴다. 실제 결함이 보이는 동일 APK/창 상태를 확보하면 새 검사로 검출 여부부터 확인해야 한다.

- 드래프트는 보존된 고교 완료 fixture 화면 검증이다. 이번 작업에서 고교 커리어를 UI로 새로 완주하지 않았다.

초기 빌드의 import 누락, 테스트 메서드의 반환형, 과거 알림 예약/취소를 게임 명령 payload로 기대하던 검사를 수정한 뒤 재실행했다. 알림은 권한/알람 경로이므로 해당 두 액션에 게임 상태 변경 payload가 없어야 한다고 검사한다. 전체 application 테스트의 20시즌 장기 커리어 실행은 중단하고 관련 테스트로 범위를 좁혔다. 전체 프로젝트 스위트 통과를 주장하지 않는다.

## 성능 재측정과 사용자용 QA 업데이트

투구 재개는 이전 4차 측정에도 사용한 실제 손상/중단 세이브 fixture(원본 파일 291,328바이트)를 매번 동일하게 가져와 포기→다시 투구 화면 진입을 실행했다. 탭 동기화부터 수동 슬라이더 노출까지 4,368 / 4,424 / 4,370 / 4,372 / 4,411ms, 중앙값 4,372ms였다. 호스트 부하 평균과 qemu CPU를 시도별로 기록했다. 이전 15~19초 관찰은 재현되지 않았으며, 저장 크기나 특정 수정이 원인이었다고 단정하지 않는다.

현재 사용자 QA 세이브(389,723바이트)를 초기화하지 않고 `com.solkim.baseball.android.compose.qa`에 업데이트 설치했다. 콜드 스타트는 `am start -W` 기준 1,543 / 1,494 / 1,390 / 1,453 / 1,483ms, 중앙값 1,483ms였다. 콜드 스타트와 중단 투구 재개는 다른 입력/동작의 측정이며 합쳐서 비교하지 않는다.

업데이트 전후 installId·highSchool·pro·pitchResume·앨범이 동일하고 파일 크기도 동일했다. 실제 QA 앱의 중단 화면에서 잘못된 스크롤 안내가 사라졌으며 두 액션이 온전히 보이는 것을 확인했다.

- 빌드 변형: debug + baseballLaunchQa + baseballQaNativeStore. 서명 RC 아님.

## 장비·배포 조건

연결 확인 결과는 `emulator-5554` 한 대였다. 실기기 재연결 가능 여부를 요청했으나 이 문서 작성 시점에는 연결된 실기기가 없다.

- OS 자동 복원/2대 기기 이전: 미검증. native 백업 파일 왕복 테스트와 구분한다.
- 실제 태블릿·폴더블: 미검증. 작은 카드/큰 글자 테스트가 이를 대체하지 않는다.
- TalkBack: 에뮬레이터에서 서비스 바인딩·터치 탐색 활성화만 확인했다. 실제 음성 청취와 전체 여정 조작은 미검증이다. 활성 서비스 설정은 테스트 전 상태로 되돌렸다.
- 서명 RC: preflight가 `BASEBALL_UPLOAD_KEYSTORE_PATH` 미설정으로 중단됐다. 키/서명 조건을 우회하거나 QA debug를 RC로 표시하지 않았다.

증거 디렉터리: `artifacts/qa/android-round5-fixes-2026-09-09/`. 세이브 원본, 변경 전후 화면, 상태 표시줄/런처 대조, 단위/계측 결과, 재개 측정 원시값 및 RC preflight 결과를 보존한다.

중단한 장기 테스트의 임시 세이브 약 2.4MB는 테스트용 installId와 사용 중인 프로세스가 없음을 확인한 뒤 삭제했다. 이전 QA 보고서·사용자 증거는 보존했다.
