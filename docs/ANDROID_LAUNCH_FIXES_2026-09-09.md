# Android 출시 QA 개선 기록 · 2026-09-09

## 범위와 현재 판정

제공된 E2E QA와 현재 소스를 대조해 커리어 복귀 → 정적 게이트 → 훈련 정보 → 온보딩·투구 화면 → 배포 준비 순으로 수정했다. 기존 대화/성장 UI 작업은 보존했다. 수정된 QA 빌드는 nativeAuthoritative 저장 모드를 사용하지만, 서명된 production RC는 아니다. 출시 승인을 의미하지 않는다.

## 수정

- 고교·프로의 COMMITTED / CONSUMED / TERMINAL 결과는 기존 투구 결과 화면으로 다시 연다. 이미 종료한 프로 경기는 기존 완료 경로도 유지한다. 결과를 새로 계산하지 않는다.
- 원래 QA의 68KB 소프트락 세이브를 회귀 fixture로 보존했다. 초기화 없이 결과 확인 → 다음 투구가 가능함을 native writer로 검증했다.
- 세 결과 상태에서 반복 확인·완료가 기록을 중복 반영하지 않는 회귀 테스트를 추가했다.
- Phase8 화면 생성 함수를 화면별 29개 메서드로 분리했다. ART의 거대한 단일 메서드 최적화 한도를 피하도록 구조를 변경했다.
- 디버그 audit 접미사를 정적 검사에서 명시적으로 허용했다. production과의 패키지 분리는 유지한다.
- 현재 일정의 남은 훈련 횟수를 공유 함수로 계산한다. 다음 등판까지 전체 일정의 누적 횟수는 범위를 명시했다. 반복 훈련 명령과 버튼의 횟수는 남은 일정에 맞춘다.
- 경기 운영 훈련의 제구 증가 이유를 기본 미리보기에 노출하고 관련 용어 별칭을 통일했다. 일반 최대 성장보다 이득이 없는 대성공 수치는 숨긴다.
- 첫 불펜은 추가 연습이 주 버튼이며, 학교 선택 건너뛰기는 보조 버튼이다. 세 구 이후 학교 선택이 주 버튼이 된다. 직접 투구 슬라이더 기본값을 유지했다.
- 조준 중에도 타자·포수·홈플레이트와 선택한 코스를 표시한다. 조작 영역을 먼저 확보하고 남는 높이를 그림에 배정한다. 투구 콘텐츠 최대 폭은 600dp다.
- 시작 버튼 전폭, 결과/타자 상세 라벨 구분, 기술 피드백의 불필요한 경고색 완화, 각성 범례 설명, 예상 구속 접힌 제목의 수치, 설정 루트 뒤로 버튼을 정리했다.
- 음악 포커스 요청은 이미 보유한 요청을 재사용한다. 거부되면 음악 재생을 시작하지 않는다.
- OS 백업은 save.json과 save.bak.1~3만 대상으로 한다. 설치 식별자·SDK 설정·임시 파일은 제외하고 Android 12+ 클라우드 백업에는 암호화 조건을 둔다.
- 복원된 파일과 새 설치 ID의 불일치를 native atomic writer로 한 번 재연결한다. 기본 repository의 불일치 거부는 유지하며 앱의 기기 복원 경로에서만 허용한다. 재연결 후 플레이·재저장·파일 내보내기를 검증했다.
- 생성 파일에만 존재하던 기존 번역을 소스 카탈로그에 보존했다. 일본어 配球 / 軽め, 영어 대성공 문구를 정리했다. Regex 패턴은 화면 문구 인벤토리에서 제외한다.

## 검증

- 현재 선택한 application 단위 테스트: 31건, 실패 0.
- production writer의 프로 시즌 진입/시즌 리뷰 회귀도 별도 통과했다. 테스트의 오래된 버전 11 고정을 현재 ProCatalog.RULES_VERSION 기준으로 정정했다.
- 정적/reference 검사 통과.
- 번역 카탈로그 재생성 일치 검사 통과. Kotlin 문구 템플릿 3,201개 / 매핑 3,201개 / 누락 0.
- 실존 야구 IP·내부 용어 문구 검사 통과.
- 에뮬레이터 계측 테스트 합계 13건 통과(재실행 중복 제외): 제스처, 훈련, 훈련 계획, 설정 대형 글자·언어, 파일 백업 export/import 테스트 통과.
- 원래 전체 application 테스트 실행은 프로 종료 동작 회귀를 발견한 뒤 중단하고 수정했다. 위 결과는 수정 후 필요한 테스트를 선택해 재실행한 것이며 전체 테스트 스위트 통과로 해석하지 않는다.
- 에뮬레이터 12회 투구 재생: 725 frames, janky 17 (2.34%), p95 23ms, p99 32ms. 소프트웨어 GPU의 debug QA 빌드 측정이므로 실기기 출시 성능 기준이 아니다.

최종 UI 회귀: 결과 복귀 후 조준·구종 변경·슬라이더 1구 완료 1건, 420dp 투구 카드/힘 배분 2건, 신규 사용자 기본 슬라이더 1건 모두 통과. 힘 배분 버튼과 조준 그림이 함께 보이는 최종 캡처를 직접 확인했다.

최종 UI 회귀와 캡처: `artifacts/qa/android-launch-fixes-2026-09-09/`.

## 외부 조건 때문에 남은 검증

- `bash tools/android-compose-build.sh rc`는 `BASEBALL_UPLOAD_KEYSTORE_PATH` 미설정으로 시작하지 못했다. 이후 필요한 서명/Firebase/분석 설정은 RC 스크립트의 원래 조건을 유지한다. 업로드·출시하지 않았다.
- 현재 연결 기기는 emulator-5554뿐이다. A53 및 태블릿/폴더블 실기기 확인은 수행하지 못했다.
- OS 자동 백업 및 제조사 기기 이전은 두 기기에서 실제 복원 검증이 필요하다. 단위 테스트의 파일 복원·설치 ID 재연결과 구분한다.
- baseline profile은 이번에 추가하지 않았다. 실제 배포 후보와 실기기 시작/프레임 기준선이 확보되면 필요성과 효과를 비교한다.
- 일본어 표현은 코드/카탈로그 수준에서 보정했다. 원어민 감수 완료를 의미하지 않는다.

## 원 보고서 해석 보정

Android 16의 대화면 강제 적응에는 appCategory=game 예외가 있고, 이 앱은 game으로 선언한다. 또한 allowBackup=false만으로 모든 제조사의 기기 이전 불가를 단정할 수 없다. 원래 QA는 하나의 커리어를 다섯 페르소나 관점으로 본 관찰이며, 독립 사용자 5명 실험과 다르다. iOS의 일본어 IPA/App Store 조건은 Android의 배포 검증과 별개다.

루트 뒤로가기의 추가 종료 확인, 타선 이름 확장, 궤적 구분 추가 연출은 이번 핵심 출시 수정 범위에서 변경하지 않았다. 정상 저장이 확인된 종료에 추가 대화상자를 강제하지 않았고, 타선·연출 변경은 별도 콘텐츠 검토가 필요하다.
