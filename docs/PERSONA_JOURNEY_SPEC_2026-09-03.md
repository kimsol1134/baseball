# 페르소나 3인 전체 여정 플레이테스트 스펙 (2026-09-03)

grok CLI가 iOS 시뮬레이터에서 실제 앱을 조작해 세 명의 가상 유저(페르소나)로 고교 3년 → 드래프트 → 프로 → (은퇴 또는 최소 2시즌)까지 **직접 플레이**하고, 각 페르소나의 눈으로 마찰 지점을 기록한다. 코드를 고치지 않는다. 결과물은 보고서 한 편과 스크린샷이다.

## 0. 절대 규칙
- 리포지토리 소스·카탈로그·테스트·설정 파일을 **수정하지 않는다.** `git commit`·`git add`·`git stash` 금지. `xcodebuild` 실행 금지(앱은 이미 시뮬레이터에 설치돼 있다).
- 시뮬레이터는 **부팅된 iPhone 17(UDID `641C2F6D-BF5F-406F-B22C-FEB35CB4E4BF`) 하나만** 쓴다. 다른 기기를 만들거나 부팅하지 않는다. 페르소나 세 명은 **순차로** 진행한다(동시 실행 금지).
- 앱 번들 ID `com.solkim.baseball.ios`. 다른 앱을 열거나 지우지 않는다.
- 호스트 CoreAudio가 걸려 있어 사운드가 켜지면 앱이 런치 10초 뒤 abort된다. **런치 전에 반드시** 아래를 실행하고, 전체 작업이 끝나면 되돌린다.
  ```
  xcrun simctl spawn booted defaults write com.solkim.baseball.ios baseball.audio.sound -bool NO
  xcrun simctl spawn booted defaults write com.solkim.baseball.ios baseball.audio.music -bool NO
  # 끝난 뒤
  xcrun simctl spawn booted defaults delete com.solkim.baseball.ios baseball.audio.sound
  xcrun simctl spawn booted defaults delete com.solkim.baseball.ios baseball.audio.music
  ```
- 스크린샷·로그는 `apps/ios/releases/qa-1.2.9/personas/<persona-id>/` 아래에만 저장한다(이 경로는 gitignore 대상). 한 페르소나당 스크린샷 40장 이하.
- 실존 구단명·선수명을 보고서에 쓰지 않는다(게임 안 가상 구단명은 그대로 인용 가능).
- 페르소나 한 명당 시간 예산 40분. 한 화면에서 5분 이상 막히면 스크린샷을 남기고 "막힘"으로 기록한 뒤 건너뛰기·자동 진행·뒤로가기로 빠져나온다. 그래도 안 되면 그 페르소나는 거기서 종료하고 다음으로 넘어간다.

## 1. 조작 도구
- 화면 읽기: `axe describe-ui --udid $U` (접근성 트리 JSON; `AXLabel`·`AXFrame`로 위치를 얻는다).
- 탭: `axe tap --label "<정확한 라벨>" --udid $U` 또는 `axe tap -x <pt> -y <pt> --udid $U` (좌표는 pt 단위, 화면 402×874).
- 스크롤: `axe swipe --start-x 200 --start-y 750 --end-x 200 --end-y 250 --udid $U` (위로 넘김), 반대로 하면 아래.
- 입력: `axe type "<텍스트>" --udid $U` (입력칸을 먼저 탭).
- 스크린샷: `xcrun simctl io booted screenshot <path>.png`.
- 앱 실행(새 커리어로 초기화): `xcrun simctl terminate booted com.solkim.baseball.ios; xcrun simctl launch booted com.solkim.baseball.ios -uiTestResetCareer -uiTestAutoRelease -baseball.audio.sound NO`
  - `-uiTestAutoRelease`는 투구 슬라이더 타이밍 없이 탭 한 번으로 던지게 한다(자동화용).
  - 페르소나마다 위 명령으로 새로 시작한다.
- **알럿(확인창)** 안의 버튼은 `--label`로 잡히지 않을 수 있다. `describe-ui`에서 프레임을 읽거나, 알럿 버튼 위치를 스크린샷으로 확인해 좌표로 탭한다.
- 탭 바 라벨: `고교` `프로` `기록` `설정`.

## 2. 여정 지도 (라벨은 실제 화면에서 describe-ui로 확인할 것)
1. 오프닝 `시작하기` → 선수 만들기 4단계(이름은 `민서준 쓰기`로 자동 입력 가능, 지역은 권역 세그먼트 → 도시, 유형, 구종/난이도) → `고교 1학년 시작`
2. 1장 시작 → `첫 공을 던진다`(연습 투구; `길게 눌러 와인드업` 버튼 탭, 끝나면 `연습을 끝낸다`) → 고교 3년 목표 선택(선택 또는 `목표 없이 시작`) → 학교 카드 탭 → 알럿 `이 학교로 간다`
3. 훈련 루프: 훈련 카드 선택 → 강도 → `훈련하기`. `같은 훈련 최대 3회` 버튼으로 자동 반복. 대화·선택지(관계 이벤트)는 페르소나 성향대로 고른다. 공식 경기(직접 승부)는 투구 화면에서 와인드업 버튼을 반복 탭한다(포수 제안 수락/변경은 페르소나 성향대로). `중단`은 쓰지 않는다.
4. 장 리뷰 → 각성(스킬트리) → 다음 장 … 3년 후 드래프트 → 지명/미지명 → 유산·환생 화면
5. 지명되면 프로: 계약 제안 수락 → 주간 계획(훈련 카드 선택 → `1주 진행` 또는 `스프링캠프 끝까지 진행`류 자동 진행) → 3주마다 결정 카드 → 직접 승부 → 시즌 결산 → 오프시즌 결정 → 다음 시즌. **최소 2시즌**, 은퇴까지 가면 더 좋다. 40분 예산 안에서 끝낸다.
6. 기록 탭·설정 탭도 한 번씩 열어 본다(설정의 `글자 크기`·`설명 밀도`를 페르소나 취향대로 바꿔도 된다).

## 3. 페르소나 (grok이 구체화한다)
아래 골격을 채워 세 명을 만든다. 이름·나이·직업·야구 지식·플레이 습관·기대·인내심(막히면 얼마나 빨리 이탈하는지)·읽기 성향(다 읽는다/훑는다/안 읽는다)을 정하고, **의사결정 규칙**을 5줄로 적는다(예: "피로 60 넘으면 무조건 회복", "포수 제안은 항상 수락", "선택지는 가장 짧은 것", "설명은 안 읽고 첫 버튼").
- P1 `light-fan`: 야구 중계는 보지만 시뮬 게임은 처음. 텍스트를 훑는다. 짧게 자주 한다.
- P2 `sim-veteran`: 육성 시뮬 다수 경험. 수치와 규칙을 다 읽고 최적화한다. 용어 오류·불일치에 민감.
- P3 `casual-story`: 이야기·캐릭터 관계가 목적. 능력치보다 대사와 선택지를 본다. 반복 작업을 싫어한다.

## 4. 기록할 것 (페르소나마다)
- 여정 로그: 단계별 소요 시간, 탭 수(대략), 어디서 무엇을 골랐는지 10~20줄.
- 마찰 목록: 화면·문구·상황 → 페르소나의 반응(1인칭) → 심각도(이탈/짜증/의문). 특히 **읽기 힘든 문구, 뜻 모를 용어, 같은 말 반복, 잘리거나 겹친 글자, 뭘 눌러야 할지 모르는 순간, 진행이 막힌 순간, 버그**.
- 좋았던 순간 3개.
- 페르소나의 한 줄 평, 별점(1~5), "돈 주고 살까"(예/아니오/조건).
- 스크린샷: 온보딩 완료, 첫 훈련, 첫 공식 경기 결과, 장 리뷰, 드래프트 결과, 프로 첫 주, 첫 결정, 시즌 결산, 그리고 마찰 지점마다.
