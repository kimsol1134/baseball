## 0. 결정

**첫 회차의 시작을 세 박자로 줄인다: 장면 → 최소 선택 → 첫 불펜.** 형식(폼)을 없애지
않는다 — 형식에서 첫 회차에 무의미한 것(난이도·카르마)을 빼고, 형식 앞에 "게임이
시작됐다"를 알리는 오프닝 장면 한 장을 세운다. 카르마와 난이도는 2회차부터 나온다.

투구를 설정보다 앞에 두는 안(콜드 오픈)은 **기각**한다. 이유는 §5.

세계관 언어는 유지하되 단위를 바꾼다. **"환생"(제목)·"다시 태어나기"·"기억"·"영혼"은
그대로 두고, 회차를 세는 "생"만 "회차"로 통일한다.** "짊어질 것"은 "핸디캡"으로 바꾼다.
근거는 §3.

## 1. 첫 60초 (1회차, 저장 없음)

### 1.1 오프닝 장면 (~5초, 신규)

`loadState == .needsSetup && inheritance.lifeNumber == 1`일 때만 `HighSchoolSetupView`
대신 먼저 뜬다. 별도 저장 플래그를 두지 않는다 — 조건이 곧 상태다. 커리어 삭제 후에도
다시 뜨는 것이 맞다(그때도 처음이다).

- 전면 키아트 `.careerIntro`. 아래를 캔버스 색으로 페이드한다(DOC-19 §7.5).
- 제목: **야구 못하면 또 환생함** — 타이포그래피로 세운다. 이미지에 글자를 굽지 않는다.
- 전제 한 줄: `당신은 고교 투수입니다. 3년 안에 프로 지명을 받아야 합니다.`
- 주 행동(라임 알약, 화면에 하나): `시작하기` — 식별자 `hs.opening.start`.
- 다른 조작·설명·페이지 넘김 없음. 한 장이다.

### 1.2 선수 만들기 (~20초, `HighSchoolSetupView` 축소)

1회차에 남는 것:

- 키아트 헤더. 눈썹 `고교 커리어 시작`, 제목 `어떤 투수로 시작할지 고르세요` (현행 유지).
- 선수 이름 입력. placeholder가 프리셋 기본 이름이라 **입력하지 않아도 진행된다** (현행 유지).
- 투수 유형 3장 (현행 유지).
- `고교 1학년 시작` (`hs.start`, 현행 유지).

1회차에서 빠지는 것:

- `이번 생의 난이도` 카드 전체. 내부적으로 `.standard`로 시작한다(현행 기본값 그대로).
- `짊어질 것` 섹션 전체. `karmas: []`로 시작한다(현행 기본값 그대로).

2회차 이후(`lifeNumber > 1`)에는 현행 폼이 전부 나온다: 눈썹 `N회차`, `가져온 것` 카드,
이름, 유형, **난이도**(문구 §3), **핸디캡**(문구 §3). 죽음(미지명)을 한 번 겪은 뒤에야
트레이드가 의미를 갖는다 — Rogue Legacy 2가 특성 카드를 첫 사망 후 첫 상속자부터
보여 주는 것과 같은 배치다.

### 1.3 프롤로그 (~5초, `PrologueCard` 문구만 조정)

구조는 그대로 둔다(뉴스 한 줄 + `지금의 나` 게이지 + 주 행동 + 건너뛰기). 두 탭으로
투구에 닿는 계약(`testFirstPitchIsReachableInTwoTaps`)을 지킨다. 조정:

- 첫 카드 제목 `시작` → `첫 등교`. 본문 첫 줄을 감독의 말로 연다:
  `"몸부터 풀자. 불펜에서 한 구 던져 봐." — 감독` (뉴스 줄은 그 아래 유지).
- 주 행동 `첫 공을 던져 본다` → `첫 공을 던진다` (현행 식별자 `hs.prologue.throw` 유지).
- 2회차 이후 카드 제목 `다시 태어났습니다`와 `짊어진 것` 표기는 §3의 문구로.

### 1.4 첫 불펜 (~30초, 현행 유지)

`PitchScenario.tutorial`은 그대로 쓴다. 제스처 교육은 이미 조작 지점에 있다 —
`DeliveryControl.swift:127,132`의 `길게 눌러 와인드업` / `끌어서 맞추세요`가 화면 안
문구로 뜨고, 정찰 신뢰도 100·연습 타자·기록 미반영도 이미 맞다. **별도 튜토리얼 화면을
만들지 않는다.** 승부가 곧 튜토리얼이다(Hades가 첫 탈출 시도 자체를 튜토리얼로 쓰는
구조).

## 2. 흐름 검증 (실측)

- 라우팅: `HighSchoolCareerView.swift:16-33`이 `loadState`로 분기, `.needsSetup` →
  `HighSchoolSetupView`. (`AppShell.swift:33`은 뷰를 얹을 뿐 분기하지 않는다.)
- 시작: `hs.start` → `startCareer` (`HighSchoolCareerStore.swift:65-108`) → phase
  `.prologue` → `PrologueCard` (`HighSchoolCareerView.swift:197-239`).
- 첫 불펜: `beginTutorialPitch` (`HighSchoolCareerStore.swift:128-133`)는
  `result.snapshot`과 `result.nextSeed`를 요구한다. **커리어 생성 전에는 튜토리얼
  세션이 존재할 수 없다** — 정확히는 `PitchSession(scenario:seed:)`가 임의 시나리오를
  받으므로 합성 시나리오로 우회는 가능하지만, 그 투구는 시드·투수·careerID가 커리어
  밖에서 만들어져 "내 투수"가 아니다. §5에서 기각.
- 난이도·카르마 기본값: `difficulty: .standard`, `karmas: []`가 이미 기본 인자다
  (`HighSchoolCareerStore.swift:68-69`). 1회차에서 섹션을 숨겨도 저장 형식·코어 호출이
  변하지 않는다.

바꾸지 않는 것과 이유:

- **환생 / 다시 태어나기** — 게임 정식명이 `야구 못하면 또 환생함`이다(GAME_NAME_CHANGE).
  제목이 파는 것을 UI가 부정하면 안 된다. 소유주의 지적은 "이번 생"이라는 *단위 표현*이지
  환생 콘셉트가 아니다.
- **영혼** — `야구혼`이 메타 진행의 공식 명칭으로 확정돼 있다(GAME_NAME_CHANGE). 영혼
  포인트는 그 화폐다.
- **기억 (카드)** — 구체물(카드 M장)이라 직관 문제가 없고, 코어 서사가 "설명하기 어려운
  감각"으로 이미 이 어휘 위에 서 있다(`HighSchoolCareer.swift:1060-1061`).

"핸디캡" 선택 근거: 뜻이 스포츠 문맥에서 즉시 읽히고(골프·바둑에서 일상어), 이 시스템의
실체 — 자발적 불리 조건과 보상 — 를 그대로 말한다. 후보였던 "각오"는 "짊어질 것"과 같은
문제(비유)를 반복한다. `tools/check-copy.mjs`의 차단 목록(내부 용어 22종·실존 IP)과
충돌 없음 확인함.

## 4. 장르 근거

| 게임 | 시작 배치 | 왜 그 배치인가 |
|---|---|---|
| Hades | 생성 없음, 즉시 플레이. 첫 탈출 시도가 튜토리얼 | 주인공이 고정(자그레우스)이라 선택할 것이 없다 |
| Rogue Legacy 2 | 1회차는 기본 기사로 즉시 플레이. 특성(트레이드 명시 카드)은 **첫 사망 후 상속자부터**, 효과 설명은 한 번 겪어야 공개 | 트레이드는 루프를 아는 사람에게만 의미가 있다 |
| 파워프로 사쿠세스 | 시나리오(학교) 선택 → 짧은 선수 등록 → 스토리 시작 | "내 선수"를 만드는 게임이라 최소 생성을 앞에 둔다 |
| MLB The Show RTTS | 역할·포지션·아키타입 생성 → 고교 쇼케이스 플레이 | 위와 같음. 단 생성 항목이 많아 첫 플레이까지 오래 걸린다는 비판이 상존 |
| Slay the Spire | 캐릭터 선택 → 즉시 첫 전투. 승천은 클리어 후 | 메타 사다리는 숙련자용이라 뒤로 뺀다 |

패턴: **주인공이 고정이면 콜드 오픈, 주인공을 만드는 게임이면 "짧은 생성 → 즉시
플레이"**. 그리고 전원이 메타·트레이드 시스템을 첫 루프 이후로 미룬다. 이 게임은
"한 명의 투수의 삶"이 정체성이므로 후자다 — 생성은 남기고 20초로 줄이고, 카르마는
2회차로 미룬다.

## 5. 기각: 투구 선행 콜드 오픈

설정 전에 첫 투구를 넣는 안은 만들 수는 있지만(합성 `PitchScenario` + 임의 시드로
`PitchSession` 생성 가능, §2) 하지 않는다.

1. 그 투구의 투수는 플레이어가 고르지도 이름 짓지도 않은 기본 프리셋이다. "내가 만든
   투수의 인생"이라는 걸개가 첫 장면부터 남의 손에 넘어간다.
2. `hs.prologue.throw` 두 탭 계약과 4개 UI 테스트의 전제가 무너지고, 커리어 밖 세션이라는
   새 상태가 `LoadState` 기계 밖에 생긴다. 얻는 것은 폼 20초 단축뿐인데, 그 20초는
   §1.2의 축소로 이미 얻는다.
3. 소유주의 문제 제기는 "투구가 늦다"가 아니라 "시작한 줄 모르겠다"였다. 답은 순서
   뒤집기가 아니라 오프닝 장면과 군살 제거다.

## 6. 만들지 않는 것

- 페이지 넘기는 온보딩 캐러셀·스킵 가능한 인트로 영상·별도 튜토리얼 모드.
- 투구 화면 위 제스처 안내 오버레이. `DeliveryControl`이 이미 조작 지점에서 가르친다.
- 1회차 카르마 미리보기·툴팁·잠금 표시. 없는 것은 없다고도 말하지 않는다.
- 설정 탭에서 난이도 변경. 난이도는 회차 시작에 고정되는 값이다(코어 계약).
- 외형·투구폼·출신지 선택 등 생성 항목 추가. RTTS의 실패를 반복하지 않는다.
- "영혼"·"환생"·"기억"·"다시 태어나기" 개명.
- 코어·저장 형식 변경. 이 사양 전체가 `apps/ios` 뷰 계층과 문자열로 끝난다.

가장 위험한 부분: **오프닝 장면의 노출 조건.** 저장 플래그 없이
`needsSetup && lifeNumber == 1`에서 파생시키는 설계라, `deleteCareer()`와
`beginNextLife()`의 차이(전자는 `inheritance = .firstLife`로 되돌리고 후자는 유지,
`HighSchoolCareerStore.swift:110-118,214-220`)를 정확히 타야 한다. 환생 직후에 장면이
다시 뜨면 루프의 리듬이 죽고, 삭제 후에 안 뜨면 처음 상태로 돌아가지 못한다. 이 두
경로를 UI 테스트(`09-rebirth` 캡처 지점)로 함께 묶는다.
