# ADR-010: Pitcher Lab 상태 머신과 확정 상태 자동 저장

- 상태: 채택
- 날짜: 2026-07-22

## 맥락

Pitcher Lab은 훈련, 중요 이닝, 관계, 각성, 스카우팅, 회고와 두 번째 삶이 정해진 선후 관계로 이어진다. 클라이언트가 카운터와 단계를 직접 조립하면 순서를 건너뛰거나 숨은 성장 특성을 변조할 수 있고, 강제 종료 시 화면과 코어의 확정 revision이 달라질 수 있다.

## 결정

- Swift 코어가 `PitcherLabSnapshot`의 단계와 카운터를 소유하고 모든 전이를 검증한다.
- 공개 상태 전체를 `stateCommitment`에 묶어 클라이언트가 능력치, 잠재 범위, 피로 또는 진행 카운터를 바꾼 요청을 거부한다.
- 숨은 성장 특성은 run ID와 시드로만 재생성하며 RPC와 저장 데이터에 노출하지 않는다.
- 생성 시 프리셋 위에 정확히 5포인트를 배분한다. 두 번째 삶에서는 선택한 야구혼 분야 2점과 기억 카드 효과를 서로 독립적으로 적용한다.
- 첫 삶의 학교와 코치 후보 해금, 기억 카드, 최종 평가를 안정 ID로 보존한다.
- React 어댑터는 확정된 Lab 응답과 중요 이닝의 마지막 확정 투구를 버전형 로컬 자동 저장에 기록한다.
- 자동 저장은 체크섬이 있는 주 슬롯과 마지막 정상 백업 슬롯을 사용한다. 손상된 주 슬롯은 백업을 덮지 않고 별도 키로 보존한다.
- 화면에는 저장·복구 상태를 표시하고, 숨은 특성을 제외한 분석 JSON을 사용자가 직접 내보낼 수 있게 한다.

## 결과

- 동일 시드와 선택 순서가 동일한 두 실행은 같은 상태와 이벤트 해시를 만든다.
- 잘못된 단계, 잘못된 생성 포인트, 변조 상태는 코어 경계에서 거부된다.
- 앱을 다시 열면 마지막으로 확정된 Lab revision 또는 중요 이닝 투구부터 이어진다.
- 최신 저장이 손상되어도 마지막 정상 백업을 복구하고 손상본을 조사용으로 남긴다.
- 두 번째 삶의 숫자 변화가 사용자가 고른 야구혼·기억과 연결되고, 두 삶의 최종 결과를 같은 화면에서 비교할 수 있다.

## 후속 작업

- P3에서 브라우저 저장을 플랫폼 중립 `.dscareer` portable archive와 3개 순환 백업으로 통합한다.
- 저장 포맷 v2부터 명시적인 순차 마이그레이션과 디버그 번들 내보내기를 추가한다.
- 플레이테스트 로그에는 한 공 결정 시간과 선택 다양성 지표를 추가하되 외부 전송은 opt-in으로 유지한다.
