# UX 3차 스펙 — C. 정보 예산 (2026-09-03)

`docs/UX_ROUND2_SPEC_2026-09-03.md`의 A·B가 끝난 뒤 grok이 수행하는 다음 라운드다. 0절 절대 규칙·1절 기존 부품·3절 보고서 양식은 2차 스펙과 같다(그 파일을 먼저 읽는다). 보고서는 `docs/UX_ROUND3_REPORT_2026-09-03.md`.

## C0. 왜 이 방향인가 — 첫 제안에서 버린 것

처음 제안은 "화면당 텍스트 6개 이하"처럼 **숨기기** 위주였다. 검토 결과 세 가지가 틀렸다.

1. **숨기면 사라진다.** 접기·시트 뒤로 보낸 정보는 라이트 유저에게는 없는 것이고, 시뮬 유저에게는 매번 두 번 탭하는 비용이다(페르소나 P2 "숫자를 대조한다"). 예산은 **기본 밀도(설정 `설명 밀도 = 자동`)에만** 적용하고, `펼침`을 고른 유저에게는 지금처럼 다 보여 준다. 새 설정을 만들지 않는다.
2. **과부하의 진짜 원인은 층수가 아니라 "같은 주에 대한 화면이 둘"이고 "알림이 위에 쌓이는 것"이다.** 프로의 오늘/이번 주 세그먼트, 부상 카드+성장 카드+배너+후속 결과가 한 스크롤 상단에 동시에 뜨는 구조가 텍스트 수보다 먼저다. 이걸 없애면 텍스트 예산은 절반이 저절로 맞는다.
3. **의미 없는 숫자가 자리를 차지한다.** 헤더의 "훈련 14"(누적 훈련 횟수)는 유저의 어떤 결정에도 쓰이지 않는다. 숫자를 줄이는 게 아니라 **결정에 쓰이는 숫자로 바꾼다.**

그래서 C의 순서는 구조(C1·C2) → 헤더(C3) → 화면 분리(C4) → 카드(C5) → 자동 접힘(C6) → 측정(C7)이다. 린트로 눈썹을 금지하는 안은 오탐이 많아 버리고, 대신 **첫 뷰포트를 자동 측정**하는 스크립트(C7)로 대체한다.

## C1. 알림은 한 번에 하나 (프로·고교 공통)

근거: `personas/sim-veteran/17-first-decision.png` 전후, 보고서 §2-5. 부상 카드·성장 카드·주간 배너·결정 후속 카드가 스크롤 상단에 동시에 쌓인다.

- `CareerFlowNotices`(2차 pro-fix가 만든 뷰)를 **큐**로 바꾼다: 우선순위 부상 → 성장 → 결정 후속 → 주간 배너. 한 번에 한 장만 그리고, 확인(닫기)하면 다음 장. 마지막 장을 닫으면 아무것도 남지 않는다.
- 고교도 같은 큐: `HighSchoolCareerView` 상단의 훈련 결과 카드·"능력이 올랐습니다"·`SummaryBanner`를 같은 규칙으로.
- 닫지 않은 알림이 있으면 주 행동 바(훈련하기/1주 진행)는 비활성 대신 **알림 확인**을 먼저 요구한다(버튼 라벨을 `확인하고 계속`으로).
- 완료 조건: 부상+성장+후속이 동시에 발생하는 픽스처(`-uiTestReviewImprovementFixture`에서 `1주 진행` 3회)에서 상단에 카드가 한 장만 보이고, 세 번 닫으면 사라진다. 각 카드의 identifier 유지.

## C2. 프로 "오늘 / 이번 주" 세그먼트 제거

근거: P2 "오늘 탭에는 계획이 없고 이번 주로 가야 한다". 같은 주를 두 화면으로 나눈 것이 프로 첫 인상의 혼란이다.

- `AppShell.swift`의 세그먼트(`proViewPicker`)와 `TodayView`를 없애고, `CareerFlowView` 상단에 **상태 헤더** 하나를 둔다: 키아트(주차·구단·보직) + 타일 3개(피로·감독의 믿음·부상) + 시즌 진행바. 지금 `TodayView`의 것을 옮기되 "커리어 방향" 6줄은 옮기지 않는다(기록 탭에 이미 있다 — `RecordView` 목표판).
- `TodayView`의 긴장(`seasonTensions`)·최근 소식·최근 기록은 `CareerFlowView` 맨 아래 `ProgressiveDisclosure("소식")` 하나로.
- 삭제 대신 파일은 남기고 사용처만 끊어도 된다(`TodayView`를 참조하는 테스트: grep `TodayView(` in apps/ios/Tests → 있으면 헤더 뷰로 이름을 바꿔 테스트를 맞춘다).
- `-uiTestOpenProWeek` 인자는 무동작으로 남긴다(UI 테스트가 넘긴다).
- 완료 조건: 프로 탭(또는 B1 뒤 커리어 탭) 첫 화면에서 스크롤 없이 "주차·상태 3개·이번 주 계획 첫 카드"가 보인다. 오늘/이번 주 전환 UI가 없다.

## C3. 헤더 압축 — 결정에 쓰는 숫자만

근거: 현재 고교 헤더 = 키아트 190pt + 제목 + 초상 + 타일 3(피로·팀의 믿음·훈련) + 전망 칩 + 바람 칩 + 스킬트리 카드 + 성과 줄 ≈ 첫 뷰포트 전부.

- 타일 3개를 **피로 · 팀의 믿음 · 드래프트 전망**으로 바꾼다. "훈련 N" 타일 삭제(값은 기록 탭 3년 돌아보기에만). 전망 타일은 값 `51`, 캡션 `당락선 66`, 색은 2차 A3 규칙. 별도 전망 칩은 없앤다(중복).
- 피로 타일 캡션(2차 A5)은 **한 단어**만(`정상/지침/과로/탈진`). "훈련 성장 없음" 같은 결과 문장은 탈진 콜아웃(A5)에만.
- 바람 칩과 스킬트리 카드를 **한 줄 두 칩**으로: `바람 · 괴물 세대 ▸` `스킬 1/3 ▸`. 탭하면 지금의 시트/카드. 텍스트 라벨은 유지한다(아이콘만 두지 않는다 — 발견 가능성·VoiceOver).
- 키아트 높이: 훈련 루프 국면(`training`)은 140pt, 사건 국면(장 시작·각성·드래프트·유산)은 190pt(2차 B6와 합친다).
- 완료 조건: 훈련 국면 첫 뷰포트(iPhone 17, 874pt)에 헤더+칩 줄+챕터 목표 진행바+추천 훈련 카드 1장이 들어간다. 텍스트 덩어리 ≤ 8(C7로 측정).

## C4. 드래프트·유산을 두 화면으로

근거: 한 스크롤에 "지명 결과·이유·완료 카드·코치·공유·유산 3개·속마음·기억·재시작"이 있다. Peak-End 순간이 묻힌다.

- 1화면(결과): 키아트 + `지명 / 미지명` 도장 + 평가 점수 + 이유 칩 2개(2차 A3) + 주 행동 하나(`프로 커리어 시작` 또는 `다음 선수 준비`). 그 외 없음.
- 2화면(유산): 지금의 유산 선택·기억·속마음·공유. 1화면의 버튼을 누르면 온다. 되돌아가기 가능.
- 구현은 `phase`를 쪼개지 않고(저장 스키마 불변) `HighSchoolCareerView` 안의 로컬 `@State legacyStep`으로 한다. 앱을 껐다 켜면 1화면부터.
- 완료 조건: 지명·미지명 두 픽스처(`-uiTestDraftedCareerFixture`, `-uiTestUndraftedCareerFixture`)에서 1화면 텍스트 덩어리 ≤ 5, 버튼 1개.

## C5. 훈련 화면 — 추천 카드만 펼친다

근거: 카드 6장이 모두 같은 크기라 결정 피로. 2차 B3(추천 선택)를 전제로 한다.

- 추천 카드(선택된 카드)만 지금 크기(칩+접기). 나머지 5장은 **한 줄**(아이콘·제목·칩 2개)로 접고, 탭하면 선택되며 펼쳐진다. 한 번에 한 장만 펼쳐진다.
- 강도 세그먼트와 "+1이 나올 수도…" 전망 문장은 펼쳐진 카드 안으로 들어간다. 카드 밖에는 남지 않는다.
- "오늘의 기회" 콜아웃 카드 삭제. 해당 카드에 `기회` 칩(이미 있음)만 남긴다.
- 고정 바의 두 번째 줄(`같은 훈련 3번 연속` 설명)은 제목만 남기고 설명은 첫 회에만(SeenContentStore `hs.training.repeat.explained`).
- 완료 조건: 훈련 국면 첫 뷰포트에 카드 전체(추천 1 + 접힌 5)와 고정 바가 들어간다(iPhone 17). SE에서는 접힌 카드 3장까지.

## C6. 자동 접힘의 기억에 유효기간

근거: 설명 밀도 `자동`은 한 번 본 설명을 접는데, 2주 뒤 돌아온 유저는 규칙을 잊는다.

- `SeenContentStore`에 본 시각을 함께 저장(`[id: timestamp]`, 기존 문자열 배열 키는 마이그레이션해 유지). `ProgressiveDisclosure`는 마지막 본 시각이 14일 이전이면 다시 펼친다.
- 이 규칙을 `ProgressiveDisclosure`를 쓰지 않는 설명 문장에도 적용한다: 2차 이후 남은 설명 문장(투구 코치 팁, 훈련 반복 설명, 결정 타이밍 문장, 계약 안내)을 전부 `ProgressiveDisclosure` 또는 `SeenContentStore` 게이트로 감싼다. 대상 목록은 C7 측정으로 뽑는다(첫 뷰포트에 두 번 이상 나타나는 20자 이상 문장).
- 완료 조건: 단위 테스트 2개 — 14일 경과 시 재펼침, 배열 형식 저장본 마이그레이션.

## C7. 정보 예산 측정 스크립트

근거: 눈썹 린트는 오탐이 많다. 대신 실제 화면을 잰다.

- `tools/measure-info-budget.mjs`: 부팅된 시뮬레이터에서 `axe describe-ui`를 받아 첫 뷰포트(y < 874, 탭바 제외) 안의 텍스트 요소를 센다. 출력: 화면 id, 텍스트 덩어리 수, 20자 이상 문장 수, 버튼 수, 큰 숫자(폰트 크기로 판별 불가하므로 `AXLabel`이 숫자만인 요소) 수.
- 측정 대상 화면과 예산(자동 밀도 기준):

| 화면 | 텍스트 덩어리 | 20자+ 문장 | 버튼 |
|---|---|---|---|
| 고교 훈련(추천 펼침) | ≤ 8 | ≤ 1 | ≤ 3 |
| 고교 장 시작 | ≤ 8 | ≤ 2 | 1 |
| 투구 준비(3구 이후) | ≤ 6 | 0 | ≤ 3 |
| 결정 카드 | ≤ 9 | ≤ 1 | 3 |
| 드래프트 1화면 | ≤ 5 | ≤ 1 | 1 |
| 프로 주간(상태 헤더 포함) | ≤ 10 | ≤ 1 | ≤ 3 |

- `QACaptureUITests`나 별도 스크립트로 위 6화면에 도달해 측정값을 `apps/ios/releases/qa-1.2.9/round3/budget.json`에 남기고, 예산 초과는 보고서에 표로 적는다. 예산은 목표이지 CI 게이트가 아니다(이번 라운드에서는 실패시키지 않는다).
