## 백업 검증 절차

Android 공식 문서는 `disableIfNoEncryptionCapabilities`가 암호화 가능 여부에 따라 클라우드 백업을 제한하며 device-transfer와 규칙을 분리한다고 설명한다. 이 설정을 테스트 통과만을 위해 제거하지 않는다. 출처: https://developer.android.com/identity/data/autobackup

1. 대상 패키지·버전·서명·저장 모드, 실제 파일 위치, 빌드에 포함된 XML 및 백업 트랜스포트 기록.
2. LocalTransport에서 포함 파일과 암호화 조건을 분리 진단. 필요하면 별도 진단 빌드에서만 조건을 비교하고 production 정책과 구분.
3. 실기기 Google 백업 및 기기 간 이전을 별도 실행. 잠금 있음/없음 조건 기록. 실제 사용자 기기 초기화는 별도 명시적 승인 없이 실행하지 않고 전용 QA 기기/데이터 사용.
4. 복원 전후 선수·커리어·진행 중 투구·기록·설정 비교. 새 설치 ID 재연결 후 한 구 진행, 종료/재실행, 재저장, 수동 export/import 확인. 복원 후 ID 변경이 있으므로 파일 해시 동일성만을 합격 조건으로 삼지 않음.
5. OS 백업 상태를 앱이 확실히 판별할 수 있는지 확인한 뒤 안내 설계. 판별 불가라면 ‘자동 백업 꺼짐’을 단정하지 않고 조건부 설명과 수동 ‘백업 저장’을 제공. 수동 백업 성공으로 H-01 자동 복원을 닫지 않음.
