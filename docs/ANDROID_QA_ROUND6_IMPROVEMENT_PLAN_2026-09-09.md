# Android 6차 QA 후속 개선 계획 · 2026-09-09

근거: `ANDROID_E2E_QA_ROUND6_2026-09-09.md`, 6차 오류 대화 캡처, 현재 `PitchActivity`·`Phase7VerticalController`·5차 테스트 소스. 이번 작업은 계획 작성이며 앱 구현·기기 검증은 수행하지 않았다.

## 판단

- T-01~T-04는 6차 재검증 통과로 닫는다. 추가 화면 재설계나 저장 구조 개편을 시작하지 않는다.
- S-03은 **QA 오탐 철회로 종결**한다. 제품 수정으로 해결된 항목으로 집계하지 않는다. 5차의 ‘미재현·원인 미확정’ 상태를 이번 정정으로 대체한다. 과거 보고서는 당시 기록으로 보존하고 이 정정을 연결한다.
- U-01은 저장 유실이 확인된 결함이 아니라 **저장된 결과와 오류 안내가 어긋난 1회 관측**이다. 재현 실패 3회를 해결 증거로 사용하지 않는다.
- `performPhase8 failed` 0건은 PitchActivity의 모든 오류가 없다는 뜻이 아니다. 이번 코드 확인에서 로그 없는 catch 경로가 발견됐다.
- 콜드 스타트 회귀 근거는 없다. 이전 재개 지연의 재측정과 구분하고, 성능 최적화를 이번 우선 작업에 추가하지 않는다.

## 1순위 — U-01 진단 로그와 오류 안내의 정확성

### 소스로 확인한 사실

`submitSelectedPitch`는 예외를 로그에 남긴 뒤 ‘투구를 저장하지 못했습니다’를 표시한다. 반면 `consumeAfterAnimationComplete`는 **같은 문구를 표시하면서 로그를 남기지 않는다**. 이 메서드는 이미 커밋한 결과를 대상으로 `ConsumePitch`와 `MarkPitchTerminal`을 처리한다. 투구 결과 저장 이후의 후속 처리 실패까지 최초 투구 저장 실패로 안내할 수 있는 구조다.

불러오기, 연습 종료, 경기 종료, 다음 투구, 빠른 진행에도 로그 없는 catch가 있다. 여러 경로가 `Throwable`을 잡고 있으며 `onDestroy`는 Activity 코루틴을 취소한다. 취소·재생 완료 콜백 경합·후속 상태 전이 실패는 조사 후보지만 **U-01의 확정 원인은 아니다**. `boundary=committed`만으로 후속 처리까지 모두 성공했다고 판단하지 않는다.

### 구현할 내용

1. 오류 대화 경로를 공통 진단 함수로 연결한다. 작업 단계(load/submit/consume/terminal/next/finish/fastForward), 예외 종류·오류 코드·스택, correlation ID, session/pitch/command ID, 기대/현재 revision, 처리 전후 boundary, Activity 생명주기 상태, 앱 버전을 기록한다. 실제 명령 ID는 controller/store 경계에서 연결하고 UI에서 추정해 만들어 넣지 않는다.
2. 전체 세이브·선수 이름·설치 ID·백업 문자열을 통째로 로그에 넣지 않는다. 평상시 성공 경로를 매 프레임 기록하지 않고 실패와 복구 결과를 중심으로 남긴다. RC에서도 진단에 필요한 오류 코드와 단계가 남는지 검증한다.
3. 정상적인 생명주기 취소는 저장 실패 대화와 분리한다. `CancellationException`을 별도로 처리하고 종료된 Activity에 대화를 띄우지 않는다. 이미 시작된 durable 저장의 완료/복구 보장은 유지한다.
4. 실패 시 해당 session·pitch ID에 대응하는 durable 결과를 확인한다. 메모리 상태만 보고 저장 성공을 단정하지 않는다. 결과가 확인되면 결과 확인/후속 처리 재시도를 안내하고, 결과가 확인되지 않으면 저장 상태 미확인 또는 실제 저장 실패를 구분해 안내한다.
5. 재시도는 현재 실패 단계만 수행한다. 저장된 투구를 다시 던지거나 보상을 다시 적용하지 않는다. 오래된 콜백이 다음 투구를 완료 처리하지 않도록 session/pitch ID 일치를 확인한다. 일치하지 않는 상태는 성공으로 무시하지 않고 진단 후 현재 화면을 다시 맞춘다.

### 필요한 검증과 완료 기준

| 주입/재현 조건 | 기대 결과 |
| --- | --- |
| 결과 커밋 전 저장 실패 | 실패 로그와 적절한 안내, 허위 성공 없음 |
| 커밋 후 consume/terminal 처리 실패 | 저장된 결과 보존, 실패 단계·명령 추적 가능, 최초 투구 재실행 없음 |
| consume 이후 종료 표시 전 중단·재시작 | 남은 단계만 복구, 투구 수·퍼펙트·보상 증가 없음 |
| 화면 종료/재생 완료 콜백 중복/오래된 pitch ID | 정상 취소는 오류 대화 없음, 중복 처리·다음 투구 오염 없음 |
| 기존 세이브 유지 업데이트 후 첫 재개 | 로그와 화면/파일 상태를 함께 보존, 결과 확인→다음 공 정상 |

UI 오류 대화에는 대응하는 진단 기록이 있어야 한다. 동일 실패의 중복 로그는 제한한다. 신규 테스트용 오류 주입 장치는 테스트 빌드에만 포함한다. 한국어·영어·일본어 오류 안내와 실제 복구 액션을 함께 검증한다.

완료 보고에서는 ‘진단 누락·안내 분류 개선 완료’와 ‘U-01의 최초 원인 확인 여부’를 분리한다. 원인 미확정 상태에서 U-01 완전 해결을 주장하지 않는다.

## 2순위 — S-10을 동일 경로의 UI 증거로 닫기

현재 증거는 두 개로 나뉜다. `Round5NaturalFatigueTest`는 정상 커널 규칙으로 seed 7819의 프로 4주차·18구째 피로 80을 확인했다. `Round4LivePitchUiTest`는 별도로 준비한 피로 80/86/87 상태에서 버튼을 실행했다. 아직 **그 seed 여정으로 도달한 같은 상태를 UI에서 실행한 증거**는 없다.

검증 경로를 재사용 가능한 테스트 도우미로 만들고, 7819·power_prospect·구위 훈련·시즌 선택 첫 항목·포심/가운데/스트라이크/전력 투구·기존 테스트의 릴리스 값과 이닝 계속 규칙을 고정한다. 게임 커널이 생성한 상태를 native 저장/복원 경로로 연결한다. 피로나 진행 단계를 목표값으로 직접 바꾸지 않는다.

그 상태에서 실제 PitchActivity를 열어 버튼 노출→탭→등판 종료→저장→재시작을 확인한다. 버튼 직전/직후 화면과 투구 수·기록·boundary를 저장하고, 피로 79 및 이미 강판된 상태도 구분한다. 기본 수동 슬라이더 동작을 유지한다.

**완료:** 같은 seed와 상태의 생성 경로·native 저장·UI 실행을 연결하는 재현 스크립트와 증거. 자동 진행 버튼과 감독 강판이 중복으로 결과를 적용하지 않음. 자동화된 정상 규칙 여정임을 명시하며 실기기 수동 완주와 혼동하지 않는다.

## 3순위 — 실기기 검증

착수 시 연결 기기를 다시 확인한다. 6차 보고서 기준으로는 실기기가 없다. A53 한 대로 할 수 있는 검증부터 수행하고, 2대가 필요한 검증은 별도 항목으로 둔다.

| 장비/환경 | 실행 범위 | 통과 증거 |
| --- | --- | --- |
| A53 | 기존 세이브 유지 업데이트, 첫 재개, 중단/포기, 직접 슬라이더, 화면 크기·큰 글자, 알림·외부 음악 | 모델·OS·APK 해시·화면·로그·전후 핵심 저장 값 |

개인 기기를 초기화하는 테스트는 별도 동의 없이 수행하지 않는다. 장비가 없는 항목 때문에 코드 개선·로그·재현 스크립트 준비를 멈추지 않는다.

## 4순위 — 서명 RC 검증

착수 때 기존 RC 스크립트의 필수 설정 존재 여부를 검사한다. 현재 보고된 장애는 `BASEBALL_UPLOAD_KEYSTORE_PATH` 미설정이며, 그 값 하나만 채우면 다른 조건도 충족된다고 가정하지 않는다. 비밀번호·키 본문은 로그/보고서에 출력하지 않는다.

설정이 준비되면 실제 배포 후보 release를 만들고 서명·버전·패키지·최적화 설정·진단 로그 동작을 확인한다. 이전 호환 release 위 업데이트 설치 후 기존 진행, 첫 재개, 한 구 투구, 결과 확인, 다음 공, 알림을 검증한다. 패키지/서명이 다른 QA debug 설치를 release 업데이트 검증으로 대체하지 않는다.

**완료:** APK 해시·서명 인증서 식별값·빌드 조건·실기기 검증표. 조건이 없으면 미검증으로 유지한다. 이 계획에는 스토어 업로드·출시가 포함되지 않는다.

## S-03 및 기존 검사의 정리

오탐 철회로 추가 원인 조사·내비게이션 변경을 중단한다. 기존 전체 화면 검사는 일반적인 그리기 회귀 검사로 유지할 수 있지만, S-03 수정 효과를 입증한 검사로 설명하지 않는다. 중앙 노치·다른 테마의 정상 픽셀까지 결함으로 판단하지 않도록 현재 Pixel 검사 조건을 명시한다. 전 화면/전 장비에 대한 보증으로 확대하지 않는다.

앞으로 시각적 지적은 원본 파일·정확한 영역·밀도·노드 좌표와 필요한 픽셀 비교를 함께 기록한다. 육안 관찰과 수치 검증이 다르면 재현 조건부터 확인한다.

## 후속 산출물

1. 투구 오류 진단과 단계별 복구 안내 코드, 실패 주입 회귀 테스트.
2. seed 7819 고피로 상태 생성→native 저장→실제 UI 실행 증거.
3. 실기기/OS 복원/TalkBack/RC의 완료·미검증을 나눈 검증표.
4. 6차 개선 결과 문서. S-03은 오탐 철회, U-01은 원인 확인 수준을 별도로 표시한다.

작업 순서는 진단·안내 개선 → seed UI 검증 → 연결 가능한 실기기 → 서명 RC다. 장비·서명 준비 상태는 첫 단계에서 확인해 후반 검증의 대기를 줄인다.
