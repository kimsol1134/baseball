## 2. 기존 플레이 경험의 변화

### P2 — 변경 안내가 실제 게임 규칙 변경을 설명하지 않는다

[릴리스 노트](/Users/solkim/Dev/baseball/marketing/appstore/RELEASE_NOTES_1.2.10.md)는 기록·앨범·큰 글씨·현지화 개선을 중심으로 설명한다. 하지만 1.2.9 출시 설정 커밋 `9e724174`와 현재를 비교하면 경기 확률, 고교 평가/장별 직접 등판, 프로 등판 길이와 평가 등도 바뀌었다. 이 기준 커밋과 실제 판매 IPA의 전체 소스 일치를 이번에 증명한 것은 아니므로 바이너리 수준의 완전한 변경 목록으로 간주하지 않는다.

- 고교: 진행 중인 v4 이상 회차는 다음 명령 결과를 저장하면서 v9로 이동한다. 이미 저장된 능력·일정·완료 기록을 다시 생성하지는 않지만 이후 경기와 드래프트 평가 기준이 달라진다. v3 이하는 보호된다.
- 프로: 주간 행동의 스냅샷 교체는 저장된 `proRulesVersion`을 유지한다. 새 커리어와 다음 시즌 전환은 v14를 사용한다. 코드 주석의 '다음 명령부터'를 모든 프로 행동의 실제 동작으로 받아들이면 안 된다.
- 프로 v14는 실전 성적에 따른 감독 신뢰의 양수·음수 효과를 모두 두 배로 한다. 예를 들어 다른 보상 전 2K·2BB·3실점의 성적 항은 -9에서 -18이 된다. 모든 기존 프로 사용자가 업데이트 직후 즉시 이 영향을 받는다는 뜻은 아니다.

추가 고교 전환 실험: 24개 시드, v4 동결 엔진에서 진행한 334개 훈련 직전 상태에 동일 행동을 v4/v9 엔진으로 적용했다. 기록된 능력·성적이 같은 비교에서 평가점수−지명문턱 마진이 나빠진 사례는 없었고, 차이는 +15~+21이었다. 예시: 6장, 같은 능력·성적에서 55/66 → 54/50. 중요 경기 결과를 합성 보고서로 제공한 전환 실험이므로 실제 손투구 지명률이나 이후 난이도 무피해 증거는 아니다.

권고: '투구 조작은 그대로'라는 안내와 별개로 경기·평가 조정 및 적용 시점을 알린다. 기존 회차의 약속을 가장 보수적으로 보호하려면 고교도 회차 완료 전까지 구규칙을 유지하고 다음 회차부터 적용하는 정책을 검토한다. 이번 검토에서는 정책이나 난이도를 변경하지 않았다.

### 방금 적용한 퍼펙트 수정 자체의 위험은 낮음

수정은 새 수동 입력의 판정만 변경한다. 기존 저장의 정확도·완료 경기·능력·계승 자원을 재계산하지 않는다. 미터 좌표상 반올림으로 약 2.55%였던 허용 폭이 표시된 2.5%와 일치하게 된다. 이는 실제 사용자 성공률이 2% 낮아진다는 측정 결과가 아니다. 중앙 부근 감속과 성장에 따른 감속 변화는 유지된다.

iOS 자동 릴리스 기본값은 OFF이며 `register(defaults:)`는 이미 저장된 ON 선택을 덮어쓰지 않는다. 현재 기존 시뮬레이터의 저장 값도 OFF로 확인했다. Android의 별도 보정 제거는 iOS 바이너리에 포함되지 않는다.

## 4. 권장 제출 순서

1. 혼합 버전 고교 저장 위험을 해결하고 구저장 왕복 회귀를 추가한다.
2. 최종 변경 목록과 릴리스 노트를 확정한다. 현재 로컬 수정이 준비된 IPA와 같다고 간주하지 않는다.
3. 새 서명 IPA를 만들어 실제 업데이트 설치 및 일본어 필수 조건을 해당 버전·빌드·해시 기준으로 확인한다. 기존 세이브를 지우는 방식으로 업데이트 검증을 대체하지 않는다.
4. 조건 충족 후 심사 제출 여부를 결정한다. 승인 후 자동 업데이트는 7일 단계적 출시를 권한다. 수동 다운로드는 즉시 가능하므로 단계적 출시가 모든 노출을 차단하지는 않는다. [Apple 단계적 출시 안내](https://developer.apple.com/help/app-store-connect/update-your-app/release-a-version-update-in-phases).

## 후속 구현 및 사용자 지시 변경

사용자가 순차 개선을 승인한 뒤, 심사 제출을 보류하고 최신 화면의 App Store 스크린샷·Remotion 영상을 먼저 제작하도록 변경했다. 따라서 업로드·심사 제출은 진행하지 않았다.

저장 보호는 고교와 프로 모두 `v2` 로컬 파일/iCloud 키로 분리했다. 새 공간에 아무 저장·백업·묘비도 없을 때만 구버전의 정상 후보를 읽어 옮긴다. 이전은 새 로컬 저장에 성공한 뒤 노출하고, 구버전 공간은 쓰거나 삭제하지 않는다. 새 공간이 존재하면 구버전이 더 높은 revision을 써도 가져오지 않는다. 구버전과 신버전에서 따로 진행한 내용을 자동 병합하는 기능은 아니다. 두 기기 모두 최신 버전으로 사용하는 것이 필요하며 구버전 원본은 보존된다.

`SaveSyncGenerationTests`의 8개 검사로 원본 보존, 다른 기기의 구버전 덮어쓰기, 새/옛 삭제 묘비, 백업, 이전 실패, 새 저장 손상, 실제 훈련 진도 유지가 통과했다. ios-layers 전체 81개와 변경 후 iOS 저장·복구·환생·투구 관련 140개도 통과했다. 물리적으로 두 iCloud 기기를 왕복한 결과로 확대하지 않는다.
