# 핵심 재미 중심 사용자 경험 재검토

2026-09-05. 현재 작업 폴더의 소스, 기존 실행 캡처, 지난 QA 결과를 검토했다. 이번 검토에서 새 사용자 플레이 관찰이나 유지율 실험을 수행하지 않았다. 앱 코드와 밸런스는 변경하지 않았다.

## 판정

슬라이더 조작과 제구 성장을 연결한 방향은 타당하다. 기본 수동 조작, 실제 판정과 표시의 일치, 퍼펙트 유지, 저장 호환성은 개선되었다. 그러나 현재 결과를 핵심 재미가 최적화된 UX 완성판이라고 평가하지 않는다. 성장의 실제 체감, 다음 투구로 돌아가는 흐름, 한 캐릭터의 환생이라는 정체성이 아직 충분히 연결되지 않았다.

## 가장 먼저 고칠 부분

### 1. P1 — 성장 안내와 당장 던지는 느낌이 엇갈릴 수 있다

실행 캡처의 `제구 25 → 27`은 저장용 제구 35 → 36에 해당한다. 현재 공식에서 안정 구간은 18.0% → 18.1%로 증가한다. 가로 300pt 게이지라면 차이는 0.3pt다. 효과는 실제지만 한 번의 변화로 눈이나 손이 구분하기 어렵다.

같은 캡처에는 피로 11(+6)이 표시된다. 피로는 별도 규칙으로 미터를 빠르게 한다. 예를 들어 명목 구속 135km/h, 모션 축소 끔을 같게 두면 다음과 같다.

| 조건 | 훈련 전 | 훈련 후 |
|---|---:|---:|
| 저장용 제구 | 35 | 36 |
| 화면용 제구 | 25 | 27 |
| 피로 | 5 | 11 |
| 안정 구간 폭 | 18.0% | 18.1% |
| 계산상 한 번 통과하는 안정 구간 시간 | 167.49ms | 165.81ms |

이 시간은 고정 구속을 가정한 식의 계산이며 실제 기기에서 측정한 입력 성공률이 아니다. 실제 명목 구속, 피로에 따른 구속 변화, 긴장, 조준도 함께 작용한다. 따라서 모든 훈련 뒤 조작이 어려워진다고 일반화할 수는 없다. 확인된 문제는 기본 구간 폭만 커졌다는 안내로 현재 조작 난이도까지 좋아진 듯한 인상을 줄 수 있다는 점이다.

권고: 영구 성장과 현재 피로를 구분하고, 작은 성장에는 작은 피드백을 준다. 체감 가능한 단계 상승에서 구간 변화와 축하를 강조하는 안을 비교한다. 최대 구간을 무조건 크게 만들거나 작은 변화의 그림을 과장하지 않는다. 성장 체험을 제공한다면 같은 구속·피로 조건의 별도 연습에서 비교하고 실제 경기의 피로 비용을 지우지 않는다.

### 2. P1 — 성장 화면은 여전히 한 변화를 여러 번 설명한다

현재 성장 캡처에는 `제구 +2`, `제구 25 → 27`, `안정 구간이 넓어졌어요`, 이전 표시선 설명, 노린 코스로 던질 힘을 키웠다는 문장이 함께 나온다. 각각은 맞는 정보지만 한 번의 보상에 집중하기에는 반복이 많다. 이어지는 각성 카운터·안내·전조·트리 버튼까지 읽으면 훈련 한 번이 긴 설명 구간이 된다.

권고: 첫 화면의 성장 결과는 핵심 변화 하나, 전후 비교 하나, 필요한 비용/경고로 제한한다. 상세 설명과 범례는 처음 필요한 순간이나 펼쳐보기에서 제공한다. 체력 등 다른 능력도 숫자의 의미가 아직 약하지만, 이를 해결하기 위해 여러 그래프를 동시에 늘리지는 않는다.

근거: [훈련 결과 구성](/Users/solkim/Dev/baseball/apps/ios/Sources/Features/HighSchool/HighSchoolTrainingResultViews.swift:100), [Android 성장 구성](/Users/solkim/Dev/baseball/apps/android/app/src/main/java/com/solkim/baseball/android/CorePlayerViews.kt:89). 변화의 중요도에 맞는 피드백과 행동 가까운 상태 표시는 [Apple 피드백 지침](https://developer.apple.com/design/human-interface-guidelines/feedback)과도 맞는 방향이며, 이 지침 자체가 재미의 실증 근거는 아니다.

### 3. P1 — 환생의 기대감이 다음 투구보다 설명으로 이어진다

iOS의 환생 후 프롤로그는 이전 선수의 편지, 시작 능력 비교, 프롤로그 순서다. 수치 계승은 이해할 수 있지만, 유저가 기대하는 새 몸으로 던져보는 행동보다 읽을 내용이 먼저 온다. 환생 화면의 지난 생 탈삼진 갱신 목표도 첫 등판보다 먼 회차 전체 목표다.

권고: 환생 후 주요 행동을 먼저 올리고, 편지·계보·상세 기록은 짧은 요약과 펼쳐보기로 둔다. 새 능력으로 바로 한 구를 체험할 수 있게 하되 반복 유저에게 매번 필수 튜토리얼을 추가하지 않는다. 첫 등판에 해당하는 가까운 목표를 우선하고 지난 생 전체 기록은 장기 목표로 유지한다.

근거: [환생 후 표시 순서](/Users/solkim/Dev/baseball/apps/ios/Sources/Features/HighSchool/HighSchoolCareerView.swift:728), [현재 다음 생 목표](/Users/solkim/Dev/baseball/apps/ios/Sources/Features/HighSchool/RunRecapView.swift:156). 기존 일본어 두 번째 생 캡처는 구조 확인의 보조 근거이며 최신 모든 문구/수치를 대표하는 캡처로 사용하지 않았다.

### 4. P1 — ‘다시 태어난 나’와 ‘유산을 받은 다른 선수’의 서사가 섞인다

같은 이름일 때 현재 문구는 `같은 이름을 이어받은 새 선수에게`다. 기록과 이름은 이어져도 다른 후계자를 만드는 이야기로 읽힐 여지가 있다. 사용자가 원하는 한 캐릭터를 환생시키며 키우는 감정과는 거리가 생긴다.

권고: 같은 캐릭터로 빠른 환생하는 기본 흐름은 `지난 생의 나`, `다시 태어난 나`, `내가 이어온 감각`으로 통일한다. 다른 이름이나 설정으로 새 캐릭터를 만드는 선택은 별도로 설명한다. 통일된 서사 없이 초상이나 수치만 보존하는 것으로 애착을 해결했다고 판단하지 않는다.

근거: [현재 수신자 문구](/Users/solkim/Dev/baseball/apps/ios/Sources/Features/HighSchool/PlayerBondStory.swift:645), [한국어 문구 생성](/Users/solkim/Dev/baseball/apps/ios/Sources/Features/HighSchool/PlayerBondStory.swift:654).

## 유지할 것

- 기본 수동 슬라이더와 정중앙 퍼펙트의 구분.
- 안정 구간 표시·햅틱·실제 점수를 같은 규칙으로 연결한 것.
- 누르고 있는 동안 해당 투구의 제구와 구간을 고정한 것.
- 초록 구간의 릴리스와 조준 흔들림을 구분한 결과 문구.
- 실제 다음 생 시작값 비교와 저장·재생 호환성.

## 다음 검증의 기준

1. 초보자가 설명 없이 초록 구간과 정중앙 퍼펙트의 차이를 이해하는가.
2. 같은 조건의 비교에서 성장 전후를 구분하고 어떤 조작이 편해졌는지 말할 수 있는가.
3. 훈련 뒤 어려워졌을 때 성장 실패와 피로 누적을 구분하는가.
4. 환생 직후 다음 행동을 바로 찾고, 진행을 방해받았다고 느끼지 않는가.
5. ‘여러 선수를 교체했다’보다 ‘내 캐릭터가 다시 도전한다’고 이해하는가.

기술 테스트 통과는 위 질문에 대한 사용자 검증을 대신하지 않는다. 기존 2,048쌍 검사는 추가 보정의 상한을 본 고정 조건 검사이며, 제구의 전체 효과나 육성 전략의 우열·장기 재미를 입증하지 않는다.
