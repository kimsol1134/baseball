# 환생 누적 각성 스킬트리 최종 구현 계획

- 작성일: 2026-08-12
- 대상: iOS 고교 커리어와 `SimulationCore`
- 상태: 구현 기준안
- 목표: 여러 번 환생해 18개 각성을 모두 숙련하고, 최종적으로 모든 각성 효과를 동시에 사용하는 궁극의 선수를 만들 수 있게 한다.

## 1. 최종 결정

**18개 스킬 효과를 일반 회차에 그대로 영구 누적하는 안은 채택하지 않는다.** 대신 아래 세 층으로 나눈다.

1. **계보 숙련**: 정상 회차를 마치고 환생하면 그 회차에서 선택한 각성이 영구 숙련된다.
2. **이번 생의 공명**: 일반 회차에서는 숙련 여부와 무관하게 세 각성만 실제 능력으로 활성화한다.
3. **전생 통합**: 18개를 모두 숙련하면 별도의 자유 플레이 모드가 열리고, 이 모드에서만 18개 효과를 모두 동시에 적용한다.

이 결정은 다음 두 요구를 함께 만족한다.

- 환생을 반복할수록 스킬트리가 실제로 채워지고 상위 스킬에 더 빨리 접근한다.
- 일반 회차의 `세 번뿐인 각성`과 빌드 선택은 계속 의미가 있다.
- 끝까지 플레이한 사람은 실제로 모든 스킬을 사용하는 궁극의 캐릭터를 얻는다.

## 2. 왜 단순 영구 누적이 최선이 아닌가

현재 각성 18개는 작은 패시브가 아니라 완성된 회차용 능력 보정이다. 예를 들어 개별 각성이 구위·제구·변화·체력을 최대 5점, 구종별 헛스윙·움직임·제구를 최대 7점가량 바꾼다. 이를 매 환생마다 상시 누적하면 다음 문제가 생긴다.

### 2.1 능력치 상한이 너무 빨리 무너진다

선수 능력과 구종 프로필은 대부분 20~80으로 제한된다. 18개 효과를 모두 더하면 여러 능력이 80에 붙어 이후 훈련, 재능 만개, 기억, 야구혼, 대표 유산의 보상이 무의미해진다.

### 2.2 기존 난도 곡선이 누적 성장을 감당하지 못한다

`DifficultyScale.rebirthCeiling`은 현재 4다. 환생 난도 보정은 빠르게 상한에 도달하지만 영구 각성은 계속 쌓이므로, 몇 회차 뒤에는 경기 선택과 투구 실행이 사실상 결과에 영향을 주지 않게 된다.

### 2.3 스킬트리의 선택이 수집 체크리스트로 축소된다

지금 구조의 핵심은 세 번으로 한 갈래를 깊게 파거나 여러 갈래를 얕게 가져가는 선택이다. 모든 과거 효과가 항상 활성화되면 현재 회차에서 무엇을 고르는지는 장기적으로 중요하지 않다.

### 2.4 밸런스를 맞추기 위해 적도 같이 올리면 성장 보상이 사라진다

영구 스킬 수만큼 상대 능력을 자동으로 올리는 방식은 숫자만 커지고 체감은 제자리인 레벨 스케일링이 된다. 궁극의 캐릭터를 만들었다는 보상을 스스로 상쇄하므로 사용하지 않는다.

### 2.5 기존 시스템과 역할이 겹친다

이 게임에는 이미 야구혼, 기억, 대표 유산, 재능 돌파가 있다. 각성까지 같은 방식의 상시 능력치 계승으로 만들면 각 시스템의 설명과 선택 이유가 흐려진다.

## 3. 검토한 대안

| 대안 | 장점 | 치명적 문제 | 판정 |
|---|---|---|---|

## 4. 플레이어가 이해할 최종 규칙

### 4.1 첫 회차

- 기존처럼 고교 3년 동안 각성 세 번을 선택한다.
- 선택 즉시 해당 각성의 현재 효과가 적용된다.
- 회차를 끝내고 계승을 확정하면 선택한 세 각성이 계보에 영구 숙련된다.

### 4.2 다음 일반 회차

- 숙련 각성은 금색으로 계속 표시된다.
- 숙련 각성은 상위 노드의 선행 조건을 충족한다.
- 숙련 각성 자체는 일반 회차 시작 능력치에 자동으로 다시 적용되지 않는다.
- 이번 생의 각성 순간에는 다음 둘 중 하나를 고를 수 있다.
  - 아직 숙련하지 않은 각성: 이번 생에 활성화하고 회차 완료 시 새로 숙련한다.
  - 이미 숙련한 각성: 이번 생에 다시 공명시켜 해당 효과를 활성화한다.
- 한 회차에서는 같은 각성을 두 번 공명할 수 없으며 총 세 번만 고른다.

### 4.3 상위 스킬 접근

- 선행 조건 판정에는 `영구 숙련 + 이번 생에 선택한 각성`의 합집합을 사용한다.
- 예: 전생에서 힘 1단과 2단을 숙련했다면 다음 생 첫 각성에서 힘 3단을 선택할 수 있다.
- `각성의 전조` 규칙은 유지한다. 전조가 충분하면 같은 갈래에서 한 단계만 건너뛸 수 있다.
- 숙련한 스킬을 이번 생에 다시 공명시키는 경우에는 이미 배운 기술이므로 선행 조건을 다시 요구하지 않는다.

### 4.4 숙련 획득 시점

- 정상 회차의 `confirmLegacy()`가 성공적으로 저장된 뒤에만 숙련을 확정한다.
- 미지명도 정상적인 한 생의 결말이므로 숙련을 얻는다.
- 진행 중 앱 종료, 저장 실패, 회차 포기, 기록 없는 시드 도전에서는 숙련을 얻지 않는다.
- 저장 실패 시 기존 `confirmLegacy()` 롤백과 함께 숙련 변경도 반드시 롤백한다.

### 4.5 완성 속도

- 한 회차에 최대 3개의 새 각성을 숙련할 수 있다.
- 중복 공명을 전혀 하지 않고 새 스킬만 고르면 6회차 완료 시 18개를 모두 숙련한다.
- 7회차부터 `전생 통합`을 선택할 수 있다.
- 플레이어가 좋아하는 세 스킬을 반복 공명하면 완성은 늦어지지만, 이는 의도된 선택이다.

## 5. 전생 통합: 궁극의 캐릭터

### 5.1 해금과 진입

- `masteredAwakenings`가 `AwakeningID.allCases`와 정확히 같을 때 해금한다.
- 새 선수 설정 화면에 `전생 통합` 카드를 표시한다.
- 자동으로 강제하지 않는다. 플레이어는 계속 일반 회차를 선택할 수 있다.
- 시작 전 다음 사실을 명시한다.
  - 모든 각성 효과가 동시에 적용된다.
  - 자유 플레이 기록이다.
  - 경쟁 성적표에는 제출되지 않는다.

권장 문구:

> 열여덟 가지 감각이 한 몸에 모였습니다. 모든 각성이 깨어난 자유 플레이로 시작합니다.

### 5.2 효과 적용

- 회차 시작 시 `AwakeningTree.nodes`에 정의된 고정 순서로 18개 기존 효과를 정확히 한 번 적용한다.
- `Set` 순회 순서에 기대지 않는다. 중간 clamp와 감산 효과 때문에 적용 순서가 달라지면 같은 저장이 다른 선수가 될 수 있다.
- 각 효과를 새로 재해석하거나 배율로 줄이지 않는다. 이 모드는 의도된 파워 판타지다.
- 최종 능력과 모든 구종 프로필은 기존 20~80 및 구속·피로 상한을 계속 지켜야 한다.
- 전생 통합을 이유로 상대에게 숨은 자동 보정을 추가하지 않는다. 난도는 사용자가 고른 기존 난도를 따른다.

### 5.3 각성 마일스톤 처리

전생 통합 회차에서도 기존 일정에는 각성 국면 세 번이 남아 있다. 선택지가 0개인 채 멈추면 안 된다.

- 각성 국면은 `통합 확인` 카드로 바꾼다.
- 버튼 문구는 `전생을 하나로 잇는다`로 한다.
- 누르면 추가 능력 보정 없이 다음 마일스톤으로 진행한다.
- 세 장의 문구는 1·2·3번째 통합에 따라 다르게 하되, 새 규칙이나 추가 보상을 만들지 않는다.
- 엔진에 명시적인 `confirmLineageUnisonAwakening` 명령을 추가한다. UI에서 상태를 임의로 건너뛰지 않는다.

### 5.4 기록과 경쟁 경계

전생 통합은 강함을 즐기는 최종 보상이지 경쟁 최적해가 아니다.

- 로컬 회차 기록과 아카이브에는 남긴다. 카드에 `전생 통합` 배지를 표시한다.
- 회차 번호와 `highest_life`는 정상적으로 갱신한다. 이는 실력 점수가 아니라 플레이 이력이다.
- Game Center의 `hall_of_fame_score`, `career_strikeouts`에는 제출하지 않는다.
- 시드 공유 도전, 공정 비교, 경쟁 성적 제출에는 사용할 수 없다.
- 주간 플레이 횟수와 연속 플레이는 인정해도 된다. 단, 전생 통합 성적으로 추가 경쟁 보상을 산정하지 않는다.
- 프로 커리어로 이어질 경우 경쟁 제외 플래그도 프로 저장에 전달해야 한다. 고교에서만 막고 프로 리더보드가 열리는 우회로를 남기지 않는다.

## 6. 용어와 상태 모델

구현 전체에서 아래 용어를 혼용하지 않는다.

| 용어 | 의미 | 지속 범위 | 능력 효과 |
|---|---|---|---|
| 숙련 `mastered` | 과거 삶에서 배워 계보에 남은 노드 | 계보 영구 | 일반 회차에서는 없음 |
| 공명 `resonated/selectedThisLife` | 이번 생의 세 선택 | 현재 회차 | 기존 각성 효과 100% |
| 활성 `active` | 현재 선수에게 실제 적용된 각성 | 현재 회차 | 일반=공명 3개, 통합=전체 18개 |
| 전생 통합 `lineageUnison` | 전체 숙련 뒤 선택 가능한 궁극 모드 | 해당 회차 | 전체 18개 효과 100% |

`selectedAwakenings`는 기존 호환을 위해 **이번 생에 선택한 각성**이라는 뜻을 유지한다. 영구 숙련을 이 배열에 섞지 않는다. 섞으면 기존 UI의 `3/3`, 업적, 약속, 대표 유산 근거가 모두 18개를 현재 선택으로 오해한다.

## 7. 데이터 모델 변경

### 7.1 앱 계승 저장

`HighSchoolCareerStore.Inheritance`에 다음 optional 필드를 추가한다.

```swift
var masteredAwakenings: [AwakeningID]? = nil
```

규칙:

- 저장 순서는 항상 `AwakeningTree.nodes` 순서로 정규화한다.
- 중복과 알 수 없는 값은 제거한다.
- 런타임 판정에는 `Set`을 써도 저장과 해시에는 정렬된 배열을 쓴다.
- `nil`과 빈 배열은 런타임에서 동일하게 0개로 해석한다.

### 7.2 코어 시작 입력

`StartHighSchoolCareerParams`에 다음 값을 추가한다.

```swift
public let masteredAwakenings: [AwakeningID]?
public let awakeningRunMode: AwakeningRunMode?
```

```swift
public enum AwakeningRunMode: String, Codable, Sendable {
    case normal
    case lineageUnison = "lineage_unison"
}
```

- 기록 없는 challenge 시작은 숙련을 빈 배열로 전달하고 모드는 `.normal`로 고정한다.
- `.lineageUnison`은 코어에서도 18개 전수 숙련을 검증한다. UI 잠금만 믿지 않는다.

### 7.3 진행 스냅숏

`HighSchoolCareerSnapshot`에 다음 optional 필드를 추가한다.

```swift
public let masteredAwakenings: [AwakeningID]?
public let awakeningRunMode: AwakeningRunMode?
```

- 진행 중인 회차는 시작 당시 숙련 목록을 동결한다.
- 다른 기기에서 계보가 갱신돼도 진행 중 선수의 트리가 중간에 바뀌면 안 된다.
- 두 필드를 state commitment에 정규화해 포함한다.
- 기존 저장본의 `nil`은 빈 숙련·일반 모드로 해석한다.

### 7.4 실제 활성 목록

코어에 한 곳의 파생 함수를 둔다.

```swift
func activeAwakenings(for state: HighSchoolCareerSnapshot) -> [AwakeningID]
```

- 일반 모드: `state.selectedAwakenings`
- 전생 통합: `AwakeningTree.nodes.map(\.id)`

화면, 아카이브, 대표 유산 근거처럼 “실제로 이 선수에게 활성화된 기술”이 필요한 곳은 이 함수를 사용한다. 약속의 `세 번의 각성`처럼 “이번 생에 직접 고른 횟수”가 필요한 곳은 기존 `selectedAwakenings`를 사용한다.

### 7.5 프로 경쟁 자격

전생 통합 선수가 프로에 진입할 수 있으므로 고교의 모드를 프로 저장까지 전달한다.

권장 필드:

```swift
public let competitiveEligibility: CompetitiveEligibility?
```

최소 값은 `eligible`과 `lineageUnisonFreePlay`다. 옛 저장의 `nil`은 `eligible`로 본다. 리더보드 제출 직전 한 곳에서 이 값을 검사한다.

## 8. 트리 판정 변경

현재 `AwakeningTree.available(selected:sparks:)`를 무리하게 확장하지 말고, 기존 동작을 보존하는 오버로드를 추가한다.

권장 시그니처:

```swift
public static func available(
    mastered: [AwakeningID],
    selectedThisLife: [AwakeningID],
    sparks: Int?
) -> [AwakeningID]
```

판정 순서:

1. `selectedThisLife`에 이미 있는 노드는 제외한다.
2. 이미 숙련한 노드는 이번 생에 공명할 수 있으므로 선택 가능하다.
3. 미숙련 노드는 부모가 `mastered ∪ selectedThisLife`에 있으면 선택 가능하다.
4. 전조가 충분하면 현재 규칙대로 같은 갈래에서 한 단계만 건너뛸 수 있다.
5. 반환 순서는 `AwakeningTree.nodes`의 고정 순서를 따른다.

기존 `available(selected:sparks:)`는 `mastered: []`로 새 함수에 위임해 기존 테스트와 다른 소비자를 깨뜨리지 않는다.

전조로 부모를 건너뛰어 얻은 상위 스킬은 정상적인 숙련이다. 다음 생에 부모가 아직 미숙련이어도 그 상위 스킬을 삭제하거나 부모를 자동 숙련시키지 않는다. 해당 상위 스킬 자체는 재공명할 수 있고, 다른 미숙련 노드의 선행 조건은 원래 트리 정의대로 판정한다.

## 9. 효과 적용 규칙

### 9.1 일반 회차

- 시작 시 숙련 목록만으로는 `pitcher`를 변경하지 않는다.
- `chooseAwakening`에서 선택한 노드에 기존 `applyAwakening`을 한 번 호출한다.
- 숙련 노드를 공명하더라도 동일하게 한 번만 적용한다.
- 저장 복원 시 `pitcher`에 이미 적용된 효과를 다시 계산하거나 재적용하지 않는다.

### 9.2 전생 통합 회차

- 새 회차 생성 과정에서 프리셋, 재능, 야구혼, 기억/대표 유산 적용 순서를 먼저 유지한다.
- 그 다음 18개 각성 효과를 `AwakeningTree.nodes` 순서로 한 번 적용한다.
- `careerStartingPitcher`는 전생 통합 효과까지 반영된 시작 선수로 저장한다. 그래야 3년의 직접 성장량이 각성 보너스를 성장으로 잘못 계산하지 않는다.
- 이후 통합 확인 세 번은 능력치를 다시 적용하지 않는다.

## 10. 계승 확정과 마이그레이션

### 10.1 신규 회차 완료

`HighSchoolCareerStore.nextInheritance`가 다음 숙련 목록도 계산하게 한다.

```text
nextMastered = previous.masteredAwakenings ∪ current.selectedAwakenings
```

- challenge 회차에서는 이 함수를 통한 숙련 변경이 일어나지 않는다.
- 전생 통합 회차에서는 이미 전수 숙련이므로 목록은 그대로다.
- `confirmLegacy()`의 기존 저장 성공/실패 원자성을 그대로 사용한다.

### 10.2 기존 사용자 보상 복원

업데이트 전에 여러 회차를 끝낸 사용자의 노력을 0으로 만들지 않는다.

- 저장 스키마를 2에서 3으로 올린다.
- v1/v2 복원 시 `archive.compactMap(\.awakenings).flatMap`의 합집합으로 숙련을 한 번 백필한다.
- 아카이브에 각성 정보가 없는 아주 오래된 회차는 추측하지 않는다.
- 현재 진행 중 회차의 `selectedAwakenings`는 아직 끝난 삶이 아니므로 백필에 포함하지 않는다.
- 백필 결과도 `AwakeningTree.nodes` 순서로 정규화하고 다음 저장부터 v3로 기록한다.
- 마이그레이션은 멱등이어야 한다. 앱을 여러 번 복원해도 숙련 수가 늘거나 줄지 않는다.

### 10.3 삭제와 동기화

- `deleteProgress()`는 숙련 목록도 다른 계승 데이터와 함께 삭제한다.
- iCloud는 기존 revision 승자 규칙을 유지한다. 이번 작업에서 별도의 집합 병합 CRDT를 만들지 않는다.
- 계승 확정 직후의 result-less 저장에도 숙련 목록이 반드시 포함돼야 한다.

## 11. UI 계획

### 11.1 선수 설정 화면

일반 회차 카드에 다음 정보를 표시한다.

- `계보 각성 7/18`
- `이번 생에 공명할 수 있는 각성 3회`
- 다음으로 열 수 있는 상위 스킬이 있으면 한 줄 추천

권장 설명:

18/18일 때 `전생 통합` 선택 카드를 추가한다. 일반 회차 버튼을 없애지 않는다.

### 11.2 스킬트리 화면 상태

노드 상태를 색만으로 구분하지 말고 아이콘과 문구를 함께 쓴다.

| 상태 | 시각 표현 | 접근성 라벨 예시 |
|---|---|---|
| 미숙련·잠김 | 흐린 윤곽 + 자물쇠 | `잠김, 먼저 폭발하는 직구 필요` |
| 미숙련·선택 가능 | 밝은 윤곽 + `새 각성` | `새로 숙련 가능, 지금 선택할 수 있음` |
| 영구 숙련 | 금색 채움 + 계보 아이콘 | `계보에 숙련됨, 이번 생에 공명 가능` |
| 이번 생 공명 | 금색/강조 테두리 + 체크 | `이번 생에 활성화됨` |
| 새로 선택·숙련 대기 | 파란 채움 + 별 | `이번 생에 활성화됨, 환생하면 숙련됨` |

상단 진행 문구는 기존 `3/3` 하나를 다음 두 줄로 분리한다.

- `계보 숙련 7/18`
- `이번 생 공명 2/3 · 남은 선택 1회`

### 11.3 회차 결산

- 새로 숙련된 각성을 결산에서 먼저 보여 준다.
- 중복 공명은 `다시 되살린 감각`, 신규는 `계보에 새겨진 감각`으로 구분한다.
- 18번째 숙련이 확정되는 순간 `전생 통합 해금` 연출을 한 번만 보여 준다.
- 해금 연출은 durable save 성공 뒤에만 실행한다.

### 11.4 아카이브

- 기존 회차 카드의 각성 목록은 당시 실제 활성 각성을 보여 준다.
- 전생 통합 회차는 18개 이름을 한 줄로 나열하지 말고 `전생 통합 · 18개 각성 활성`로 접는다.
- 일반 회차에는 `신규 숙련 N개`를 표시해 어떤 삶이 계보를 넓혔는지 알 수 있게 한다.

## 12. 분석 이벤트

기존 이벤트 이름을 임의로 재사용하지 말고 다음 이벤트 또는 동등한 명시 필드를 추가한다.

| 이벤트 | 시점 | 필수 속성 |
|---|---|---|
| `awakening_mastery_committed` | 계승 저장 성공 뒤 | `life_number`, `new_count`, `total_count`, `awakening_ids` |
| `awakening_resonated` | 숙련 노드를 이번 생에 선택 | `life_number`, `awakening_id`, `tier`, `mastered_count` |

| `lineage_unison_started` | 통합 회차 생성 저장 성공 뒤 | `life_number`, `difficulty` |

## 13. 구현 순서

### 단계 A — 코어 모델과 순수 규칙

1. `AwakeningRunMode`와 숙련 필드를 시작 입력·스냅숏에 추가한다.
2. 숙련 정규화 함수를 `AwakeningTree`에 추가한다.
3. 숙련·이번 생 선택을 받는 `available` 오버로드를 구현한다.
4. 일반 모드의 `awakeningOptions`가 새 판정을 사용하게 한다.
5. state commitment에 숙련과 모드를 넣는다.
6. 기존 각성 3회 동작이 숙련 0개일 때 바뀌지 않는지 먼저 테스트한다.

### 단계 B — iOS 계승과 저장 마이그레이션

1. `Inheritance.masteredAwakenings`와 SaveRecord v3 마이그레이션을 구현한다.
2. 아카이브 기반 백필과 정규화를 구현한다.
3. `startCareer`가 정상 회차에 숙련을 전달하고 challenge에는 전달하지 않게 한다.
4. `nextInheritance`와 `confirmLegacy` 롤백 범위에 숙련을 포함한다.
5. 삭제·result-less 저장·iCloud 복원 경계를 테스트한다.

### 단계 C — 일반 회차 UI

1. 스킬트리의 다섯 상태를 표시한다.
2. `계보 숙련/이번 생 공명` 진행을 분리한다.
3. 숙련 노드 재공명과 신규 노드 선택 확인 문구를 분기한다.
4. 결산과 아카이브에 신규 숙련을 표시한다.
5. 18번째 숙련 해금 연출을 durable save 뒤에 붙인다.

### 단계 D — 전생 통합

1. 18/18 검증과 설정 화면 진입 카드를 추가한다.
2. 시작 시 18개 효과를 고정 순서로 한 번 적용한다.
3. 통합 확인 명령과 각성 국면 UI를 추가해 진행 정지를 막는다.
4. 아카이브 배지와 경쟁 제외 정책을 구현한다.
5. 프로 저장까지 경쟁 자격을 전달하고 리더보드 제출 우회를 막는다.

### 단계 E — 계측과 최종 QA

1. 분석 이벤트를 durable save 뒤에 연결한다.
2. 정상·challenge·전생 통합 세 모드를 끝까지 플레이한다.
3. 저장 복원과 업데이트 마이그레이션을 실제 JSON fixture로 검증한다.
4. 접근성 라벨과 작은 화면 스크롤을 확인한다.

## 14. 필수 테스트

### 14.1 `SimulationCore`

- 숙련 0개일 때 기존 첫 선택은 네 갈래 뿌리만 나온다.
- 숙련한 부모가 다음 생의 미숙련 2·3단을 연다.
- 숙련 노드는 이번 생에 한 번만 공명할 수 있다.
- 숙련하지 않은 갈래의 3단은 전조 없이 열리지 않는다.
- 전조는 같은 갈래 한 단계만 건너뛴다.
- 전조로 부모 없이 숙련한 3단은 다음 생에도 유지되고 재공명할 수 있다.
- 반환과 저장 순서는 항상 `AwakeningTree.nodes` 순서다.
- 일반 회차는 여전히 정확히 세 번 선택하고 드래프트까지 진행한다.
- 전생 통합은 18개 미만 숙련 입력을 거부한다.
- 전생 통합 시작은 18개 효과를 정확히 한 번만 적용한다.
- 전생 통합의 세 각성 국면이 선택지 부족으로 멈추지 않는다.
- 저장 후 복원해도 효과를 두 번 적용하지 않는다.
- 숙련·모드 commitment를 변조하면 검증이 실패한다.
- 전체 효과 적용 뒤 모든 수치가 기존 범위를 지킨다.

### 14.2 iOS 저장·계승

- 정상 회차 완료 시 신규 세 개가 숙련된다.
- 이미 숙련한 세 개만 공명하면 숙련 수가 증가하지 않는다.
- 미지명 회차도 정상 계승 확정 뒤 숙련된다.
- challenge 회차는 숙련·아카이브·야구혼을 바꾸지 않는다.
- 저장 실패 시 result, inheritance, archive, recap이 모두 이전 값으로 돌아간다.
- v1/v2 아카이브에서 각성 합집합을 한 번만 백필한다.
- 각성 정보가 없는 옛 기록은 잘못 추측하지 않는다.
- 현재 진행 중 회차의 선택은 마이그레이션 숙련에 포함되지 않는다.
- 삭제 후 숙련이 0개가 된다.
- result-less 회차 사이 저장을 복원해도 숙련이 유지된다.
- iCloud에서 높은 revision을 불러왔을 때 숙련과 회차가 같은 레코드에서 온다.

### 14.3 UI와 E2E

- 0/18, 일부 숙련, 18/18 트리가 각각 올바르게 보인다.
- 색을 보지 않아도 VoiceOver 라벨로 상태를 구분할 수 있다.
- `이번 생 공명 3/3` 뒤 네 번째 선택이 불가능하다.
- 숙련 부모 덕분에 열린 3단이 첫 각성에서 실제 선택된다.
- 18번째 숙련 저장 성공 뒤에만 해금 연출이 나타난다.
- 전생 통합을 선택하지 않고 일반 회차를 계속 시작할 수 있다.
- 전생 통합 회차가 고교 완료와 프로 진입까지 막히지 않는다.
- 전생 통합 프로 성적이 경쟁 리더보드에 제출되지 않는다.

## 16. 완료 조건

다음 조건을 모두 만족해야 구현 완료다.

- 여러 정상 회차의 각성이 영구 숙련으로 누적된다.
- 숙련 부모가 다음 회차에서 상위 스킬 접근을 실제로 연다.
- 일반 회차의 실제 활성 각성은 여전히 세 개뿐이다.
- 18개 숙련 뒤 모든 효과를 동시에 쓰는 전생 통합 회차를 시작할 수 있다.
- 전생 통합의 기존 각성 국면 세 곳에서 진행이 멈추지 않는다.
- 기존 사용자 아카이브에서 가능한 숙련을 안전하게 복원한다.
- challenge와 경쟁 리더보드가 메타 성장으로 오염되지 않는다.
- 저장 실패·복원·삭제·iCloud 회차 사이 상태가 숙련 원장을 잃지 않는다.
- 코어 전체 테스트와 iOS 테스트가 통과한다.
- 새 UI 문구에 실존 구단명, 통용 구단 약칭, 실존 선수명, 실존 리그명이 없다.

## 17. 이번 작업에서 하지 않을 것

- 각성 18개의 개별 수치 재밸런싱
- 환생 횟수에 비례한 숨은 상대 자동 스케일링
- 숙련 효과의 25% 잔향 같은 부분 배율 시스템
- 야구혼으로 숙련을 구매하거나 초기화하는 상점
- 숙련 트리의 유료화
- Android·Windows·웹의 동시 UI 구현
- iCloud 충돌 시 서로 다른 기기의 숙련 집합을 자동 합치는 새 동기화 프로토콜

공유 `SimulationCore`의 저장 계약이 바뀌므로 다른 플랫폼 포팅 시에는 새 필드를 `nil = 숙련 없음, normal`로 읽을 수 있어야 한다. 다만 이번 구현의 제품 완료 범위는 iOS다.
