# 출시 기준 실행 및 차이 판정

기준 문서: [제품·플랫폼 동등성 계약](RELEASE_PRODUCT_CONTRACT.md). 사용자 승인 범위는 PM 제안 1·2·3번이며, 플레이테스트의 모집·관찰·재미 평가는 사용자가 담당한다. 스토어 제출은 수행하지 않는다.

## 최종 상태

- 고정 후보: `codex/android-release-gate-20260905`, 커밋 `1c39749f2875fe4d7eee17aa668f8e9258bd62e4`, 버전 코드 **42**.
- 고정 체크아웃에서 소스 전후 해시가 일치했고 **249개 검사**(코어 118·앱 로직 108·저장 14·앱 9), debug/release lint, 릴리스 코드 컴파일을 통과했다.
- 같은 QA APK로 Galaxy A53와 16KB 에뮬레이터에서 **12개 기기 검사**를 통과했다. 양방향 파일 복원→이어 하기→다시 열기, 슬라이더 취소/릴리스, 훈련·각성·환생 조작을 포함한다.
- Galaxy QA 앱을 42로 업데이트했다. 검사 중 기존 저장 파일의 바이트가 같았고, 메인 화면을 다시 연 뒤에도 기존 고교·프로 기록이 같음을 확인했다.
- **production 서명 AAB는 아직 만들지 않았다.** 업로드 키 설정이 현재 환경·로컬 Gradle 설정·프로젝트 내에 없다. Play 업로드·출시나 계정 설정 변경도 하지 않았다.
- 실제 Play Console에서 최신 업로드 코드 **41**, 내부 테스트와 비공개 Alpha 활성, 프로덕션 비활성을 확인했다. 다음 후보를 42로 고정했다. [확인한 출시 개요](https://play.google.com/console/u/0/developers/5198814359992339237/app/4973220489799176676/releases/overview). 인증서와 관찰 기록은 [배포 기준](PLAY_RELEASE_BASELINE.json)에 보관한다.

처음 원래 작업 폴더에서 실행한 검사들은 실행 중 UI 파일이 바뀌어 소스 안정성 조건을 충족하지 못했다. 원래 작업을 보존하고 별도 체크아웃에 후보를 고정한 뒤 다시 검사했다. 최종 결과는 이 고정 후보에만 해당한다.

## 고정한 자동 비교 범위

- 현재 iOS `SimulationCore`를 Swift로 실행해 입력·기대 결과를 생성한다. Kotlin이 같은 단계 입력을 재생한다. Android 결과를 기대값으로 복사하지 않는다.
- 신규 구종 학습을 포함한 고교 **38개 전이**를 재생하고, 실제 지명 결과와 선수를 프로로 전달한다.
- 재계약 경로 **748개**, FA 경로 **749개**, 고교 지명 선수의 프로 경로 **781개**로 총 **2,278개 프로 전이**를 비교한다. 각 경로는 20시즌과 은퇴까지 진행한다.
- 선택하지 않은 계약 제안도 구단·기간·연봉·계약금·보직·계약 목표로 비교한다. 선수 능력·숙련, 피로·신뢰·부상, 경기 기록, 자금, 목표 달성, 은퇴 점수와 다음 난수 시드를 비교한다.
- 훈련은 4개 유형 × 3개 학습 구종 × 6개 훈련 × 3개 강도의 **216개 조합**을 비교한다.
- 각 커리어 전이 뒤에 저장 codec으로 다시 열어 같은 상태임을 확인한다. 실제 배포 저장 어댑터와 Compose 조작은 별도 회귀/기기 검사로 확인한다.

프로 비교의 직접 경기 입력은 동일한 고정 보고서(24구·4삼진·0볼넷·0실점·3아웃, 등판 점수 차 +2, 등판 아웃 1)다. iOS 앱과 마찬가지로 절대 팀 점수는 보고서에서 지정하지 않는다. 이 검사는 모든 공을 UI로 직접 던지는 플레이테스트가 아니다. 실제 투구 판정/슬라이더는 별도 커널·제스처 검사로 확인한다.

시작 시드만 주고 양쪽 앱 UI를 자동 완주했다는 뜻도 아니다. **공통으로 고정한 각 단계의 시드·선택·보고서**를 비교하는 검사다. 모든 선택 조합이나 현재 App Store 판매 바이너리와의 동등성을 주장하지 않는다.

## 발견하여 수정한 출시 차단 문제

| 항목 | 수정 전 차이 | 수정 |
|---|---|---|
| 지명→프로 연결 | 지명 구단 대신 다른 구단을 골랐고 지명 순서·계약금이 신인 계약에 전달되지 않음 | 실제 지명 정보와 팬 관심도, 학습·숙련, 고교 시작 능력을 전달 |
| 미지명 결말 | 미지명 선수에게도 고교 연계 프로 진입이 노출됨 | 지명된 선수에게만 연계 진입 제공. 직접 프로 모드와 구분 |
| 프로 목표 선택 | 계약 때 목표를 한 가지로 고정 | 남은 프로 목표를 명시적으로 선택해 계약. 완료된 목표 재선택 방지 |
| 난수 순서 | 계약·결산·시즌 전환처럼 추첨이 없는 행동도 다음 난수를 소비 | 현재 Swift 계약에 맞게 시드를 유지 |
| 계약 유지 | 새 시즌에 유효 계약의 연봉·보직을 임의로 다시 계산 | 계약을 유지하고 계약상 보직으로 다음 시즌 시작 |
| 시즌 결산 | 과거 수상을 반복 집계하고 계약 목표·통산 이정표·가을 수상에 따른 팬 반응이 누락 | 해당 시즌 근거와 목표 이행 기록을 반영 |
| 재계약/FA | 고정 시장 점수·단순 제안으로 실제 평가와 계약 조건이 다름 | 능력·최근 성적·나이·팬·계약 이행·구단 기록을 평가. FA의 장기 계약과 계약금 포함 |
| 리그·가을 진출 | 순위 생성 시드/난수 소비 순서와 승패 합계 보정이 달라 가을 진출이 달라짐 | 공통 순위 계산과 승패 균형, 플레이어 경기 보존 적용 |
| 미디어 선택 | 선택 ID와 피로·신뢰 효과가 iOS와 다름 | 광고/팬 촬영/시즌 집중의 비용·보상 일치. 옛 저장의 선택 ID는 계속 처리 |
| 대표팀 자격 | 시장 평가 대신 단순 능력 평균, 이번 시즌 대신 과거 수상을 사용 | 현재 시장 평가·해당 시즌 수상·팬 기준으로 판단 |
| 이전 버전의 소집 저장 | 자격 계산을 바꾸면 이미 받은 소집까지 읽기 오류가 될 수 있음 | 이미 발급된 유효 소집은 보존하고 응답 가능. 새 소집은 현재 기준 사용 |
| 회복 연도 | 선택 후 다음 해 능력 하락 완화가 적용되지 않음 | 회복 상태를 저장하고 성장 일시 중지/하락 완화 후 해제 |
| 사건 우선순위 | 노화 갈림길을 미디어 사건이 가림 | iOS와 같은 우선순위 적용 |
| 이적 저장 | 다음 시즌 계약 직후 이전 팀의 완료 시즌 기록을 오류로 거부 | 이적 준비 단계의 이전 시즌 기록을 보존하고 재시작 허용 |
| 은퇴 | 계약/목표가 열린 채 남고 은퇴 표시·점수·명예 근거가 어긋남 | 계약과 목표를 마감하고 은퇴 점수·명예·금메달 보너스 반영 |
| 유형 기본값 | 일부 유형의 기본 주 구종/학습 구종이 다름 | iOS 추천 구성으로 통일. 명시적 사용자 구종 선택은 유지 |
| 릴리스 검사 | release lint 의존성 잠금 누락 | 실제 해석 결과로 잠금을 갱신. RC 빌드의 잠금 우회 옵션 제거 |

종전 테스트 일부는 미지명 선수의 프로 승격, 무조건 5년인 FA 제안 등 잘못된 동작을 전제로 했다. 해당 기대는 실제 규칙에 맞게 수정했다. 저장 완주 검사는 정상적인 플레이 입력으로 지명받는 고정 시드·설정·추천 투구를 사용하며, 지명 결과 자체를 덮어쓰지 않는다.

## 의도한 차이와 후속 범위

| 분류 | 항목 | 판정 근거 |
|---|---|---|
| PLATFORM | 은퇴 직후의 코어 상태 이름 | iOS는 코어를 `completed`로 끝내고 앱에서 유산 선택을 다룬다. Android는 `legacy_selection` 경계를 둔다. 비교는 은퇴 점수가 확정된 상태를 `retired`로 명시하고 원래 Android 상태도 로그에 남긴다. Android 유산 선택 후 완료·저장은 추가 검사한다. |
| PLATFORM | 진동·배치·뒤로 가기 | 기기별 구현 허용. 기본 수동 슬라이더, 정상 릴리스 한 번, 취소 미투구는 필수. |
| PLATFORM | 파일 복원 | 자동 동기화와 구분되는 사용자 선택 방식. 생성한 기록의 기기 간 복원과 이어 하기를 검사한다. |
| LATER | 온라인 이용자 순위·자동 계정 동기화·인물 성격/연대기 연출 전체 | 승인한 제품 기준의 후속 범위. 구현 완료로 표시하지 않는다. |
| UNVERIFIED | 모든 선택·모든 시드·판매 중인 iOS 바이너리 | 이번 고정 경로의 통과를 해당 범위로 확대 해석하지 않는다. |
| UNVERIFIED | 최종 서명 production 후보 | Play 버전·트랙과 업로드 인증서는 확인했다. 비공개 업로드 키 설정은 없어 경로·주입 방법을 사용자에게 요청했다. QA debug나 릴리스 코드 컴파일을 서명 검증으로 대체하지 않는다. |
| 사용자 담당 | 플레이테스트 | 사용자가 직접 수행. 자동 검사 결과와 구분한다. |

## 재현과 산출물

```sh
python3 tools/run-android-release-gate.py
```

동일 경로를 재사용하며 Swift 기준 생성 → 소스/번역 검사 → 코어·저장·앱 회귀 → debug/릴리스 lint·릴리스 코드 컴파일 → native 저장 모드 QA 빌드를 실행한다. 비교만 실행하려면 `--compare-only`를 사용한다. 동시 실행은 잠금으로 막는다.

후보 위치는 `artifacts/android-compose/release-gate/candidate.json`을 따른다. 최종 기계 판정은 **고정 체크아웃 내부**의 `artifacts/android-compose/release-gate/gate.json`이다. `sources-before.json`·`sources-after.json`과 `changedSources`로 검증 도중 소스가 바뀌었는지 확인한다. 변경되면 자동 검사 통과로 표시하지 않는다. 서명된 production 후보 조건이 남으므로 `releaseReady`는 false다.

Swift 입력·기대값은 `swift-release-parity.json`, Android 비교값은 `kotlin-release-parity-pro*.json`, 기기 검증은 `device-verification.json`에 보관했다. 개인 커리어의 로컬 복사본과 임시 전송 파일, 기기 테스트 패키지는 제거했다.

고정 소스와 재사용 빌드는 `/Users/solkim/Dev/baseball/artifacts/android-compose/candidate-source`에 약 **341MiB**로 한 벌 보관한다. 이 폴더의 QA APK가 플레이테스트 대상이며, 원래 작업 폴더에서 나중에 만든 APK와 구분한다. 최근 QA 증거만 유지하고 과거 훈련 증거 원본은 정리했다.
