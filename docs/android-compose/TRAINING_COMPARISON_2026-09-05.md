# iOS 훈련 비교와 Android 개선

비교 기준은 현재 작업 폴더의 iOS/Android 소스다. 실제 App Store 바이너리의 동일성을 주장하지 않는다. 기존 선수·세이브·훈련 능력치를 초기화하거나 재조정하지 않았다.

## 확인한 차이와 변경

| 항목 | iOS | 수정 전 Android | 이번 변경 |
|---|---|---|---|
| 선택과 실행 | 종류를 고른 뒤 훈련하기 | 종류 버튼을 누르면 즉시 실행 | 선택은 저장 명령을 보내지 않으며 하단 훈련하기로 실행 |
| 강도 | 가볍게·보통·몰아붙이기 | 보통으로 고정 | 세 강도를 고르고 직전 선택을 이어 사용 |
| 회복 | 휴식 방식에 맞는 강도 이름 | 일반 훈련과 같은 행동 버튼 | 푹 쉬기·가볍게 몸 풀기·쉬면서도 던지기 |
| 변화구 | 대상 구종과 학습 정보 | 대상이 기본값으로 전달됨 | 보유 구종 선택과 실제 구종별 성장 연결, 선택한 대상 저장 |
| 비용/기회 | 학교 특기·오늘의 기회·피로/위험·성장 전망 | 짧은 일반 설명 | 학교/기회/추천 배지, 강도별 피로와 팔 부담, 성장 예상 표시 |
| 결과 | 능력 변화·피로·발현을 결과 카드로 표시 | 결과 전용 카드 없음 | 성장 0도 표시, 피로/숙련/재능 발현 표시, 다음 일정에서는 작은 카드 |
| 연속 훈련 | 최대 3회, 상황에 따라 중단 | UI 없음; 코어 묶음 명령은 대상 구종/안전 중단 정보 없음 | 최대 3회, 선택 구종 유지, 일정·발현·피로·팔 상태에 따른 중단 |
| 훈련 버튼 | 화면 아래 고정 | 목록의 개별 즉시 실행 버튼 | 훈련하기와 ×3을 탭 바 위에 고정 |

피로 70 또는 팔 부담 55부터 회복을 추천한다. 재활 중에는 회복으로 진행한다. 연속 훈련은 일정이 바뀌거나 재능이 발현되면 중단한다. 회복 외 훈련은 피로 75 이상, 팔 부담 55 이상 또는 재활 상태가 되면 중단한다. 여러 번 훈련한 결과에는 마지막 한 번이 아닌 실제 수행한 전체 훈련의 성장·피로 합계를 표시한다.

## 수치와 저장

훈련의 기본 성장 신호, 학교/기회 보너스, 피로 보정, 분산, 강도별 피로와 팔 위험 계산을 iOS 소스와 대조했다. 화면에서 미래 판정을 실행하거나 RNG를 소비하지 않는다. Android의 실계산과 전망이 같은 함수를 사용하도록 정리했다. 성장 예상은 대성공을 제외한 기본 범위이며 재능 한계는 별도로 안내한다.

기존 `TrainingBlock` 명령의 기본 직렬화는 유지한다. 새 UI에서만 대상 구종과 안전 중단 필드를 추가한 형식을 사용한다. 실제 훈련 내역은 기존 `trainingEvidence`에 저장하므로 세이브 스키마의 기존 기록을 버리지 않는다. 결과 카드는 기록을 읽기만 한다.

## 아직 같은 형태가 아닌 부분

- 능력 눈금: iOS `AbilityDisplayScale`은 내부 20~80 값을 표시용 1~100으로 환산한다. Android는 기존 화면과 일관되게 20~80 표시를 유지한다. 숫자 차이를 실제 능력치 차이로 간주해서는 안 된다.
- 구종 학습: iOS의 그립→불펜→실전 적응 프로젝트와 Android의 구종 역할/능력 성장 모델은 다르다. 이번에는 실제 Android 구종 상태(연습 중·실전 구종·주 구종)를 표시했다. 존재하지 않는 iOS 단계/진척도를 꾸며 표시하지 않는다.
- 결과: 성장량·피로 변화·숙련·발현은 표시하지만 iOS의 모든 수치 애니메이션과 과거 값 타일을 그대로 이식한 것은 아니다. 재시작 후에는 마지막 훈련의 확정 증거를 보여준다.

## 검증

- 기존 game-core/game-application 회귀, 앱 단위 검사와 lint 통과.
- 10개 시드 × 정상/재활 × 6종류 × 3강도에서 표시 피로·팔 부담과 실제 결과 일치 확인.
- 대상 구종 유지·다른 구종 미변경·안전 중단·구간 종료·명령/세이브 round-trip 확인.
- 배포용 C# 호환 저장 경로에서 대상/강도가 있는 반복 훈련과 합산 결과·재시작 보존 확인.
- Compose 실제 화면에서 종류/구종/강도 선택만으로 훈련이 소모되지 않음, 훈련하기가 선택값을 실행함, 결과 카드 노출 및 배포 저장 재열기를 확인.
- 초기 좌표 기반 테스트는 스크롤 후 이동한 컨트롤을 안정적으로 찾지 못했다. Compose의 화면 스크롤·클릭 동기화를 사용해 실제 선택과 저장 결과를 검사하도록 수정했다.

최종 UI 실행 증거는 `artifacts/android-compose/qa-training/`에 보관한다.

최종 UI 검증: 한국어 100%/200%, 영어·일본어에서 선택과 실행 분리, 구종/강도 저장, 결과 노출 검사를 통과했다. 연속 훈련 설명은 스크롤 영역으로 옮겨 큰 글자에서도 고정 버튼 공간을 확보했다. Galaxy 재연결 후 QA 앱 업데이트를 완료했다. 설치 전후의 실제 고교 저장 snapshot이 동일함을 확인했으며, 기존 경기를 진행하거나 초기화하지 않았다.
