# iOS 비교 후 Android 개선 결과

2026-09-05. 현재 Kotlin/Compose 작업본에 적용했다. 기존 미커밋 작업을 보존했고 스토어 제출은 하지 않았다. 앞선 [차이 재점검](IOS_ANDROID_PARITY_REAUDIT_2026-09-05.md)의 개선 순서에 따른 기록이다.

## 적용한 내용

1. **구종 학습**
   - 새 선수의 개발 구종에 그립→불펜→실전 적응→습득 완료 단계를 연결했다. 연습 2에서 불펜, 5에서 경기 사용, 7과 좋은 실전 사용 2회 또는 연습 9에서 완성된다.
   - 가벼운/보통/강한 변화구 훈련은 각각 연습 1/2/3을 더한다. 선택한 학습 구종을 훈련했을 때만 진척된다. 프로의 변화구 개발 주간은 대상 구종의 연습 2를 더한다.
   - 잠긴 구종은 경기용 추천·직접 선택·자동 경기에서 제외하고, 훈련에는 계속 표시한다. 경기에서 쓸 수 있게 될 때 시작 준비 보너스를 한 번만 회수한다.
   - 좋은 실전 사용은 같은 타석에서 중복 지급하지 않고, 저장·재시작 후에도 중복을 막는다. 학습 상태와 네 구종의 전체 프로필을 프로 진입 명령과 실제 저장에 유지한다.
   - 기존 선수에게 없던 학습 잠금을 소급 적용하지 않는다. 빠른 환생은 새 학습 규칙으로 시작한 선수의 구종 구성을 이어받는다.

2. **관계 대화**
   - iOS `RelationshipVoiceCatalog.swift`에서 사건·분류별 장면 60개를 생성 도구로 가져왔다. 매번 같은 공통 선택지를 제시하던 경로에 사건별 선택지와 본문을 연결했다.
   - 화자에 따라 감독/포수/라이벌 신뢰도를 사용하고, 낮음 45 미만·보통 45~64·높음 65 이상에서 대사가 바뀐다. 화자의 실제 가상 인물 이름을 표시한다.
   - 긴 대사와 선택지는 한 열로 읽게 했다. 선수 이름은 번역 후 삽입하고, 구종 이름과 같은 선수 이름도 오역하지 않도록 검증했다.
   - 새 대사 선택 때문에 관계 효과나 기존 사건 기록을 바꾸지 않는다. 번역은 기존 iOS 항목과 Android 추가 문안에 연결했다.

3. **각성과 결산**
   - 네 갈래 전체 각성 트리를 표시하고 보유/선택 가능/잠김, 먼저 익힐 각성, 단계 건너뛰기를 구분한다.
   - 실제 코어 계산으로 현재 능력→선택 후 능력을 보여주고, 확인 버튼을 눌렀을 때만 각성을 확정한다. 기존 해금 규칙을 그대로 사용한다.
   - 드래프트에 지명 기준과의 점수 차이, 능력·경기·시즌·위기 관리·관심도·관계·각성·팔 상태 등의 평가 근거를 연결했다. 기록에 따라 다음 생의 훈련/회복 조언을 제시한다.
   - 이번 생에 키운 강점, 훈련 횟수, 직접 경기 기록과 선택한 각성을 결산에 추가했다. iOS의 인물 성격·연대기 전체를 복제했다는 의미는 아니다.

4. **능력치와 훈련 결과**
   - 공통 표시 계층의 iOS 1~100 눈금을 사용한다. 선수 헤더·유형 수치·훈련 전망·결과·프로 주간·보관 기록·공유 수치를 맞췄다. 시뮬레이션에 넣는 내부 20~80 값은 바꾸지 않는다.
   - 작업본에 있는 실제 성장 영수증과 전후 비교 화면을 연결하고, 배포 저장 어댑터에서 영수증이 보존되는 경로까지 검증했다. 학습 구종의 현재 단계와 연습/실전 진척도도 훈련 화면에 함께 표시한다.

5. **투구 햅틱**
   - 지원 기기는 낮은 강도의 기본 진동 조합을 사용해 타이밍 근접도에 따라 강도를 바꾼다. 초당 호출 횟수를 제한하고, 미터 끝 반전·좋은 타이밍 진입·릴리스 효과가 겹치지 않도록 순서를 정리했다.
   - 연결된 Galaxy A53은 진동 primitive/강도 조절 기능을 지원한다고 보고하지 않았다. 이 기기에는 좋은 타이밍에 가까워질수록 TICK 간격이 320ms에서 120ms 쪽으로 좁아지는 대체 피드백을 적용했다.
   - 앱/시스템 진동 끄기를 존중한다. 손을 떼거나 조작이 취소되거나 화면이 사라지면 와인드업 효과를 끝낸다. 직접 슬라이더가 기본이며 취소는 투구를 제출하지 않는다.
   - 기기별 지원과 효과 선택은 [Android 공식 햅틱 API 문서](https://developer.android.com/develop/ui/views/haptics/haptics-apis)를 기준으로 확인했다. iPhone과 촉감이 동일하다고 주장하지 않는다.

6. **파일로 기록 보관·복원**
   - 배포 저장 경로를 사용하는 앱의 설정에 `기록을 파일로 보관`과 `보관한 기록 불러오기`를 추가했다. Android 파일 선택기를 통해 사용자가 저장 위치를 고른다.
   - 불러올 선수와 진행 정보를 먼저 보여주고, 확인한 뒤 현재 기록을 교체한다. 확인 중 현재 기록이 바뀌었으면 거부한다.
   - 파일 크기·형식·체크섬·내부 커리어 상태를 검사하고 기존 원자적 저장/백업/읽기 검증을 사용한다. 다른 설치 ID에서도 이어서 명령을 실행할 수 있도록 복원한다.
   - 자동 클라우드 동기화는 아니다. 사용자가 보관한 파일을 새 기기에서 선택하는 방식이다.

## 검증과 발견한 회귀

- 코어 115개, 앱 로직 105개, 저장 14개, 앱 단위 9개와 나머지 모듈 검사가 통과했다. 후속 변경에는 관련 검사와 debug lint를 다시 실행했다.
- 새 학습의 단계/해금/완성, 같은 타석 보상 중복 방지, 고교·프로 저장, 다른 설치로 백업 복원, 손상/오래된 확인 요청 거부, 복원 후 실제 명령 진행을 검증했다.
- Galaxy에서 훈련 선택→실제 학습 진척, 각성 잠김/확인→한 번 적용, 제스처 취소 0구/정상 릴리스 1구를 검사했다. 16KB 에뮬레이터에서도 훈련·각성 UI를 확인했다.
- Galaxy 서비스 로그에서 실제 TICK·시작·릴리스·성공 피드백의 재생 완료를 확인했다. 지원 기기의 강도 조절 경로는 연결된 A53에서 실물 검증할 수 없었다.
- 업데이트 설치 도중 학습 필드가 없는 옛 저장본의 해시가 달라지는 회귀를 발견했다. Phase 4가 내부 저장 바이트를 해시에 포함하기 때문에 빈 필드를 추가하는 것도 호환성 변경이었다. 기존 기록에는 해당 필드를 아예 쓰지 않도록 수정하고, 기기에 보존된 원본을 복원했다. 수정 후 앱 시작과 검사에 성공했으며 실기기 검사 전후 저장 파일의 SHA-256이 동일했다.
- 기존 Swift 비교 데이터 두 개가 현재 투구 계산보다 오래되어 실패했다. 현재 Swift 실행 결과가 Kotlin 결과와 일치함을 확인한 뒤 생성 데이터를 갱신했다. 고교·프로 모두 현재 소스 커밋과 Swift 코어 파일 해시를 기록한다. 기대값을 Android 출력으로 만든 것은 아니다.
- 전체 cross-runtime 보고서는 통과했다. 단, 8월 28일의 사용하지 않는 Unity 생성 결과를 정리했으며, 이번 작업에서 실제 Unity 재저장은 실행하지 않았다. 보고서의 해당 항목은 `NOT_RUN`이다. 현재 Android 제품은 Unity 런타임을 사용하지 않는다.
- 한국어/영어/일본어 문자열 매핑 검사와 대사 생성본 일치 검사를 통과했다. 이는 모든 언어의 전체 커리어를 사람이 읽어 검수했다는 뜻은 아니다.

## 남은 출시·플랫폼 작업

- 계정 기반 자동 클라우드 동기화와 온라인 이용자 순위는 추가 서비스 연동이 필요하다. 파일 복원과 게임 속 가상 리그 순위를 각각 이 기능들의 완료로 간주하지 않는다.
- 최신 작업본의 서명 production AAB, 실제 Play 트랙/버전 확인, verified App Links와 웹 배포, 스토어 업로드는 이번에 하지 않았다.
- 현재 기기에서 확인할 수 없는 강도 조절 지원 기기, 지원 하한 Android, 서명 후보의 장시간 플레이 검증이 필요하다.

소스: `PitchLearning.kt`, `RelationshipNarrative.kt`, `CareerChoicePresentation.kt`, `AwakeningTreeView.kt`, `PitchTouchFeedback.kt`, `CareerBackup.kt`, `CareerBackupControls.kt`와 해당 저장/명령 경계. 재현 로그와 화면은 `artifacts/android-compose/qa-parity/`에 보관한다. 원본 기기 저장을 진단하기 위해 만든 로컬 복사본은 확인 후 제거한다.
