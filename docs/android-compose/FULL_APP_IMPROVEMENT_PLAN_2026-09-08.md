# 전체 개선 실행 계획

기준: `FULL_APP_QA_2026-09-08.md`, QA 커밋 `e18e6eb5`.
상태: 계획 수립. 아래 제품 수정은 아직 실행하지 않았다.

목표는 **내 투수가 무엇을 했고, 무엇을 얻었으며, 다음에 무엇에 도전할지 바로 이해할 수 있게 만드는 것**이다. 정확한 기록과 결과를 먼저 연결한 뒤 화면을 단순하게 만든다.

## 유지할 기준

- 기존 선수·학교·능력·경기·계약·환생 기록을 보존한다. 새 필드는 이전 저장에 없어도 읽을 수 있어야 한다.
- 직접 투구의 기본값은 타이밍 슬라이더다. 기존 64dp 조작 영역과 한 구를 끝까지 던지는 동작을 유지한다.
- 미리보기·선택·상세보기는 시간, 재화, 난수, 경기 기록을 소비하지 않는다. 명시적 실행만 상태를 변경한다.
- 중요한 결과는 자동으로 사라지지 않는다. 동일 결과를 중복 지급하거나 여러 팝업으로 연속 표시하지 않는다.
- 짧은 버튼 이름, 버튼 밖 설명, 명확한 선택 색상을 사용한다. 일반 터치 영역은 최소 48dp를 유지한다.
- 한국어·영어·일본어와 가상 야구 세계관을 유지한다.
- 이번 QA 문제 해결과 관계없는 추가 성장 상향·난이도 하향은 섞지 않는다.

## 0. 검증 기준과 공통 데이터 준비

**작업**

- 확인된 결함을 실제 입력과 기대 결과가 있는 회귀 검사로 고정한다. 정상 경로뿐 아니라 프로 단독 시작·고교 연계·빈 기록·지난 생이 남은 상태를 포함한다.
- 화면에서 core 타입과 계산을 직접 다루는 부분을 애플리케이션의 화면 모델·명령으로 옮긴다. UI는 이미 계산된 데이터와 실행 가능한 행동을 받는다. 재현 fixture도 적절한 테스트 계층으로 옮긴다.
- 기록, 선택 효과, 주간 결과, 등판 배정의 공통 표현을 정한다. 문자열 순서나 행 번호에 의존하는 표시를 없앤다.
- 오래된 버튼명·스킬 이미지 태그 검사 2개는 현재 동작을 검증하도록 갱신한다. 단순히 화면에 존재하는지만 보지 않고 선택·확인·결과 유지까지 확인한다.
- Swift 기준값 비교 실패 2개는 의도된 규칙 변경과 실제 회귀를 분리한다. 규칙 버전과 출처가 같은 데이터끼리 비교하고, 비의도 차이는 수정한다. 현재 출력을 그대로 정답으로 덮어쓰거나 검사를 끄지 않는다.
- 제외된 릴리스 비교 검사 2개도 제외 사유와 지원 규칙 버전을 확인한다. 대체 검증 없이 완료 처리하지 않는다.

**완료 기준:** 각 실패의 원인과 처리 방향이 기록되어 있고, 이후 단계가 이 기준을 공유한다. 구조 정리는 기능별 변경과 함께 작은 단위로 진행한다.

## 1. 경기·통산 기록의 정확성 복원

**화면**

- `경기`는 현재 선수·현재 단계의 기록을 기본 표시한다.
- 기록이 있을 때만 고교/프로/시즌 필터를 제공한다. 지난 생은 선수별로 열어 현재 선수 기록과 혼동하지 않게 한다.
- `통산`은 내 등판·이닝·탈삼진 등 핵심 기록이 먼저다. 리그 순위는 별도 영역으로 분리한다.
- 새 선수는 `첫 등판 전`과 현재 가능한 다음 행동을 보여 준다. 타 구단의 0승 0패 순위를 첫 기록처럼 내세우지 않는다.
- 상세 펼치기는 한 단계로 줄인다.

**계산**

- 합계와 경기 목록을 같은 기록 모델에서 만든다. 고교·프로·시즌·커리어를 구별하는 경기 식별자를 사용한다.
- 직접 투구와 자동 진행이 섞인 같은 경기는 한 경기로 합산한다. 이닝은 아웃 수로 합산한 뒤 표기한다.
- 이전 저장에 없는 개별 수치는 만들어 채우지 않는다. 보존된 누적 기록과 복원 가능한 경기 목록을 구별해 설명한다.

**완료 기준:** 프로 1경기가 화면에서도 1등판으로 표시된다. 자동/직접/혼합 경기, 시즌 전환, 은퇴·환생 후 재열기에서 중복·누락이 없다.

## 2. 프로 주간 선택과 결과 피드백 완성

**흐름:** `계획 선택 → 이번 주 예상 확인 → 이번 주 진행 → 실제 결과 → 다음 일정`.

- 계획 버튼은 `구위 / 제구 / 변화구 / 체력 / 회복 / 신뢰`처럼 짧게 만들고 선택만 한다. 실행 버튼은 `이번 주 진행` 하나다.
- 선택한 계획 아래에 성장 진도, 예정 또는 예상 등판, 피로·부상 부담을 표시한다. 불확실한 수치는 확정값처럼 쓰지 않는다.
- `0주차`는 `시즌 준비`로 바꾸고, 이후에는 사용자가 진행할 주를 기준으로 표시한다.
- 실행 후에는 `성장 / 이번 주 경기 / 몸 상태` 3항목을 담은 결과 카드 하나를 보여 준다. 능력치가 같아도 `성장 진도 1/2`처럼 실제 누적을 표시한다.
- 결과 확인이 끝난 뒤 예정된 대화·직접 등판·시즌 결산으로 이어진다. 여러 결과 팝업이 겹치지 않도록 표시 순서를 관리한다.
- 결과는 성공적으로 저장된 전후 상태에서 만들고, 재실행해도 보상을 다시 계산하지 않는다. 앱을 다시 열어도 확인하지 않은 결과를 볼 수 있게 한다.
- 여러 주 또는 훈련 계획을 묶어 진행하면 합산 결과를 한 번 보여 주고 세부 내역은 펼쳐 본다.

**완료 기준:** 계획을 눌러 보는 것만으로 한 주가 지나가지 않는다. 성장 +0인 주에도 쌓인 진도와 자동 경기 결과를 알 수 있다. 연속 탭·재시작으로 이중 진행되지 않는다.

## 3. 경기 전·투구 중·경기 후 상황 통일

**경기 전:** 작은 선수 헤더 → 상황판 하나 → 목표·보상 → `등판하기`.

- 고교와 프로의 경기 전 카드, 실제 투구 HUD, 등판 결과가 동일한 등판 배정 데이터를 사용한다.
- 보직, 이닝, 아웃, 주자, 점수 차, 목표를 한 번씩 표시한다. 실제 전체 점수가 없는 상황에서 임의의 점수를 만들지 않는다.
- 보직과 무관한 ‘선발 맞대결’ 같은 문구를 수정한다. 선발·긴 이닝 구원·셋업·마무리 및 개막·승격·가을야구를 함께 확인한다.
- 긴 이야기, 상대 상세, 지난 기록은 접고 목표와 실제 투구 선택을 우선한다. ‘타석/이닝/등판’ 단위를 실제 플레이 범위에 맞춘다.
- 공이 날아가는 동안 다음 결과가 점수판이나 목표에 먼저 드러나지 않게 유지한다.
- 선발 테스트 중 이닝 종료 시 `테스트 이어 던지기`를 주 행동으로 둔다. 자동 진행으로 종료하면 직접 투구 목표가 중단된다는 사실을 버튼 밖 한 줄로 명시한다.
- 경기 종료 결과에는 목표 달성 여부와 실제 지급 보상을 남긴다. 진행 중인 구버전 투구는 확정된 상황을 보존한다.

**완료 기준:** 사전 안내와 실제 투입 상황이 일치한다. 작은 화면에서도 목표·구종·코스·슬라이더를 쉽게 확인한다. 목표 보상은 상한을 반영해 한 번만 지급된다.

## 4. 대화의 이득·비용과 인물 일관성 보완

- 효과를 성장·피로·신뢰·훈련 지원·기회 등 구조화된 항목으로 전달한다. 앞의 두 문자열만 잘라 쓰지 않는다.
- 선택 카드에는 주요 이득과 비용을 함께 표시한다. 추가 효과가 있으면 개수와 한 번의 상세보기로 전부 확인한다.
- 높은 피로, 팔 부담, 신뢰 감소 등 중요한 불리한 효과가 요약에서 누락되지 않도록 우선순위를 정한다.
- 결과 카드도 생략된 효과를 확인할 수 있게 한다. 모든 선택에 비용을 인위적으로 추가하지는 않는다.
- 각 효과를 번역한 뒤 조합한다. 실제 `지원 · 신뢰 +4` 같은 합성 문장과 접근성 설명을 한국어·영어·일본어에서 검사한다.
- NPC 초상화는 번역 이름이 아닌 고정 식별자를 사용한다. 기존 한국어 얼굴에 쓰인 seed를 보존해 업데이트와 언어 변경 때문에 얼굴이 바뀌지 않게 한다.

**완료 기준:** 선택 전에 알 수 없었던 비용이 결과에서 갑자기 나타나지 않는다. 혼합 언어·부호 유실이 없고 같은 인물은 모든 언어에서 같은 얼굴을 유지한다.

## 5. 공통 버튼·색상·정보량 정리

- 선택은 초록색과 선택 표시, 유리한 변화는 성장색, 부담은 주의색, 실패·오류는 오류색으로 통일한다. +/-와 설명을 함께 제공한다.
- 능력 증가와 피로 감소처럼 유리한 방향이 다른 수치를 항목별로 처리한다. 숫자가 커졌다는 이유만으로 같은 색을 쓰지 않는다.
- 기록 탭의 별도 보라색 선택 상태를 공통 선택 표현에 맞춘다.
- 버튼 안에는 행동 이름만 두고 가격·효과·위험은 밖으로 옮긴다. 의미를 자르거나 글씨를 과도하게 줄여 맞추지 않는다.
- 중복 선수 헤더·안내·‘자세히’ 버튼을 정리하고 상세는 한 단계로 유지한다.
- 작은 화면, 큰 글씨, 키보드 표시에서도 실행 버튼과 다음 행동이 가려지지 않게 한다.

**완료 기준:** 고교와 프로에서 선택/실행/비용의 의미가 같다. 360dp 화면과 글자 배율 1.0·1.3·1.5·2.0에서 핵심 행동을 사용할 수 있다.

## 6. 실제 기록을 바탕으로 캐릭터 애착 강화

- 선발 테스트 통과, 첫 세이브, 처음 지킨 리드, 개인 최고 등판처럼 의미 있는 실제 사건을 한 줄 기억으로 남긴다.
- 같은 사건은 커리어와 사건 식별자로 중복 저장하지 않는다. 모든 훈련·투구를 새 알림으로 만들지 않는다.
- 선수 화면에는 대표 기억 소수만 보여 주고 나머지는 카드에서 확인한다. 다음 대화는 관련된 실제 기억을 짧게 언급한다.
- 환생 결산에는 `이번 생의 대표 장면 → 다음 생에 이어지는 힘 → 새 출발 비교`를 연결한다. 기록에 없는 활약이나 지급되지 않은 보상을 이야기로 만들지 않는다.

**완료 기준:** 유저가 내 투수가 해낸 일을 쉽게 떠올릴 수 있고, 다음 도전과 연결된다. 대화·카드·환생에서 사실과 수치가 일치하며 팝업 수가 늘지 않는다.

## 7. 전체 검증과 실기기 마무리

- 기능별 수정 때 관련 검사와 재현 화면을 함께 갱신한다. 마지막에 core/application/persistence/app/UI 검사를 모아 실행한다.
- 알려진 실패 5개를 해소하고 제외된 릴리스 비교 검사에는 검증 가능한 근거와 결과를 남긴다. 실패·미검증을 숨긴 ‘전체 통과’ 판정은 하지 않는다.
- 새 게임 → 첫 불펜 → 학교 → 훈련·대화 → 직접 경기 → 드래프트 지명/미지명 → 연계/단독 프로 → 시즌 전환 → 은퇴 → 환생을 확인한다.
- 저장 후 재열기, 백그라운드 복귀, 미확인 결과 복구, 빠른 연속 탭, 언어 변경을 포함한다. 삭제·복구 검사는 별도 데이터로 수행한다.
- 기본 슬라이더 한 구, 보조 원탭 투구, 퍼펙트 햅틱, 결과 대기, 테스트 중단 경로를 확인한다.
- 연결된 실기기에서 터치감·햅틱·화면 밀도·발열·끊김을 직접 확인한다. 연결되지 않으면 해당 검증은 미완료로 남긴다.

**최종 완료 기준:** 기록 수치가 일치하고, 실행 전 결과 범위를 이해할 수 있으며, 실행 후 성과가 남는다. 기존 저장이 유지되고 핵심 투구 조작이 정상 작동한다.

## 작업 기록과 전달

- 기능별로 구현·관련 검증·변경 설명을 묶어 커밋하고 푸시한다. 큰 UI 변경 전에 데이터/규칙 변경을 검증한다.
- 같은 문제를 발견한 QA 재현 화면과 수정 후 화면을 비교해 남긴다.
- 기존 안정된 빌드 디렉터리를 재사용한다. 사용자 저장과 최종 증거는 보존한다.
- 단계별 완료 보고에는 변경점, 검증 결과, 남은 문제만 적는다. 전체 제품 수정에 착수할 때 이 문서를 실행 기준으로 사용한다.
