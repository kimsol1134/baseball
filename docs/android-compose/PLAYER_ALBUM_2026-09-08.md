# 선수 앨범 구현 및 검증

## 의도

선수가 시즌을 마치거나 환생해도 개별 등판과 직접 투구를 보존하고, 기록 탭에서 선수·시즌을 골라 카드로 공유한다. 기록이 없는 과거의 경기나 투구를 만들어내지 않는다.

## 구현

1. 기록 보존: aggregate meta.album을 추가했다. 기존 필드가 없는 저장 파일은 원래 포맷·commitment를 유지한다. 시즌 전환 직전/직후를 함께 수집해 프로 개별 등판 유실을 막고, 동일 경기 ID의 자동 결과가 직접 결과로 정산되면 최종 결과로 교체한다. 이전 시즌의 사진 기준·소속·대표 구종·능력을 보존한다. 읽기만 하는 앨범 조회는 저장 명령을 내리지 않는다.
2. 선수 앨범: 현재 선수의 현재 시즌부터 보여준다. 첫 화면은 얼굴·이름·소속·대표 구종·기록 세 개와 대표 경기. 전체 등판은 접어서 5개씩 더 보기. 기록이 불완전한 과거는 누적 성적과 상세 기록의 차이를 알린다.
3. 공유 카드: 선수 / 인생 경기 / 시즌 / 계보 카드. 이미지 미리보기와 저장·공유가 같은 비트맵을 사용한다. 사용자가 선택하기 전에는 외부 앱을 열지 않는다. 임의 등판 카드와 선택 기간의 첫 승·첫 세이브·첫 선발·첫 무실점 기록을 고를 수 있다. 이미지에는 내부 seed, 설치 식별자를 넣지 않는다.
4. 환생 계보: 지난 선수 앨범으로 이동하며 대표 유산을 확인한다. 두 고교 커리어가 모두 끝났을 때 같은 기간의 최종 능력을 비교한다. 자동 경기와 직접 경기를 구분한다.
5. 재생: 저장된 직접 투구의 궤적·구종·구속·결과·투구 전 주자 상황을 보존한다. 기존 투구 렌더러를 읽기 전용으로 사용한다. 재생은 시뮬레이션·명령·RNG·보상 경로를 호출하지 않는다. 당시 타구/수비 애니메이션의 전체 재현을 약속하지 않는다. 저장되지 않은 이전 투구는 재생할 수 없다.
6. 백업: 운영용 native 저장 및 개발용 shadow 저장 모두 앨범을 포함한다. 개발용 백업은 같은 저장 형식에서 복원한다. 복원 전 checksum/구조를 검증하고, 저장 후 읽기 검증을 통과해야 성공을 표시한다. 마지막 성공한 파일 백업 시점을 설정에서 표시한다.

## 검증

전체 application 테스트 175개, Android JVM 테스트 15개 통과 (중간 전체 실행). 20시즌 native 저장·재실행·은퇴·환생 경로 포함. lintDebug 통과. 이후 보완의 타깃 재검증과 실기기 UI 검증은 아래에 추가한다. 사용자 실기기의 기존 저장 파일을 초기화하지 않는다.

### 최종 확인

- 추가/보완 application 타깃 테스트 9개 통과: 구버전 저장, 앨범 변조 거부, 시즌 전환, 궤적 유지·중복 방지, native/QA 백업·다른 설치 복원·복원 후 진행.
- Galaxy A53 실기기: 앨범 테스트 3개 통과 (미리보기·재생의 기록 불변, 글씨 2배, 영어·일본어 팝업). 기본 투구 슬라이더/힘배분 테스트 4개도 통과.
- 최초 locale 시험에서 Dialog가 기기 언어로 돌아가는 문제를 발견하여, 팝업 진입 시의 언어를 명시적으로 전달한 후 재검증 통과.
- 한국어·영어·일본어 34개 변경 항목 확인. 추가 콘텐츠의 실존 구단명 검색 통과. 최종 APK 빌드 및 lintDebug 통과.
- 실기기에 최신 QA APK 설치·MainActivity 실행. 기존 shadow 및 native 저장 파일 두 개는 설치 전/최종 실행 후 SHA-256 동일.
- 공유 대상 앱으로 전송하거나 사용자의 갤러리에 시험 이미지를 추가하지 않았다. 카드 미리보기, 저장·공유 경로의 구현과 오류 처리까지 확인했다.
