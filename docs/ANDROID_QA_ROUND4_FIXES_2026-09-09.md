# Android 4차 QA 개선 결과 · 2026-09-09

계획: `ANDROID_QA_ROUND4_IMPROVEMENT_PLAN_2026-09-09.md`. 기존 2·3차 미커밋 작업을 보존한 추가 수정이다. 업로드·출시는 수행하지 않았다.

## 저장 전이와 오류 복구

S-01의 원인은 두 writer가 ABANDONED로 바꿀 때 suspendedFrom을 남긴 것이었다. `PitchStateTransitions`를 추가해 native bridge와 일반 reducer가 중단·재개·포기 규칙을 공유하도록 했다.

- RESERVED/PLAYING에서 중단한 투구는 suspendedFrom을 정리하고 안전하게 포기한다.
- 이미 결과가 커밋된 중단 투구는 포기를 허용하지 않고 결과 확인 경로로 복구한다. 결과 ID·hash·기록을 지워 검사를 통과시키지 않는다.
- RESERVED에서 중단된 연습 투구는 재개 후 StartPitch까지 진행해 실제 입력 가능한 PLAYING 상태가 된다. 새 투구를 다시 예약하지 않는다.
- 불변식은 느슨하게 만들지 않았다. 12개 유효한 출발 상태에서 중단/재개/포기 36조합의 허용·거부를 확인했다. 허용된 결과는 validate를 통과하고 금지된 명령은 원본을 바꾸지 않는다.
- 오류 문구도 공통 분류 함수로 옮겼다. 투구 상태 오류를 단순 재시도/저장 공간 오류와 구분하고, 저장된 투구·결과로 돌아가도록 안내한다.

보존된 실제 SUSPENDED(from PLAYING) 프로 파일과 고교 결과 파일에서 포기·재개·native 재저장/재개방, 기록 보존을 검증했다. 현재 수집한 4차 최종 파일은 프로 주간 계획 상태이므로 S-01 순간의 파일이라고 표현하지 않는다. 실제 중단 상태 검증에는 보존된 3차 실제 파일을 재사용했다.

## 검증과 증거

관련 application 단위 테스트 43개와 platform 단위 테스트 29개, **합계 72개 통과**. 계측은 독립 재실행을 포함해 **고유 16개 통과**(화면/기존 회귀 14개 + 실제 투구/포기·재개 2개). 전체 프로젝트 테스트 스위트 통과라는 뜻은 아니다. 상세는 `artifacts/qa/android-round4-fixes-2026-09-09/unit-results.json` 및 계측 로그에 보존했다.

- 직접 조작의 기본값은 투구 슬라이더로 유지한다. 피로 47/79에서 별도 탭 없이 결과 진입, 피로 80/86/87의 유효한 입력 화면에서 보조 버튼 노출과 등판 종료를 확인했다. 최신 두 정상 투구의 결과 진입은 약 5.5~5.7초였으며, 이전 따뜻한 실행에서는 약 3.3~3.7초였다.
- 공용 배치·내비게이션 픽셀·드래프트 끝 문장·선택 설명·승격 안내·비행 도형 검사를 수행했다.
- 커널에서 준비한 실제 입력 상태를 사용하는 QA fixture로 고피로 버튼을 검증한다. 자연 플레이의 강판 후 화면에서 버튼이 보였다고 주장하지 않는다.
- 실제 중단 세이브를 앱 버튼으로 포기하고 다시 슬라이더까지 복귀했으며, 고교/프로 데이터가 변하지 않음을 확인했다. 큰 QA 파일의 재개는 에뮬레이터에서 약 14.8~18.9초가 걸린 사례가 있다. 짧은 자동화 대기 시간이 끝나 앱을 종료시키지 않도록 완료 상태를 기다려 검증했고, 제품에는 그동안 마운드 준비 화면을 표시한다. **이 지연의 실기기 성능 검증은 남아 있다.**
- 테스트용 비공개 PitchActivity는 앱 내부의 Instrumentation 경로로 실행한다. 테스트 편의를 위해 exported를 변경하지 않았다. 화면 전환과 fixture 교체 사이의 기존 Activity/비동기 작업을 정리했다.
- 실제 QA 게임 파일은 `source-save.json`, 테스트 패키지의 이전 저장은 `harness-before.json`에 보존했다. 전용 `.reset.compose.qa` 테스트 데이터와 사용 중인 `.compose.qa` 진행을 분리했다.
- 최종 캡처: 오류 시 액션, 드래프트 끝 문장, 내비게이션, 좌/우 비행 장면, 승격 안내, 능력 변화 기록, 고피로 입력 및 중단 후 재개.

## 사용자 확인용 QA 업데이트

`baseballLaunchQa=true` + `baseballQaNativeStore=true`로 만든 `com.solkim.baseball.android.compose.qa`를 에뮬레이터에 업데이트 설치했다. 원본 QA 앱을 초기화하지 않았다. 업데이트 전후 pro·highSchool·installId의 동일성을 확인했다. APK 해시, 설치 로그, 화면과 세이브 비교는 증거 디렉터리에 보존했다. 테스트 fixture는 사용자 확인용 APK에 포함되지 않음을 확인했다.

## 외부 조건

이번 작업에서 확인된 연결 기기는 에뮬레이터였다. 실기기 OS 자동 복원/기기 이전, 태블릿·폴더블, TalkBack 실청취는 완료로 처리하지 않는다. RC 스크립트는 `BASEBALL_UPLOAD_KEYSTORE_PATH` 미설정으로 시작하지 못했다. 서명 조건을 우회하지 않았다.

4차 QA 패키지의 알림 권한 허용과 기존 예약 1건을 확인했다. 이 예약을 테스트용으로 간주해 취소하지 않았으며, 원본 QA 패키지를 초기화하지 않았다. 이 보고서는 출시 승인이나 production 배포 완료를 의미하지 않는다.
