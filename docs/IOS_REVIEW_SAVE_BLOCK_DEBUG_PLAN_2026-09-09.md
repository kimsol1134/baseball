## 판단

진행 불가와 누적 보상 손실을 최우선 장애로 다룬다. 증상은 네 갈래지만 저장 호환성과 고교/프로 연결 오류가 여러 증상을 함께 만들었을 가능성이 있다. 단일 원인으로 확정하지 않는다.

| 증상 | 코드에서 확인한 사실 | 아직 확인할 것 |

기능 도입 전 고교 회차의 `signatureLegacyRulesVersion == nil`은 기존 기억 규칙으로 마무리하도록 구현되어 있다. 새 기능을 위해 전체 기록을 지워야 한다는 안내를 해결책으로 사용하지 않는다.

## 디버그 순서

### 1. 증거 확보와 원본 보존

- 앱 버전/빌드, iOS 버전, 정확한 오류 문구 또는 화면, 시즌/주차, 마지막 성공 행동, 사용한 삭제 메뉴를 확보한다. 먼저 내부 배포 기록과 장애 로그를 확인하고, 사용자에게는 없는 정보만 요청한다.
- 저장본 접근이 가능하면 복구 로직을 실행하기 전에 고교·프로 원본, 원격 사본, 백업, 삭제 레코드를 별도 보존한다. 실사용 저장본에서 삭제·초기화로 재현하지 않는다.
- 배포 태그와 현재 HEAD를 비교하여 아래 호환성 및 은퇴 처리 변경의 실제 출시 여부를 기록한다. 기존 답글 파일에 있는 “수정 완료” 표현을 출시 증거로 사용하지 않는다.
- 로그는 오류 코드, 실행 명령, phase/revision, 저장 스키마·규칙 버전, 복원 출처, 연결 판정 사유를 남긴다. 공개 로그에 선수 이름이나 전체 저장본을 올리지 않는다.

### 2. 시즌 전환 교착 재현

- 문제 업데이트 직전 버전에서 만든 시즌 종료 직전 저장을 대상 버전으로 연다. 시즌 리뷰 → 결산 → 재계약/오프시즌 → 투자 → 다음 시즌을 각각 검증한다.
- 옛 `journeyState == nil` 저장, 계약 제안 대기, 시즌 결정 누락, 반복 시즌 기록, 군 복무/이적/은퇴 분기를 포함한다.
- 디코딩/마이그레이션, commitment 검증, 엔진 명령, 영속 저장, 화면 라우팅 중 실패 지점을 나눈다. 오류를 무시하거나 검증을 끄는 방식으로 우회하지 않는다.
- 기존 `ProCareerJourneyMigrationTests`, `ProCareerJourneyStoreTests`, `ProSeasonDecisionTests`를 출발점으로 실제 재현 저장에 대한 회귀 테스트를 추가한다.
- 합격: 기록 삭제 없이 다음 시즌 첫 주 도달, 재실행 후 유지, 시즌 기록·정산 보상 중복 없음.

### 3. 은퇴 → 고교 새 회차와 유산 보존

- `careerOrigin`, `sourceHighSchoolCareerID`, `enteredProCareerID`, `creditedProCareerID`, 선수 신원, 고교 phase를 함께 비교한다.
- 신규 정상 저장, origin/source 없는 옛 저장, 명시 source 불일치, 고교만 삭제된 상태, 직접 프로 시작을 각각 재현한다.
- 유산 저장 직후 프로 삭제 실패, 재시도, 앱 종료, 원격 동기화, 유산 선택/정산 후 새 선수 시작 실패를 주입한다. 특히 대체 보상 경로가 고교의 오래된 화면을 남기는지 끝까지 확인한다.
- `SignatureLegacyIntegrationTests`의 연결·중복 지급·저장 실패 테스트를 확장한다. 설정의 고교 삭제 성공/프로 삭제 실패도 별도 검증한다.
- 합격: 고교 → 프로 → 은퇴 → 고교 새 선수 루프를 최소 5회 완료. 매 회차 아카이브·목표 보상·야구혼·유산과 실제 시작 능력치를 전후 비교하고 재실행 뒤에도 유지한다. 정상 성장으로 변하는 값은 예상 변화량과 비교한다.
- 복구 설계는 현재 진행 복구와 전체 초기화를 분리한다. 출처가 불명확한 옛 선수를 임의로 연결하지 않으며, 기존 누적 자산을 유지하는 복구 경로를 우선한다.

### 4. 동기화와 복구 가능성

- 고교/프로는 별도 저장이므로 각각 최신이어도 서로 다른 시점일 수 있다. 리비전이 엇갈린 두 저장, 지연된 원격 변경, 동일 리비전 삭제 레코드 충돌을 테스트한다.
- `SaveSync`와 각 저장 코덱의 복원·백업 테스트를 실행하고, 실제 iCloud 환경에서도 재설치/재실행 복원을 확인한다.
- 복구 가능한 사본이 남았는지 먼저 판정한다. 전체 삭제 경로가 복구 사본을 폐기하므로 복구를 보장하지 않는다. 반대로 리뷰 작성자의 “복구 불가” 추측만으로 조사를 닫지도 않는다.

### 5. 구종 연구 표시와 집계

- 훈련/실전 `(5,0)`, `(7,1)`, `(7,2)`, `(9,0)`, `(9,1)`을 고교·프로에서 확인한다.
- 완료된 연구에는 완료 상태를 보여 주고 미완료 과제처럼 보이는 잔여 수치 표시를 정리한다. 단순히 실전 수치를 2로 채워 실제 기록을 바꾸지 않는다.
- 직접 투구, 자동 진행, 경기 재개, 고교→프로 이관에서 `qualityUses` 집계와 저장을 추적한다. 횟수 인정 조건과 단순 투구 횟수를 구분한다.
- 기존 구종 연구 테스트를 실행하고 완료 표시 회귀를 보강한다. 기본 슬라이더로 한 구를 끝까지 던지고 관련 집계가 반영되는지도 확인한다.

## 완료 및 배포 판단

재현 저장의 비파괴 복구, 다회차 보존, 실패 주입 후 재시도, 재실행/동기화 검증까지 통과해야 수정 완료로 보고한다. 수정 범위에 맞는 한국어·영어·일본어 UI 검증을 수행하고, 공개 배포는 AGENTS.md의 서명 IPA 현지화·일본어 스모크·대상 버전 App Store 지원 언어 확인 조건을 따른다.

말씀해 주신 시즌 전환과 은퇴 후 새 선수 시작 경로를 우선 조사하고 있습니다. 기존 선수와 누적 보상을 보존하면서 진행을 이어 갈 수 있는지 확인하고, 구종 연구 후 실전 적응 문구가 남는 문제도 함께 살펴보겠습니다.
