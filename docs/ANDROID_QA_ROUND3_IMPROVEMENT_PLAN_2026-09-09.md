크래시 없이 고교→계약→프로 시즌을 완주했다는 점은 긍정적이다. 남은 핵심은 후반부 화면의 정보 부족, 선택과 확정의 혼동, 커리어 상태를 잘못 참조하는 표시/알림 경로다. 개별 화면만 고치지 않고 같은 역할의 모든 화면에 동일한 완료 기준을 적용한다.

## 코드 대조에서 확인한 것

- R-08·09: `Phase8ScreenModels.kt`의 복귀 카드와 `MainActivity.scheduleSavedReturnPlan()` 모두 `highSchool.returnPlan`을 참조한다. `Phase9AndroidServices.kt`는 권한이 없으면 `Blocked`를 반환하지만 호출부가 반환 결과를 사용하지 않는다. 카드 표시만 프로로 바꾸면 알림·알림 탭 후 이동은 여전히 틀릴 수 있다.
- R-03·04: `Phase8ContractChoices()`의 목표 항목은 바로 `acceptOffer` 명령을 전달한다. 계약 요약의 라벨 없는 금액은 실제로 `offer.annualSalary`, 펼친 금액은 `offer.signingBonus`다. 서로 다른 금액을 잘못 계산한 것으로 단정할 사안은 아니며 우선 라벨과 확정 흐름을 수정한다.
- R-06: 선택 효과 미리보기 함수는 이미 있다. 그러나 일부 결정만 `role()`을 얻어 대화 화면/미리보기 경로를 사용하고 나머지는 일반 화면으로 빠진다. 기존 효과 계산을 모든 결정 유형에 연결하는 것이 우선이다.
- R-10 대화 결과: `ConversationFeedbackGate()`는 공통 내비게이션보다 먼저 반환된다. 이전 수정에서 선택 화면만 감쌌고 결과 화면을 놓쳤다. 결과 버튼에 Kotlin testTag는 있으므로 ‘태그를 처음 추가’하는 것과 화면의 resource-id 노출 누락을 구분한다.
- R-10 중단 경기: 기존 `OutingPresentation.briefing()`에는 이미 활성 경기 참조 경로가 있다. 요약 UI를 새로 만들기 전에 실제 화면 ID·stage·phase·activePitch·projection 결과가 어디서 어긋나는지 재현 상태로 추적한다.
- R-07: 주간 화면에는 이미 `Scaffold`가 준 padding이 적용된다. 스크린샷은 스크롤 영역의 끝에서 제목이 일부 보이는 현상을 확인해 주지만, 버튼이 실제 콘텐츠를 덮는다는 원인까지 확정하지는 않는다. 버튼 높이만큼 padding을 중복 추가하지 않는다.
- R-11: 결과 UI가 outcome이 없으면 ‘투구 완료’로 대체하는 경로, 시즌 요약이 경기/탈삼진/퍼펙트와 팀 승수만 표시하는 경로를 확인했다. 헤더 초기화·궤적 누락의 구체적인 원인은 추가 추적이 필요하다.

### 알림·복귀 작업의 추가 조건

- R-08의 공통 목적지 계산을 먼저 만들고 R-09가 이를 사용한다. 필요하면 프로 직접 시작도 저장할 수 있는 복귀 계획 모델을 추가하고 이전 세이브 호환을 검증한다.
- ‘계획 저장’, ‘알림 예약’, ‘실제 알림 표시’를 다른 상태로 취급한다. 권한을 받았다는 이유만으로 예약 성공을 표시하지 않는다.
- 기존 알림을 먼저 취소하고 새 예약에 실패하는 경우까지 처리한다. 중복 탭·예약 변경·취소·앱 재실행에 대해 알림이 중복되거나 성공 표시만 남지 않아야 한다.
- 현재 구현의 다음 날 09:00 Asia/Seoul 정책을 우선 유지하고 날짜 경계·과거 시각을 검사한다. 현지 시간대로 바꾸는 일은 별도 제품 정책 변경으로 취급한다.
- 알림을 누르기 전에 선수 환생·커리어 변경·진행 삭제가 일어나면 오래된 목적지를 실행하지 않고 현재 유효한 화면으로 안전하게 연결한다.

### 드래프트·인물 작업의 추가 조건

- 통산 기록은 수동 투구 기록과 자동 경기 기록의 기존 집계 범위를 따른다. 합계를 중복 계산하지 않는다.
- 다른 구단의 평가는 실제 데이터가 있을 때만 제공한다. 없는 평가·경쟁 제안·인물의 과거 행동을 만들어 사실처럼 표시하지 않는다.
- 새로운 인물의 대사는 창작 콘텐츠로 작성할 수 있으나, 실제 플레이의 선택·관계와 맞는 조건에 연결한다. 가상 구단·인물 규칙과 3개 언어 지원을 유지한다.
- R-01은 서사 밀도 개선이다. 공간을 채우기 위해 무관한 카드나 긴 대사를 추가하지 않고 실제 성취를 우선한다.

## 같은 결함이 반복되지 않게 하는 범위 점검

다음 표를 실제 화면별 점검표로 만들고 해당 없음에도 이유를 기록한다. 특정 화면 이름이 테스트에 들어갔다는 것만으로 모든 변형이 검증됐다고 보지 않는다.

| 화면군 | 함께 점검할 표면 | 공통 규칙 |
| --- | --- | --- |
| 선택/확정 | 학교, 계약, 고교 대화, 모든 프로 결정 유형, 각성, 환생 | 선택과 커밋의 의미가 명확하고 비용·효과가 사전에 보임. 기존 즉시 선택형 대화까지 무조건 확인 대화상자를 추가하지 않음 |
| 진행/결과 | 투구 전, 투구 중단, 일반 결과, 마지막 공, 대화 결과, 시즌 결산 | 현재/마지막 상태 구분, 정보 유지, 결과 확인의 중복 반영 방지 |
| 화면 이동 | 선택, 결과, 상세, 기록, 복귀, 알림에서 열린 화면 | 버튼/시스템 뒤로 동작 일치, 클릭 식별자와 접근성 의미 제공 |
| 숫자/문구 | 생성, 성장, 계약, 통산, 시즌, 도전, 알림 | 눈금·단위·기간·합계 범위 명시, 명칭과 실제 내용 일치 |
| 배치 | 위 화면 전체의 기본 상태·긴 내용·큰 글자 | 초기 핵심 행동 노출, 전체 콘텐츠 접근, 하단 가림·중복 블록 없음 |

모든 프로 결정 유형을 열거하는 테스트를 추가해 `role()` 분류에서 빠진 경우에도 효과 미리보기와 올바른 선택 UI를 제공하는지 검사한다. 대화 선택과 결과는 반드시 별개의 테스트 대상으로 둔다.

## 검증 방법과 완료 기준

1. R-11A 마지막 투구, R-10A 중단 경기, R-09 권한 거절, R-03 계약 직전의 최소 재현 상태를 먼저 확보한다. 상태 JSON/명령 경계와 스크린샷을 연결하고 수정 전 실패를 확인한다.
2. 데이터/상태 변경에는 의미 있는 회귀 테스트를 작성한다. 단순 문구 수정을 그대로 복사하는 테스트는 추가하지 않는다. 표시 모델과 저장 모델의 합계·효과·대상 커리어를 비교한다.
3. 알림은 전용 QA 패키지에서 권한별 예약 결과, 수신, 탭 후 복귀까지 검증한다. 실제 사용자에게 반복 테스트 알림을 남기지 않고 테스트 예약과 변경한 설정을 정리한다.
4. 짧은 재현 검사 외에 고교 8장→지명→계약→프로 한 시즌을 다시 진행한다. 프로 직접 시작과 고교 출신 프로를 모두 검사한다. 마지막 공과 중단/재실행을 여정에 포함한다.
5. Pixel 에뮬레이터와 연결된 A53에서 ko/en/ja, 글자 100/130/150%, 작은 높이·긴 내용·시스템 뒤로를 확인한다. 기기 연결 여부는 실행 시 다시 확인한다.
6. 기존 B-01 복구, N-02 능력치, N-03 단일 격자, N-13 고피로 출구, N-14 재개 무결성을 회귀 검사한다. 직접 투구의 기본값과 실제 한 구 완료는 계속 슬라이더로 검증한다.
7. `check:android:compose`, `check:android:compose:release`, `check:copy`, 현지화 재생성/인벤토리 검사를 통과한다. 서사·인물·구단 문구의 실존 야구 명칭 및 약칭 혼입을 검사한다.

각 작업은 수정 완료와 검증 완료를 분리하고, 대상 패키지·APK 해시·저장 모드·기기·상태·기대/실제 결과·증거 경로를 남긴다. 이번엔 R-10A/B, R-11A/B/C를 분리하여 일부만 고치고 항목 전체를 닫지 않는다.

## 기존 미완료 항목과 보고서 해석

- N-01 OS 자동 복원은 계속 별도 검증 항목이다. 수동 파일 이전 성공이나 안내 수정으로 완료 처리하지 않는다. 두 실기기 자동 복원·제조사 이전 조건이 필요하다.
- 태블릿·폴더블 및 TalkBack 실청취도 유지한다. 오디오 포커스 요청/반환 횟수 개선은 긍정적이나 외부 음악과의 상호작용이 모두 검증됐다는 뜻은 아니다.
- 3차 보고서의 N-13·14는 코드 확인이다. 이전 A53 합성 상태/UI 검사와 이번 자연 플레이 재현을 구분해 기록한다.
- 요약은 ‘14건 중 해결 12/잔여 2’지만 표에는 N-01·06·08이 부분 완료이며 N-13·14는 코드 확인이다. 완료 숫자를 그대로 이월하지 말고 ID별 증거 기준으로 재집계한다.
- 스크린샷 수집 62장과 공유 증거 9장은 전체 수집/선별본일 수 있다. 재검증에 필요한 누락 상태는 따로 확보한다. 11개 ID 안에 여러 독립 문제가 묶였으므로 작업 수를 11개로 고정하지 않는다.
- 이전 RC의 키스토어 미설정 상태는 실행 시 다시 확인한다. 서명된 production RC 확인 전 debug QA를 출시 완료로 표현하지 않는다. 이 계획은 업로드·출시 승인이 아니다.

권장 실행 묶음은 **경기 결과/복귀·알림 → 계약·시즌 결정 → 중단 경기·대화 결과·배치 → 드래프트·프로 인물 → 기록·용어 → 전체 후반부 여정 재검증**이다.
