## 1. 최종 판단

초기 감사에서는 6.5/10의 고급 프로토타입으로 판정했으나, 구현과 세 차례의 재감사를 거친 현재 빌드는 **정의한 IMP-01~10의 코드·웹 출고 조건을 모두 충족한다.** 행동 우선순위, 실패 복구, 결과 전달, 모드 정체성, GameCast 상태 정확성, 성장 피드백, 세계관 검증이 같은 기준으로 연결됐다.

- 실존 학교·독립구단과 충돌한 27개 고위험 명칭을 공식 학교 데이터 및 공개 이력과 대조해 독자 명칭으로 교체했다.
- Pitcher Lab의 확인 여부와 실제 전후 수치를 저장·코어 결과에서 직접 전달해 재실행·상한 clamp에서도 거짓 수치를 표시하지 않는다.
- Chromium 실제 UI 회귀 검사가 데스크톱, 390×844, 130% 글자, 고대비, OS 모션 감소와 실제 Swift 코어 연결 상태를 CI에서 실행한다. 고교 설정·훈련 결과·GameCast는 승인 기준 이미지와 픽셀 회귀를 비교한다.
- 프롬프트 기록이 없던 커리어 키아트를 은퇴시키고 고교 진입·고교 구장·프로 만원 구장을 같은 Midnight Dugout 방향으로 다시 생성했다. 고교와 프로의 장소 규모가 관중·조명·시설로 구분된다.
- 현재 구현 완성도는 **9.2/10, 출고 후보 통과**로 판정한다. 남은 0.8은 실제 Windows WebView2/macOS WKWebView 프레임 시간 계측과 대규모 외부 플레이테스트이며 디자인 시스템 미적용 항목은 아니다.

## 2. 개선 원칙

1. **행동이 장식보다 먼저다.** 첫 화면에서 지금 해야 할 선택과 그 결과를 발견할 수 있어야 한다.
2. **수치는 실제 상태만 말한다.** 모델에 없는 학년·신장·등번호·점수는 그럴듯하게 꾸며 넣지 않는다.
3. **결과는 다음 선택 전에 닫는다.** 능력·피로·관계의 변화를 확인한 뒤 다음 단계로 이동한다.
4. **모드마다 하나의 장소성을 갖는다.** 고교, 연구실, 프로, 경기 중계가 같은 전역 배경을 공유하지 않는다.
5. **이미지는 세계를 만들고 UI는 판단을 돕는다.** 한 화면의 큰 시각 앵커는 하나로 제한하고 텍스트 대비를 희생하지 않는다.
6. **접근성 설정은 실제 동작을 바꾼다.** 운영체제 모션 감소와 고대비가 CSS 장식뿐 아니라 RAF 재생·사진 배경에도 적용돼야 한다.
7. **완료는 자동 검증과 실제 화면 검토로 증명한다.** 토큰 검사 통과만으로 반응형·포커스·상태 정확성을 주장하지 않는다.

## 4. 화면별 적용 결정

### 고교 커리어

- 모바일 현재 행동 바로가기를 히어로 직후에 둔다.
- 능력치 증감 버튼에 지표 이름이 포함된 접근 가능한 이름을 부여한다.
- 튜토리얼과 드래프트 공개를 공통 모달 동작으로 통합한다.
- 학교색은 데이터 ID에서 파생한 의미 토큰으로만 표현하고 실존 학교·구단 문양을 만들지 않는다.

### Pitcher Lab

- 진입 실패를 공통 복구 화면으로 대체한다.
- 훈련 문구를 확정적 상승이 아닌 가능성·피로·반복 감쇠 언어로 바꾼다.
- 결과 전후 값, 피로, 관계 변화를 확인하는 단계를 고교 커리어와 같은 패턴으로 제공한다.
- 연구실은 사진을 추가로 겹치지 않고 TRACKLAB 좌표·계측 질감으로 장소성을 만든다.

### 프로 커리어

- 고교 전역 배경 의존을 제거하고 구장·기록 보드 중심의 프로 장면을 사용한다.
- 데이터에 없는 키·학년·등번호는 삭제한다.
- 구단별 강조색은 가상 구단 ID에만 매핑한다.

### GameCast

- 투구는 TRACKLAB 분석 좌표계, 인플레이는 구장 시점으로 역할을 분리한다.
- 리플레이 표시 상태는 반드시 결과 스냅샷을 기준으로 한다.
- OS 모션 감소, 앱 모션 감소, 고대비를 동일한 렌더 분기로 연결한다.
- 배경과 SVG가 서로 다른 카메라로 움직이지 않도록 사진은 변형하지 않고 안전 크롭을 사용한다.

## 5. 자산·세계관 계약

- 기본 배포물에 실존 프로 구단명, 구단 약칭, 리그명, 선수명, 로고, 유니폼 문양, 슬로건을 사용하지 않는다.
- 실제 도시명은 허용하되 가상 학교·구단·대회 명칭은 독자 명칭으로 유지한다.
- 역할 초상은 캐릭터의 신분증이 아니라 분위기를 보조하는 장식 자산이다. 이름과 연결되지 않으면 `alt=""`로 처리한다.
- 생성·파생 자산에는 파일명, 사용 위치, 생성/가공 방식, 실존 인물·상표 검토 결과를 기록한다.
- 고대비 모드에서는 큰 사진 배경을 제거해도 모든 정보와 조작이 남아야 한다.

## 10. 잔여 비차단 한계

- Playwright는 Chromium 회귀를 자동화한다. Windows WebView2와 macOS WKWebView의 픽셀 차이는 각 CI 패키지의 실제 실행 QA에서 별도로 확인해야 한다.
- 로컬 기준 검증은 완료했지만 현재 브랜치를 원격에 push하지 않았으므로 GitHub-hosted Ubuntu/Windows/macOS의 해당 커밋 실행 결과는 아직 없다. 원격 게시 권한이 주어지면 CI 실행 결과를 출시 판정에 추가한다.
- 새 프로 히어로는 생성 원본·프롬프트·런타임 자산 검사를 통과했지만 프로 커리어까지 진행하는 픽셀 기준선은 아직 없다. 자동 검사는 고교 설정·오프라인·Lab 결과·GameCast의 핵심 화면을 우선 보호한다.
- GameCast는 React 상태 커밋을 30fps로 제한했지만 저사양 WebView의 프레임 시간 수치는 아직 수집하지 않는다. 성능 회귀가 관찰되면 궤적 진행률을 DOM/CSS 레이어로 분리한다.
- 역할 장면과 아이콘은 생성 시 실존 인물·팀을 입력하지 않았고 가시 로고·문자를 검토했다. 법률상 상표 검색과 외부 플레이테스트는 출시 운영 절차로 남는다.
