# 디자인 시스템 최종 판단 및 개선 기준

| 항목 | 값 |
|---|---|
| 문서 ID | DOC-18 |
| 버전 | 1.3 Visual Direction Revision |
| 기준일 | 2026-07-23 |
| 대상 | Windows React/Tauri · iOS SwiftUI |
| 결정 | 기존 다크그린 정체성은 유지하고 의미 기반 디자인 시스템으로 재구성 |

## 1. 목적

이 문서는 현재 구현을 기준으로 야구 못하면 또 환생함의 시각 체계를 최종 평가하고, 이후 UI 구현과 검수에 사용할 단일 기준을 정의한다. DOC-06의 경험 원칙은 유지하되, 실제 제품에서 확립된 다크그린·라임·골드 방향을 정식 기준으로 승격한다.

## 2. 최종 판단

초기 감사에서 확인한 의미색 중복, 하드코딩, 작은 본문, 플랫폼별 역할 불일치는 제거됐다. 다만 1.2의 “전면 적용 통과” 판정은 토큰과 컴포넌트 준수를 제품의 미술 완성도와 동일하게 취급한 오류였다. 기능적으로 일관돼도 동일한 암록 카드가 반복되고 장면·인물·공간의 맥락이 없으면 게임이 아니라 관리 도구처럼 보인다.

> **최종 판정: 시스템 일관성과 접근성은 통과, 미술 방향은 1.3에서 재정의했다. 고교 커리어의 핵심 진입·현재 학교·인물 장면에는 구장 키아트와 역할 이미지가 적용됐으며, 이후 신규 화면도 “정보 위에 장면을 얹는” 동일 기준을 통과해야 한다.**

| 평가 축 | 판정 | 근거 |
|---|---|---|
| 의미색·팔레트 | 통과 | action, selection, positive, warning, negative, information, milestone 역할 분리 |
| 컴포넌트 적용 | 통과 | 선수 카드, 결과 카드, 버튼, 배지, 스코어보드, 기록지 계약 연결 |
| 본문 가독성 | 통과 | 두 줄 이상 설명은 중앙 규칙으로 14px 이상 강제 |
| 선택·결과 이해 | 통과 | 비색상 선택 표식, 전후 수치, 상태 문구, 다음 행동을 함께 제공 |
| 고대비·모션 감소 | 통과 | 의미 토큰 대응값과 축약 경로 유지 |
| 반응형 | 통과 | 데스크톱 다열과 모바일 단일 열·2열 상태 요약 규칙 적용 |
| 고유한 게임성 | 조건부 통과 | 선수 카드·기록지·스코어보드에 구장·더그아웃·인물 키아트를 결합. 신규 핵심 장면은 자산 없이 출시하지 않음 |

이 판정은 자산을 많이 넣으면 자동으로 좋아진다는 뜻이 아니다. 이미지는 진입, 현재 소속, 중요한 인물, 경기·드래프트 같은 장면 전환에만 사용하고 반복 목록과 수치 판독 영역은 차분하게 유지한다. 서로 다른 이름의 인물에 같은 얼굴을 반복 사용하는 식의 임시 적용은 금지한다.

## 3. 유지할 자산

- 야간 구장과 분석실을 연상시키는 암록색 바탕.
- Pitcher Lab과 브랜드의 산뜻한 라임.
- 드래프트, 데뷔, 수상 등 커리어 절정의 골드.
- 한 화면에 강한 기본 행동 하나를 두는 구조.
- 요약 → 상세 → 근거로 이어지는 결과 공개.
- 44px 입력 영역, 포커스 링, 고대비, 모션 감소, 명시적 상태 레이블.

## 4. 디자인 원칙

### DS-01. Baseball first

화면은 일반 대시보드가 아니라 스코어보드, 기록지, 선수 카드, 드래프트 보드의 정보 구조를 사용한다. 장식보다 이닝, 카운트, 주자, 선수 상태, 다음 행동을 우선한다.

### DS-02. One saturated accent

한 화면의 기본 상태에서는 채도가 높은 강조색을 하나만 주도적으로 사용한다. 보조 상태색은 작은 배지, 아이콘, 수치에 제한한다.

### DS-03. Brand is not status

브랜드 라임은 로고, 핵심 CTA, 제한된 초점 표시에 사용한다. 온라인, 성공, 설정 활성 상태에는 별도의 의미색을 사용한다.

### DS-04. Gold is narrative reward

골드는 드래프트, 프로 데뷔, 수상, 은퇴, 기억 계승과 같은 서사적 보상에만 사용한다. 피로와 위험은 warning 색으로 분리한다.

### DS-05. Selection is not color-only

선택 상태는 색 변화와 함께 체크, 굵기, 테두리 형태, `선택됨` 레이블 중 하나 이상을 추가한다. 보조 기술에는 `aria-pressed` 또는 동등한 접근성 상태를 제공한다.

### DS-06. Calm by default, stage the moment

평상시는 차분한 데이터 화면으로 유지한다. 중요 순간에는 주변 정보의 대비와 밀도를 낮추고 결과·선택 영역을 무대 중앙으로 올린다.

## 5. 색상 체계

### 5.1 Primitive palette

| Token | 값 | 용도 |
|---|---|---|
| `color-canvas` | `#080D0B` | 전체 배경 |
| `color-surface` | `#101815` | 기본 카드 |
| `color-surface-raised` | `#17231E` | 선택·행동 영역 |
| `color-surface-soft` | `#1E2B25` | 배지·보조 셀 |
| `color-border` | `#3F554B` | 비필수 구분선 |
| `color-border-strong` | `#5F736A` | 입력·선택·중요 경계 |
| `color-text-primary` | `#F1F4EE` | 제목·본문·핵심 수치 |
| `color-text-secondary` | `#B4C1BB` | 설명·보조 정보 |
| `color-text-tertiary` | `#84968E` | 메타데이터 |
| `color-brand` | `#B7F36B` | 로고·브랜드 표식 |
| `color-action` | `#B7F36B` | 화면의 단일 기본 CTA |
| `color-selection` | `#86C96A` | 선택 테두리·체크 |
| `color-milestone` | `#D8B565` | 드래프트·데뷔·수상 |
| `color-positive` | `#55C58A` | 성장·회복·성공 |
| `color-warning` | `#F0A94A` | 피로·불확실·위험 |
| `color-negative` | `#EF746A` | 부상·실패·오류 |
| `color-information` | `#67B6C1` | 연결·분석·중립 상태 |

### 5.2 역할 규칙

- 기본 CTA 이외의 버튼은 action 색으로 채우지 않는다.
- 선택은 `color-selection`, 성공은 `color-positive`로 분리한다.
- 코어 연결과 분석 상태는 `color-information`을 사용한다.
- 중요 커리어 장면은 `color-milestone`을 사용하되 일반 경고에는 사용하지 않는다.
- 팀 색상은 전용 `team-*` 토큰을 사용해 장식과 엠블럼에만 적용하며 상태색과 장면색을 재사용하지 않는다.
- 고대비 모드는 화면별 색을 덮는 방식이 아니라 동일한 의미 토큰의 고대비 값으로 제공한다.

## 6. 타이포그래피와 수치

| 역할 | 기준 |
|---|---|
| 핵심 제목 | 24–32px · Bold |
| 섹션 제목 | 18–22px · Bold |
| 본문 | 14–16px · Regular |
| 보조 본문 | 13–14px · Regular/Medium |
| 메타 레이블 | 12px · Bold, 짧은 텍스트만 허용 |
| 중요 수치 | 24–40px · Bold · tabular figures |
| 일반 수치 | tabular figures 적용 |

12px 텍스트는 짧은 레이블, 단위, 날짜, 상태에만 사용한다. 두 줄 이상 설명과 뉴스 본문에는 사용하지 않는다.

## 7. 컴포넌트 기준

### 7.1 공간과 모서리

- spacing: `4 / 8 / 12 / 16 / 24 / 32px`.
- radius: `6 / 10 / 14px`.
- 새로운 임의 간격과 1px 단위 radius를 추가하지 않는다.

### 7.2 카드

| Variant | 용도 | 표현 |
|---|---|---|
| Default | 정보·기록 | surface + 기본 경계 |
| Raised | 현재 선택·다음 행동 | raised surface + strong 경계 |
| Result | 직전 결과 | 상태색은 아이콘·제목·좁은 가장자리에 제한 |
| Milestone | 드래프트·데뷔·수상 | milestone accent + 주변 정보 대비 축소 |

### 7.3 버튼

- Primary: 화면당 하나. action 배경과 어두운 텍스트.
- Secondary: surface 배경과 strong 경계.
- Quiet: 투명 배경. 반복 빈도가 낮은 보조 행동.
- Danger: 삭제·초기화처럼 되돌리기 어려운 행동에만 negative 사용.
- 비활성 버튼은 상태색을 사용하지 않고 텍스트와 배경 대비를 낮춘다.

### 7.4 설정

접근성·효과음·햅틱·진단은 상단에서 하나의 `접근성·설정` 메뉴로 묶는다. 현재 모드, 코어 상태, 화면 전환보다 강하게 보이지 않아야 한다.

## 8. 플랫폼 적용

- Windows와 iOS는 렌더링 컴포넌트는 달라도 `action`, `selection`, `milestone`, `positive`, `warning`, `negative`, `information`의 의미를 공유한다.
- iOS의 밝은 환경에서는 WCAG 대비를 만족하는 어두운 대응색을 사용하고 다크 모드에서는 원래 팔레트의 밝은 대응색을 사용한다.
- 플랫폼 기본 컴포넌트는 유지하되 중요한 순간과 선택 상태의 색 의미를 동일하게 맞춘다.

## 9. 구현 우선순위

### P0 — 현재 릴리스에 반영

- 의미 기반 색상 토큰과 기존 토큰 호환 레이어 추가.
- 상단 설정을 접이식 메뉴로 통합.
- 온라인 상태, 설정 활성, 선택, 성공, 골드 마일스톤의 역할 분리.
- 선택 카드에 비색상 체크 표시 추가.
- 전체 숫자에 tabular figures 적용.
- 고대비 모드를 의미 토큰 기반으로 변경.
- iOS tint와 결과·중요 순간 색상을 공통 의미에 맞춤.
- DOC-06의 팔레트 기준을 본 결정과 동기화.

### P1 — 구현 완료

- 하드코딩 색상을 의미 토큰으로 전환.
- 카드·버튼·배지 variant 컴포넌트화.
- 12px 장문 텍스트를 13–14px로 상향.
- 드래프트·데뷔·은퇴 장면에서 주변 패널의 밀도와 대비를 낮추는 stage layout 적용.
- Pitcher Lab과 Career 사이에 공통 선수 카드·기록지 문법 도입.

### P2 — 구현 완료

- 스코어보드 숫자 체계와 기록지 표 패턴.
- 팀 엠블럼과 유니폼 색상의 장식 전용 규칙.
- 야구혼·기억 카드의 절제된 종이/기록 질감.
- 실제 플레이테스트를 통한 중요 행동 탐색 시간과 가독성 검증.

## 10. P0 완료 조건

- 상단에는 설정 버튼 하나만 보인다.
- 코어 온라인 표시와 활성 설정이 라임 CTA처럼 보이지 않는다.
- 선수·훈련 선택을 흑백 화면에서도 체크 표시로 식별할 수 있다.
- 기본 CTA, 성공, 경고, 오류, 정보, 마일스톤이 서로 다른 의미 토큰을 사용한다.
- 고대비와 모션 감소가 기존 기능을 유지한다.
- Windows TypeScript 빌드와 테스트가 통과한다.
- iOS Simulator 대상 빌드가 통과한다.
- 변경 후 1280px급 데스크톱 화면에서 게임의 다음 행동이 상단 설정 메뉴보다 먼저 인식된다.

## 11. 변경 관리

본 문서는 DOC-06의 색상 체계 1.0 Baseline을 대체한다. 경험 원칙, 정보 순서, 접근성 원칙은 계속 DOC-06을 따른다. 이후 색상이나 컴포넌트 역할을 추가할 때에는 본 문서의 역할 규칙과 완료 조건을 먼저 갱신한다.

## 12. 전면 적용 완료 기록

2026-07-22 기준으로 P0·P1·P2의 구현 항목을 Windows와 iOS에 전면 적용했다.

### 12.1 Windows

- `design-system.css`를 색상·타입·간격·radius·그림자·구장 장면 토큰의 단일 원본으로 사용한다.
- `styles.css`, `release.css`, TS/TSX에는 원시 HEX/RGB 색상을 두지 않는다. 구장·GameCast 색도 `scene-*` 토큰으로 분리했다.
- 레거시 `lime`, `amber`, `red`, `blue`, `surface`, `line`, `muted` 참조를 제거했다.
- 고정 글자 크기를 역할 토큰으로 바꾸고, 읽어야 하는 설명문은 최소 14px, 짧은 메타와 구장 레이블은 최소 12px로 제한했다.
- 주요 화면이 `ds-card`, `ds-button`, `ds-badge`, `ds-player-card`, `ds-scoreboard`, `ds-record-grid` 계약을 사용한다.
- 드래프트·신인 계약·프로 데뷔·1군 데뷔·은퇴·커리어 완료에는 `data-stage` 기반 stage layout을 사용한다.
- 프로 구단 색상은 상태색과 분리된 `team-*` 토큰, `data-team`, `team-decoration`을 통해 선수 카드 상단 장식에만 적용한다.
- 고교·프로·Pitcher Lab의 선수 카드와 기록 영역이 동일한 테두리, 숫자, 기록지 패턴을 공유한다.

### 12.2 iOS

- `BaseballTheme`가 canvas, surface, border, text와 action, selection, milestone, positive, warning, negative, information을 모두 제공한다.
- 라이트·다크·고대비 환경별 대응값을 같은 의미 토큰에서 선택한다.
- `BaseballCard`와 `ScoreboardValue`로 다음 행동, 중요 순간, 최근 기록, 핵심 수치의 시각 문법을 공유한다.
- 구단 장식색은 상태 의미와 분리된 적응형 색으로 제공하고 오늘 화면의 구단 표식에만 제한한다.
- 선택은 체크 아이콘, 선택색, 테두리, 접근성 선택 trait를 함께 사용한다.
- 기록 화면의 숫자에는 monospaced digits를 적용한다.

### 12.3 자동 회귀 방지

`npm run check:design-system`은 다음을 빌드 전에 검사한다.

1. 중앙 토큰 파일 밖의 원시 색상 값이 0개인지 확인한다.
2. 레거시 색상 토큰 참조가 0개인지 확인한다.
3. CSS의 고정 본문 크기가 역할 토큰을 우회하지 않는지 확인한다.
4. 공통 카드·버튼·장면·스코어보드 계약이 주요 화면에 연결되어 있는지 확인한다.
5. 일반 UI에서 구장 전용 `scene-*` 토큰을 사용하지 않는지 확인한다.
6. 기본·고대비의 의미색, 장면색, 구단색 토큰이 일대일로 대응하는지 확인한다.
7. 본문과 상태 텍스트 조합이 WCAG AA 4.5:1 대비를 충족하는지 확인한다.
8. GameCast·Trajectory의 플레이 장면에서 서사 전용 `milestone` 토큰을 사용하지 않는지 확인한다.

### 12.4 화면 검증

- 1280×900: 경기 상황 → 선수 정보 → 투구 선택 → 결과의 우선순위와 단일 CTA를 확인했다.
- GameCast: 구장 장면 토큰, 스코어보드 수치, 결과 정보의 가독성을 확인했다.
- 고대비: 루트와 본문에 동일한 의미 토큰이 적용되고 선택 상태가 색상과 체크로 함께 구분되는지 확인했다.
- 390×844: 세 주요 패널이 단일 열로 전환되고 가로 스크롤이 발생하지 않는 것을 확인했다.
- 모션 감소: 기존 재생·드래프트 공개 단축 경로를 유지한다.

이후 새 UI가 이 기준을 우회하면 자동 검사가 실패해야 하며, 새 의미 역할이 필요할 때에만 본 문서와 중앙 토큰을 함께 갱신한다.

## 13. 2026-07-23 기능 화면 적용 감사

고교 커리어의 실제 플레이 흐름을 다시 감사해 토큰 적용 여부뿐 아니라 선택 결과가 플레이어에게 이해되는지까지 확인했다.

- 훈련 선택 전에 성장 가능성, 학교 강점 적용, 상·하한을 반영한 예상 피로를 제공한다.
- 훈련 뒤에는 능력치와 피로의 실제 전후 값을 공통 Result 카드와 기록지 숫자로 보여 준다.
- 감독, 포수, 라이벌의 관계 수치를 분리하고 각 대화가 해당 인물의 수치만 바꾸도록 규칙과 테스트를 추가했다.
- 대화 뒤에는 선택 요약, 관계·팬 관심·피로·능력치 변화를 확인한 다음 다음 일정으로 이동한다.
- 성장·회복은 positive, 피로 누적은 warning, 관계 하락은 negative, 변화 없음은 neutral로 표시한다.
- 결과 확인 상태는 손상되거나 미래 회차를 가리키는 로컬 저장 값을 거부하며 키보드 포커스와 라이브 알림을 제공한다.
- Result 카드, `ds-record-grid`, 장문 본문 크기, 5개 핵심 상태의 반응형 배치는 자동 디자인 시스템 계약으로 고정했다.

자동 검증 기준은 Swift 고교 커리어 테스트, Windows 단위 테스트, TypeScript 빌드, 디자인 시스템 검사다. 실제 화면은 데스크톱·모바일·고대비·모션 감소 상태를 마지막 출고 검증에서 다시 확인한다.

## 14. 2026-07-23 아트 디렉션 재감사

DOC-19의 비교 리서치와 `Midnight Dugout` 방향을 적용했다.

- 전역 캔버스, 고교 커리어 진입, 현재 커리어, 연결 대기 화면에 야간 구장·더그아웃 키아트를 연결했다.
- 선택된 학교의 감독·포수와 현재 라이벌에 역할 초상을 연결했다.
- 같은 초상이 서로 다른 이름으로 한 화면에 반복되지 않도록 학교 선택 목록에는 공통 초상을 적용하지 않았다.
- 본문 판독을 위해 이미지는 의미 토큰 기반 어두운 오버레이 아래에 두고, 고대비 모드에서는 큰 배경을 제거한다.
- 이미지가 없는 수치·선택·결과 컴포넌트는 기존 디자인 계약을 그대로 유지한다.

이 개정으로 “디자인 시스템을 잘 적용했는가”와 “완성도 높은 야구 게임처럼 보이는가”를 별도 축으로 검수한다. 이후 두 축 가운데 하나라도 실패하면 전면 적용으로 판정하지 않는다.
