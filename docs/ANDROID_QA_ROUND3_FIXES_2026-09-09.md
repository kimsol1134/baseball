# Android 3차 QA 개선 결과 · 2026-09-09

계획: `ANDROID_QA_ROUND3_IMPROVEMENT_PLAN_2026-09-09.md`. 기준 HEAD `5b8294e2` 위의 기존 2차 미커밋 수정은 보존하고 후반부 개선을 추가했다. 업로드·출시는 하지 않았다.

## 가장 중요한 원인과 수정

3차 QA의 실제 저장 파일은 프로 중요 경기가 활성 상태인데 최상위 `stage`가 `highSchool`이었다. 고교용 복귀 계획 명령이 연결된 프로 커리어의 stage를 덮어쓰는 경로가 있었다. 이 때문에 잘못된 복귀 안내뿐 아니라 stage에 의존하는 중단 경기 요약도 사라질 수 있었다.

- 복귀 카드·알림은 현재 커리어 기준의 `ReturnVisitPresentation`을 사용한다. 알림 요청은 더 이상 고교 진행 명령을 실행하지 않는다.
- 기존 고교 복귀 계획 명령을 실행하더라도 프로/은퇴/유산 단계는 보존한다. native writer와 테스트용 reducer에 모두 반영했다.
- 이미 저장된 오류는 **고교 완료 + 활성 프로 + 연결 원본 고교 ID 일치 + 도전 아님**이라는 좁은 조건에서 읽기 시 복구한다. 실제 QA 파일로 로드·명령 실행·재저장·재개방을 검증했다. 신규 고교 커리어로 무조건 돌려놓거나 모든 stage를 프로로 바꾸지 않는다.
- 마지막 자동 투구는 등판 결과를 확인하기 전까지 TERMINAL 상태와 활성 투구 데이터를 유지한다. 결과 표시가 끝나기 전에 등판을 정산해 outcome/이닝/피로/궤적이 사라지는 경로를 수정했다.

실제 오류 저장 파일은 `game-application/src/test/resources/regression/round3-linked-pro-return-stage.json`에 회귀 fixture로 보존했다.

## 빌드·증거·남은 조건

계측 검사는 `com.solkim.baseball.android.reset.compose.qa`, nativeAuthoritative에서 수행했다. 기존 QA 패키지와 별도로 테스트했다. 전용 테스트 패키지를 초기화하기 전 저장 파일은 `qa-harness-before-reset.json`에 보존했다.

최종 사용자 확인용 빌드는 `baseballLaunchQa=true` + `baseballQaNativeStore=true`의 `com.solkim.baseball.android.compose.qa`다. 에뮬레이터의 기존 QA 패키지에 초기화 없이 업데이트 설치했다. 업데이트 전후 pro·highSchool·installId가 동일함을 확인했고, 이전에 비어 있던 중단 경기 화면이 정상 표시되는 것을 확인했다(`update-preservation.json`, `updated-qa.png`).

이 설치 확인은 원본 데이터를 바꾸지 않는 읽기 호환 보정이다. 원본 파일의 stage 문자열은 아직 highSchool일 수 있으며, 후속 정상 명령/저장에서 PRO 단계가 유지되는 것은 별도 회귀 테스트로 확인했다. APK 해시는 `apk-sha256.txt`에 기록했다. 서명된 production RC가 아니다.
