# 안드로이드 5차 QA 개선 계획

작성일: 2026-09-09. 대상: `com.solkim.baseball.android.compose.qa`, 5차 QA 보고서 및 현재 작업 트리. 이 문서는 구현 계획이며, 수정·기기 재검증 완료 보고서가 아니다.

## 1. 판단과 범위

저장 포기 경로 S-01과 버튼 크기 S-02는 5차에서 같은 상태로 재현해 통과했다. 해당 동작은 회귀 방지 대상으로 유지한다. 이번 작업은 상단 잔상의 재현 검사 보완, 스크롤 안내 단순화, 투구 가독성·배치 개선, 저장 데이터 보존 정책, 고피로 및 배포 환경 검증에 집중한다.

T-05 정정을 반영한다. 사용자 재측정은 동일한 372KB 세이브에서 콜드 스타트 1,494 / 1,515 / 1,535 / 1,642ms였으며, 이 증거로 콜드 스타트 회귀나 세이브 크기 때문에 느려진다고 주장하지 않는다. 이전의 투구 재개 15~19초 관찰은 시작 시간과 다른 동작이다. 원인과 재현성은 별도 측정 전까지 미확정으로 둔다.

현재 증거 디렉터리에서 확인한 파일은 4장이다. 시즌 화면과 조준 화면을 직접 열어 하단 텍스트 잘림, 격자 대비, 그림 아래 공백을 확인했다. 보고서의 런처 대조 캡처는 현재 파일 목록에서 찾지 못했으므로 직접 확인한 증거로 기록하지 않는다. 다음 검증에서 앱·런처 대조를 다시 남긴다.

## 2. 실행 순서와 완료 기준

### 1순위 — S-03 상단 잔상과 잘못된 통과 검사

**확인한 문제:** `Round4SurfaceUiTest.navigationLabelsStayInsideTheirBarAcrossScreenChanges`는 별도 Compose 테스트 화면을 구성하고 `onRoot().captureToImage()`의 y=4~29 픽셀만 검사한다. 실제 MainActivity의 시스템 상태 표시줄과 전체 창 합성 경로를 검증하지 못한다. 접근성 노드 위치가 정상이라는 것만으로 픽셀 잔상이 없다고 판단할 수 없다.

**작업:**

1. 수정 전 실제 설치 APK에서 설정·기록·커리어 탭 전환 및 백그라운드 복귀를 실행한다. 같은 기기의 런처와 앱을 전체 화면 캡처하고 화면 크기·밀도·상태 표시줄 인셋을 기록한다.
2. 기존 실패 화면을 검출하는 검사를 먼저 만든다. 고정 26픽셀 띠 대신 실제 상태 표시줄 영역을 사용하고, 시계·시스템 아이콘 등 변하는 영역만 제외한다. 좌표 검사와 픽셀 검사를 분리한다.
3. 가운데 레이블만 나오는 경로를 추적한다. 진단용 빌드에서 가운데 텍스트 교체·항목 순서 변경·레이블 제거를 각각 비교해 텍스트/슬롯/그리기 캐시 중 무엇을 따라가는지 좁힌다. 현재 원인을 특정 컴포넌트나 에뮬레이터 탓으로 단정하지 않는다.
4. 원인에 해당하는 레이아웃·그리기 경로만 수정하고 진단 코드는 제거한다.

**완료:** 수정 전 실패/수정 후 통과하는 실제 화면 증거, 세 탭과 드래프트·계약 화면의 상단 확인, 반복 전환·앱 복귀에서도 잔상 없음. 기존 캡처 재사용만으로 드래프트 재검증을 완료 처리하지 않는다.

### 2순위 — T-01·T-02 스크롤 안내와 본문 끝 처리

**확인한 문제:** `CareerScrollBody`의 `scroll.canScrollForward`는 본문 뒤 32dp Spacer와 여백까지 포함한다. 조건부 안내가 화면 높이를 차지하면서 스크롤 가능 여부에 다시 영향을 줄 수도 있다. 코드상 안내는 본문의 형제 영역이므로, 실제 오버레이인지 스크롤 경계의 클리핑인지는 좌표를 측정해 구분한다. 캡처에서는 제목이 경계에서 잘린 사실이 확인된다.

**작업:** 공용 텍스트 안내 바를 제거하는 방향을 우선 적용한다. 본문에 실제로 필요한 스크롤만 남기고, 고정 CTA·내비게이션과 스크롤 본문의 공간을 명확히 나눈다. 안내를 유지해야 하는 화면이 있다면 여백이 아닌 마지막 실제 콘텐츠의 경계로 판단하며, 안내 출현 자체가 뷰포트 크기를 바꾸지 않게 한다.

**완료:** 짧은 중단 등판 화면은 불필요한 안내·빈 스크롤이 없고, 긴 시즌 결산과 드래프트 화면은 끝까지 스크롤했을 때 마지막 문장 전체가 CTA 위에 보인다. 중간 스크롤 위치에서 텍스트가 뷰포트 경계에 걸리는 현상과, 끝까지 내려도 읽을 수 없는 가림을 구분해 검사한다. 오류 배너 유무·본문 펼침/접힘·글자 크기 100%/150%·작은 화면에서도 고정 버튼은 48dp 이상을 유지한다.

### 3순위 — T-03·T-04 조준/비행 화면과 슬라이더 사이 공백

**확인한 문제:** 조준 인물 투명도는 포수 0.35, 타자 0.5인데 비행 인물은 `PlateFigures.ASSET_OPACITY=0.13`을 사용한다. 비행 격자는 이미 인물을 그린 다음 그려지므로 순서 변경만으로 해결된다고 가정하지 않는다. 조준 영역은 남은 높이를 모두 차지하는 `weight(1f)` 안에 그림만 180dp로 고정해 공백이 생길 수 있다.

**작업:**

- 조준·비행의 인물 밝기 기준을 공유하고, 격자는 인물·미트 위에서도 읽히도록 셀 바탕과 경계선 대비를 조정한다. 선택/추천 표시는 색 외에도 테두리·표식으로 구분한다.
- 그림과 슬라이더 간 불필요한 확장 공간을 제거한다. 큰 화면에서 그림을 합리적으로 확장하거나 요소를 가까이 배치하고, 작은 화면에서는 선택 영역의 스크롤을 사용한다.
- 포수 아래 플레이트, 타자 전신, 비행 자동 진행·저장 안내 등 4차 해결 사항을 유지한다.

**완료:** 좌·우타 모두 9개 셀 경계와 선택 셀이 식별되고 각 조준 셀의 터치 영역은 48dp 이상이다. 조준·비행 동일 인물의 밝기가 일관된다. Pixel 기준 그림과 슬라이더 사이의 약 360px 빈 띠가 제거된다. 작은 화면·큰 글자에서도 기본 수동 슬라이더가 노출되고 직접 한 구를 끝까지 던질 수 있다. 대표 프레임을 눈으로 확인하며, 단순 도형 좌표 테스트만으로 가독성을 통과 처리하지 않는다.

### 4순위 — T-04 저장 증가에 대한 안전한 보존 정책

**확인한 문제:** 영수증은 `withCommandReceipt`에서 계속 누적하고 문자열 정렬하여 저장한다. 정렬된 배열의 뒤쪽 N개가 최신 N개라는 보장은 없다. 저장소는 revision 검사와 영수증 검사를 함께 사용한다. 앨범은 시즌 페이지 수뿐 아니라 각 페이지의 투구 궤적과 경기 내역이 계속 쌓이므로 페이지 개수만 제한해도 크기는 충분히 제한되지 않는다.

**작업:**

1. 반복 시즌 진행에서 영수증·앨범의 페이지/경기/궤적별 개수와 바이트 증가를 측정한다. 일시적인 명령 내역과 보존해야 하는 선수 기록을 구분한다.
2. 영수증에 시간 순서를 보장하는 revision 기반 보존 범위와 개수 상한을 설계한다. 모든 명령 생성·재시도 경로를 확인하고 오래된 명령이 최신 revision으로 다시 포장되어 중복 적용되지 않도록 한다. 진행 중/예약/재시도 가능한 명령은 보호한다. 단순 `sorted().takeLast(N)`은 사용하지 않는다.
3. 앨범은 시즌 통계·선수 이력·업적을 유지한다. 큰 비중의 투구 재생 상세는 기존 기록 보존과 호환되는 압축/보관 방식을 우선 검토하고, 앞으로 저장할 상세의 개수·바이트 예산을 정한다. 기존 앨범 전체를 오래됐다는 이유로 삭제하지 않는다.
4. 구체적 상한은 증가량과 재시도 안전성 확인 후 구현 문서에 명시한다. 전체 커리어 기록이 늘어나는 것과 무제한 임시 데이터 누적을 혼동하지 않는다.

**완료:** 보존 범위를 넘는 반복 실행에서도 영수증과 신규 재생 상세가 정한 예산을 지킨다. 중복 명령, 오래된 revision, 재시작 후 예약 명령, 백업 복원에서 능력·보상·투구 결과가 두 번 적용되지 않는다. 기존 372KB 세이브가 호환되며 선수 기록과 시즌 합계가 유지된다. 현재 성능 결함을 고쳤다고 표현하지 않는다.

### 5순위 — S-10 고피로 버튼의 실제 도달성

기존 유효 상태 fixture의 피로 80·86·87 테스트와 자연 플레이 검증을 별도 항목으로 관리한다. 피로만 임의 변경한 불가능한 상태로 자연 도달을 증명하지 않는다.

피로 79/80 경계, 경기 종료 여부, PLAYING 여부, 튜토리얼 제외 조건 및 감독 자동 강판 순서를 확인한다. 실제 게임 규칙으로 생성한 상태에서 버튼 노출→실행→결과 저장→계속 진행까지 검증한다. 자연 플레이에서는 언제 자동 강판이 먼저 일어나는지 기록한다. 정상 플레이에서 항상 강판이 먼저라면 현재 버튼 조건이 사각 경로인지 판단하고 규칙·표현을 정리한다.

**완료:** 단위 조건 통과, 화면/행동 통과, 자연 플레이 도달성의 세 상태가 각각 명확히 기록된다. 자동 강판과 수동 종료가 중복으로 적용되지 않는다.

## 3. 성능 정정과 별도 측정

콜드 스타트는 5차 보고서 기준 회귀 없음으로 정정한다. 이번 계획에서 대규모 저장 구조 개편을 성능 개선이라는 이유로 진행하지 않는다.

이전 15~19초 투구 재개는 유휴 호스트에서 같은 APK·세이브로 별도 재측정한다. 앱 시작, 이어 하기 탭, 명령 처리, 저장, 첫 조작 가능 화면의 시점을 분리하고 호스트 부하·에뮬레이터 CPU·시도별 원시 시간을 함께 남긴다. 최소 5회 측정하여 중앙값·최댓값을 기록하고 실기기 결과와 구분한다. 재현될 때만 느린 구간을 추적하고 최적화한다. 재현되지 않으면 기존 관찰을 환경 영향 가능성이 있는 미확정 기록으로 수정한다.

## 4. 실기기와 배포 전 검증

화면 수정 후 마지막에 장비를 찾는 방식 대신, 착수 때 연결 장비와 서명 설정부터 확인한다. 장비/서명이 없어도 코드 수정과 가능한 검증은 계속한다.

| 대상 | 확인 내용 | 완료 증거 |
| --- | --- | --- |
| 연결 Android 실기기 | 실제 세이브 유지 업데이트, 상단 잔상, 조준·비행, 중단/재개/포기, 알림·외부 음악 | 모델·OS·APK 해시·전체 화면 캡처·로그 |
| TalkBack | 탐색 순서, 선택지 효과 읽기, 슬라이더 조작 또는 명시적 접근성 보조 경로, 고정 CTA 접근 | 주요 여정 실행 기록; 설정만 켠 것은 통과 아님 |
| OS 자동 복원 | 2대 사이 Android 백업·복원으로 진행/설정 보존, 중복 알림·중복 처리 없음 | 원본/복원 기기의 핵심 저장 값 비교; 수동 파일 복사와 구분 |
| 태블릿·폴더블 | 큰 화면·접힘/펼침·화면 크기 변경 중 레이아웃과 진행 보존 | 실제 기기 검증 여부 명시; 에뮬레이션은 별도 표기 |
| 서명 RC | 실제 배포 후보 release 설치·업데이트·핵심 여정, 최적화 설정에서의 동작 | 서명 인증서 식별값·빌드 변형·APK 해시·결과 |

QA debug 통과는 서명 RC 통과로 대체하지 않는다. 서명 키·추가 장비가 없으면 해당 항목만 미검증으로 남긴다. 개인 기기를 초기화하는 방식은 별도 동의 없이 진행하지 않는다. 이 계획은 스토어 업로드·출시를 포함하지 않는다.

## 5. 다음 완료 보고서의 기준

- 각 항목에 코드 수정 / 자동 테스트 / 실제 화면 / 실기기 / 미검증을 구분한다. 원인 미확정 항목을 해결로 집계하지 않는다.
- 기존 S-01 상태를 그대로 사용하는 중단→포기→계속 진행, 시즌 경계, 기본 슬라이더 직접 투구를 회귀 확인한다.
- 바뀐 화면은 한국어·영어·일본어 및 큰 글자로 확인한다. 문구 추가 시 문구 게이트와 가상 야구 콘텐츠 규칙을 검사한다.
- 검증 APK 해시, Git HEAD 및 작업 트리 차이를 기록한다. 고교 완주를 생략하면 드래프트는 fixture 검증임을 명시한다.
- 증거는 안정된 QA 디렉터리에 즉시 저장한다. 사용자 제공 증거와 최종 전달 자료는 정리 대상에서 제외한다.

산출물: 원인·수정·검증 한계를 담은 5차 개선 결과 문서, 필요한 회귀 테스트, 실제 수정 전후 캡처, 실기기/RC 검증표. 현 계획 작성에서는 앱 코드·세이브·설치 상태를 변경하지 않았다.
