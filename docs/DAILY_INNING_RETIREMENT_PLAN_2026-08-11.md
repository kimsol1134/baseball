# 오늘의 이닝 임시 제거 및 재도입 계획

- 상태: iOS 제거 구현·자동 검증 완료, 출시 전 수동 스모크 대기
- 결정일: 2026-08-11
- 대상: iOS 우선, Android·일본어판 계획 동기화
- 결정: 현재 형태의 `오늘의 이닝`을 제품에서 제거하고, 별도 재설계를 통과한 뒤 새 버전으로 다시 도입한다.

## 0. 구현 결과 (2026-08-11)

iOS 앱에서 사용자 진입 UI, 플레이 화면, 시나리오 생성, 보상 지급, 리더보드 제출, 주간 목표
생성, 신규 알림 목적지를 제거했다. 과거 딥링크와 저장된 알림 계획은 안전한 커리어 탭으로
보내며, 이미 발급된 주간 목표는 가능한 목표로 교체하거나 대체 후보가 없을 때 면제 완료한다.

저장 호환을 위해 과거 알림 목적지 enum, 주간 목표 enum, 분석 이벤트 이름, 로컬 저장 키는
레거시 경계에 남겼다. 기존 사용 기록은 업데이트만으로 삭제하지 않으며, 사용자가 설정에서
전체 진행 삭제를 명시했을 때만 옛 로컬 키도 함께 지운다.

자동 검증 결과:

- iOS 시뮬레이터 앱 빌드 성공
- 관련 회귀 테스트 67개 통과
- 전체 `BaseballIOSTests` 314개 통과, 실패 0개
- 사용자 노출 문구와 `DailyInningView` 실행 참조 검색 결과 0개

Android Unity 포팅 제외와 일본어판 계획 동기화는 각 플랫폼 구현 문서가 별도 작업 중이므로
이번 iOS 코드 변경 범위에는 포함하지 않았다.

## 1. 결정 배경

현재 모드는 본편 투구를 짧게 반복하는 수준에 머물러 있고, 매일 달라지는 규칙이나 독자적인
의사결정이 부족하다. 점수 역시 세이브 성공보다 탈삼진 수를 더 강하게 보상해 모드의 목표와
플레이 최적해가 충돌한다. 최근 사용 데이터도 낮은 이용 방향을 보이지만, 진입·시작·중도
이탈·완료를 연결할 계측이 없어 현 상태에 보상이나 노출만 더하는 것은 근거가 약하다.

따라서 이번 작업의 목표는 기능을 더 고치는 것이 아니라 다음 세 가지다.

1. 사용자가 더 이상 현재 모드와 관련된 입구·목표·알림을 만나지 않게 한다.
2. 기존 저장, 완료 기록, 알림, 주간 목표가 고아 상태나 오류를 만들지 않게 한다.
3. 현재 구현에 끌려가지 않고 새 일일 퍼즐을 설계할 수 있도록 재도입 조건을 남긴다.

## 2. 제거 완료의 제품 계약

다음 조건을 모두 만족해야 제거 완료로 본다.

- 고교·프로·기록·주간 노트·설정 어디에도 오늘의 이닝 입구나 안내 문구가 없다.
- 알림과 앱 내 복귀 카드가 오늘의 이닝을 새 목적지로 선택하지 않는다.
- 과거 알림이나 외부 링크의 `daily-inning` 주소를 눌러도 빈 화면이나 닫힌 화면이 뜨지 않는다.
- 새 주간 노트에 `오늘의 이닝 1회 완료`가 발급되지 않는다.
- 이미 그 목표를 받은 사용자는 보상을 얻을 수 없는 상태로 남지 않는다.
- 새 점수, Game Center 제출, 계승 포인트 지급, 일일 완료 영수증이 발생하지 않는다.
- 기존 최고점·플레이 날짜·보상 영수증·Game Center 기록은 삭제하거나 초기화하지 않는다.
- iOS 빌드, 저장 호환 테스트, 알림·딥링크 테스트와 핵심 UI 스모크가 통과한다.

## 3. 제거 원칙

### 3.1 사용자 기능은 제거하고, 호환 데이터는 보존한다

화면을 숨기는 플래그만 추가하지 않는다. 제품 경로에서는 진입, 플레이, 보상, 순위 제출을
실제로 끊는다. 반면 옛 버전이 쓴 enum 값과 저장 키는 최소 2개 정식 버전 동안 읽을 수 있게
보존한다. 제거와 데이터 파괴를 같은 배포에서 하지 않는다.

보존 대상:

- 개인 최고점, 날짜별 시도 횟수, 플레이 날짜 키
- 계승 포인트 중복 방지 영수증
- 이미 완료된 업적과 Game Center 점수
- 옛 `DailyReminder.Plan`의 `.dailyInning` 디코딩 호환
- 옛 `WeeklyTaskKind.dailyInningCompleted` 디코딩 호환

### 3.2 과거 링크는 거부하지 말고 안전한 화면으로 보낸다

이미 전달된 알림과 App Store 이벤트 링크는 배포 후에도 눌릴 수 있다. `.dailyInning` 값과
`com.solkim.baseball.ios://daily-inning` 파싱은 당분간 남기되 실행 화면은 열지 않는다.

리다이렉트 우선순위:

1. 진행 중인 프로 커리어가 있으면 프로 탭
2. 진행 가능한 고교 커리어가 있으면 고교 탭
3. 둘 다 없으면 현재 기본 홈

리다이렉트 과정에서 새 보상이나 완료 기록을 만들지 않는다.

### 3.3 이미 발급된 주간 목표를 불가능하게 만들지 않는다

새 보드 생성 후보에서는 `dailyInningCompleted`를 즉시 제외한다. 저장된 이번 주 보드는 다음
규칙으로 한 번만 마이그레이션한다.

- 이미 완료된 목표: 완료 상태와 보상 판정을 그대로 보존한다.
- 미완료 목표: 같은 보드에 없는 수행 가능한 후보로 결정론적으로 교체한다.
- 교체 후보가 없으면 해당 목표를 `retired` 사유로 면제 완료한다.
- 다른 목표의 진행도, 완료 ID, 보상 수령 여부, 주차 키는 변경하지 않는다.
- 같은 기기에서 마이그레이션을 반복해도 결과가 달라지지 않아야 한다.

무료 완료보다 불가능한 목표를 남기는 피해가 더 크므로, 마지막 예외에서만 면제 완료를
허용한다. 이 동작은 단위 테스트로 고정한다.

## 4. 구현 단계

### 단계 A — 진입과 화면 제거

1. `AppShell`의 오늘의 이닝 표시 상태, 전면 화면, 진입 콜백을 제거한다.
2. 고교 홈의 `DailyInningEntryRow`와 기록 화면의 진입 카드를 제거한다.
3. `WeeklyProgramView`의 `오늘의 이닝 던지기` 버튼과 접근성 문구를 제거한다.
4. 설정 화면에서 오늘의 이닝 최고점 초기화 항목이 독립 노출된다면 제거한다.
5. `DailyInningView`를 참조하는 경로가 0개인지 검색하고 컴파일로 확인한다.

### 단계 B — 알림·복귀·딥링크 정리

1. `BaseballApp.resolvedReturnContext()`의 일일 이닝 fallback을 없앤다. 이어 갈 실제 커리어가
   없으면 복귀 계획과 알림을 만들지 않는다.
2. `DailyReminder`가 새 `.dailyInning` 계획을 생성하지 못하게 한다.
3. 기존 `baseball.daily.reminder.*` 중 오늘의 이닝 목적지로 예약된 알림을 앱 활성화 시
   취소한다. 다른 고교·프로 복귀 알림은 보존한다.
4. 옛 계획과 딥링크는 3.2의 우선순위로 리다이렉트한다.
5. 알림 문구, 기본 알림 등록, 앱 내 복귀 카드에 남은 관련 문구를 제거한다.

### 단계 C — 주간 프로그램과 보상 정리

1. `WeeklyProgramEligibility.dailyInningUnlocked`와 생성 후보 의존성을 제거한다.
2. 3.3의 저장 보드 마이그레이션을 추가한다.
3. `WeeklyProgramView`와 테스트 픽스처에서 일일 이닝 전용 분기를 제거한다.
4. `creditDailyInning`, `weekly.record(.dailyInningCompleted)`, 일일 리더보드 제출 호출이 더
   이상 실행 경로에 없음을 확인한다.
5. 이미 받은 계승 포인트, 주간 스탬프, 업적을 회수하지 않는다.

### 단계 D — 실행 코드 정리

단계 A~C를 한 빌드에서 검증한 뒤 아래 코드를 제거한다.

- `DailyInningView.swift`와 Xcode 프로젝트의 파일·빌드 참조
- `PitchScenario.daily(...)` 및 일일 시나리오 전용 헬퍼
- 일일 화면에만 쓰이는 점수 계산, 시도 제한, 정산 UI
- 실행 경로가 사라진 전용 테스트

다만 저장 키와 옛 enum 값을 읽는 데 필요한 최소 코드는 `LegacyDailyInningData`처럼 목적이
분명한 호환 계층으로 옮긴다. `DailyStreak`는 현재 모든 경기의 연속 플레이를 기록하므로
일일 이닝 전용 키와 범용 스트릭 로직을 분리해서 판단한다. 범용 스트릭은 제거 대상이 아니다.

### 단계 E — 다른 플랫폼과 문서 동기화

아직 구현 중인 Android Unity에는 오늘의 이닝을 포팅하지 않는다. 다음 문서에서 항목을
`DEFERRED — redesign required`로 바꾸고 구현·QA·분석 범위에서 제외한다.

- `docs/ANDROID_UNITY_IMPLEMENTATION_PLAN_2026-08-11.md`
- `docs/android-unity/PARITY_MATRIX.md`
- `docs/android-unity/IMPLEMENTATION_STATUS_2026-08-11.md`
- `docs/android-unity/ANALYTICS_EVENT_MATRIX.md`
- `docs/JAPANESE_IOS_IMPLEMENTATION_PLAN_2026-08-11.md`
- `docs/IMPROVEMENT_TRACKER.md`

과거 리뷰와 분석 보고서는 당시 판단의 기록이므로 내용을 지우지 않는다. 문서가 현재 계획을
가리켜야 하는 경우에만 이 문서 링크와 `retired` 상태를 덧붙인다.

## 6. 검증 계획

### 자동 검증

- iOS 앱 빌드와 관련 Swift 테스트 통과
- 옛 `.dailyInning` 복귀 계획 디코딩 성공 및 안전한 탭 리다이렉트
- 옛 `dailyInningCompleted` 주간 보드의 완료·교체·면제 세 경우 테스트
- 마이그레이션 2회 실행 결과가 동일한 멱등성 테스트
- 기존 최고점과 보상 영수증이 제거 전후 동일한 저장 호환 테스트
- 신규 주간 목표를 여러 시드로 생성해 일일 이닝 목표가 0건인지 확인
- `rg`로 실행 UI 문구와 호출 경로가 0건인지 확인
- 프로젝트 콘텐츠 불변 규칙에 따라 새 UI 문구에 실존 구단명·약칭이 없는지 확인

### 수동 스모크

1. 신규 설치: 첫 실행부터 기록·설정까지 관련 입구가 보이지 않는다.
2. 진행 중 고교: 기존 일일 알림 링크가 고교로 안전하게 이동한다.
3. 진행 중 프로: 같은 링크가 프로로 안전하게 이동한다.
4. 커리어 없음: 링크가 기본 홈을 열고 모달·빈 화면을 남기지 않는다.
5. 기존 주간 보드: 불가능한 목표가 없고 수령 가능 상태가 퇴행하지 않는다.
6. 알림 허용 사용자: 예약 목록에 오늘의 이닝 목적지 알림이 남지 않는다.
7. 모든 진행 삭제: 옛 일일 기록 때문에 화면이나 보상이 다시 나타나지 않는다.

### 출시 후 관찰

기능 이용률은 제거 성공 지표가 아니다. 배포 후 7일 동안 다음 회귀만 본다.

- 크래시·비정상 종료
- 알림 열기 후 유효 화면 도착률
- 주간 보상 도달률과 수령 실패
- 고교·프로 이어하기 진입률
- D1 의미 세션과 전체 게임 완료율

오늘의 이닝 관련 과거 이벤트는 분석 사전에서 `retired`로 표시하고, 제거 빌드 이후 발생하면
구버전 클라이언트 또는 남은 실행 경로로 분리해서 조사한다.

## 7. 출시·롤백 순서

1. 한 PR에서 호환 마이그레이션과 사용자 경로 제거를 함께 구현한다.
2. 내부 빌드에서 옛 저장·옛 알림·옛 주간 보드 픽스처로 검증한다.
3. TestFlight에서 신규 설치와 업데이트 설치를 모두 확인한다.
4. 정식 배포 후 7일간 6장의 회귀 지표를 관찰한다.
5. 문제가 생겨도 현 모드 전체를 다시 노출하지 않는다. 리다이렉트나 주간 마이그레이션만
   작은 핫픽스로 수정한다.

## 8. 재도입 게이트

다음 조건이 모두 준비되기 전에는 같은 이름의 기능을 다시 제품 계획에 넣지 않는다.

- 한 판이 3타자 또는 최대 10구, 목표 90~180초 안에 끝난다.
- 매일 타자 이름과 능력치만 바꾸는 것이 아니라 규칙·상황·제약 중 하나가 달라진다.
- 어떤 세이브 성공 점수도 모든 실패 점수보다 높다는 불변식 테스트가 있다.
- 결과 화면에 순위 또는 백분위, 최고점 변화, 즉시 재도전 이유가 있다.
- 첫 완료 보상과 기록 재도전 보상이 명확히 분리된다.
- `impression → open → start → abort/complete → retry → next-day start` 퍼널이 고유 사용자
  기준으로 연결된다.
- 내부 플레이테스트에서 최소 7개의 서로 다른 일일 규칙을 반복해도 선택이 달라진다.
- 새 저장과 분석 키는 기존 키를 재사용하지 않고 `daily_inning_v2`처럼 버전 경계를 둔다.

새 기획은 과거 Game Center 점수와 직접 비교하지 않는다. 옛 리더보드는 기록 보존용으로
동결하고, 점수 규칙이 달라지면 새 리더보드를 만든다.

## 9. 이번 작업에서 하지 않는 것

- 새 오늘의 이닝 설계 또는 프로토타입 구현
- 과거 사용자 기록과 지급 보상 삭제
- 옛 분석 데이터 재해석 또는 성과 목표 확정
- 모드 제거를 보완하기 위한 새 출석·통화·광고 기능 추가
- 과거 리뷰 문서의 주장이나 수치를 현재형으로 일괄 수정

이 경계를 지켜야 임시 제거가 또 다른 리텐션 기능을 급히 덧붙이는 작업으로 번지지 않는다.
