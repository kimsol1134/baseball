# Android 투구 성능 최적화 — 2026-09-06

## 적용 범위

- `PitchActivity`: 스코어보드/HUD 투구 예측을 `remember(gameState)`로 캐시. 게임 상태가 바뀔 때 갱신하며 애니메이션 프레임 때문에 예측 커널을 반복 실행하지 않는다.
- `PitchDramaView`: 궤적 65개 점을 요청별로 캐시. 매 프레임 궤적 재생성 및 여러 `map`/부분 목록 생성을 제거하고 현재 공 위치만 보간한다. 구종별 곡선, 도착점, 접촉 시점은 유지한다.
- `PitchDeliveryControl`: 일반/불규칙 심박음 PCM을 효과 시작 시 `Dispatchers.Default`에서 생성해 재사용한다. 투구 시작·백그라운드 진입 시 기존 취소 경로를 유지한다.
- 애니메이션 진행값을 Canvas에 지연 전달하는 변경도 실험했으나, 계측상 이득이 확실하지 않아 최종본에서 제외했다. 접근성 설명은 실제 진행 단계와 일치한다.

수동 슬라이더 기본값, 성공 판정, 투구 물리, 성장·피로, 저장 형식은 변경하지 않았다. 저장은 기존 비동기 영속화 경로를 유지한다.

## 측정 조건과 한계

Galaxy A53, 별도 `reset.compose.qa` 패키지, Debug, 앱 요청 60Hz. 리플레이 2회 예열 후 12회 측정. 메인 사용자의 진행은 벤치마크에서 사용하지 않았다.

초기 실험은 매번 앱 데이터를 초기화하여 설치 ID 기반 경기 시드가 달라질 수 있었다. 따라서 해당 결과로 성능 개선율을 주장하지 않는다. 최종 비교에서는 같은 저장된 투구를 보존하고 APK만 교체했다. 각 측정에서 경기 상태가 불변임을 확인한다.

Debug 단일 기기의 짧은 리플레이 측정은 출시 성능이나 모든 화면의 끊김 해소를 보증하지 않는다. 실측 개선이 확인되지 않은 항목은 개선 완료로 간주하지 않는다.
